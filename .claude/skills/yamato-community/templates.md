# コミュニティ・イベント部のテンプレート

スキル `yamato-community` の出力の型。すべて**下書き**。配信・告知・読者への返信はCEOが承認したあと(L2)。
置き場所は非公開リポジトリ `aoi7160/yamato-outdoor-editorial` の `content/community/`。読者の個人情報はどこにも書かない。

```
content/community/
  design.md                 配信設計書(受け口ごとに1節。開設前に1回作り、四半期ごとに見直す)
  scenario.md               ステップ配信のシナリオ(登録直後〜7日)
  seeds.md                  配信の種(公開した記事・入荷・季節の話題を1行ずつ。受け口が開くまでは種だけ貯める)
  issues/YYYY-MM-<n>.md     メルマガ・LINEの配信文の下書き(1通1ファイル)
  replies/templates.md      問い合わせの返信テンプレ(このファイルの5章を育てたもの)
  questions.md              読者の質問の要旨(個人が分からない形)と渡した先
  events/YYYY-MM-<略称>.md  イベント・企画登山の企画書
```

---

## 1. 配信設計書(design.md の1節)

```
## <LINE / メール>

- 受け口:<LINE公式アカウント(コミュニケーションプラン)/ Googleフォーム→MailerLite Free など>(料金と上限の出どころと確認日)
- 誰に:P1(関西・月1〜2回の日帰り)。登録の動機は「次の1回の判断材料がほしい」
- 約束(src/lib/cv.ts の文面と一致させる):<メール:装備の実測値と、関西の山の状況をまとめて月に1〜2回。宣伝だけのメールは送らない / LINE:新しい記事と、道具の入荷を通知>
- 頻度:<月◯回。上限の根拠(LINEは 友だち数×回数 ≤ 月200通)>
- 配信日時:<例 木曜21:30(週末の前に、P1がスマホで読む22:30〜24:30の手前)>
- 中身の配分:判断材料8:お知らせ2。1通の宣伝(グッズ・ASPリンク)は1枠まで
- 測る数字:登録数(週)/ 配信あたりのクリック / 配信停止・ブロック(配信ごと)/ 質問の数
- 見直しの線:スキル3-3の閾値
- 法令・規約:特定電子メール法の表示(メール)/ 個人情報の利用目的と /privacy の改定 / Amazonリンクはオプトインの相手だけ(法務 rulebook 5・6章)
- 開設に必要なCEOの作業:<アカウント作成・URLを src/lib/site.ts に入れる承認・送信者の住所の出し方>
```

## 2. ステップ配信のシナリオ(scenario.md)

| 通 | いつ | ねらい | 中身 | 測る |
|---|---|---|---|---|
| 1 | 登録直後 | 約束の確認 | 何が・どれくらい届くか / 停止の方法 / 運営者が誰で、どの山を歩いているか(1行) | 停止・ブロック |
| 2 | 3日後 | 1回目の価値 | 「次の1回」に効く記事を3本(分析部の確定値で読まれている記事から。季節に合うもの) | クリック |
| 3 | 7日後 | 双方向にする | 「次に行く山と、迷っている装備を1つだけ教えてください」(返信・フォーム) | 返信の数 |

第1通の下書き(メール):

```
件名:YAMATO OUTDOOR に登録いただき、ありがとうございます

<運営者名>です。関西の山を、働きながら月1〜2回歩いて、装備を量って記録しています。

このメールでは、月に1〜2回、
- 自分で量った装備の数字
- 関西の山の状況(通行止め・季節の変わり目など。出典つき)
をまとめて送ります。宣伝だけのメールは送りません。

まずは、いま読まれている記事を1本。
<記事タイトル>
<URL>

――
このメールの送信者:YAMATO OUTDOOR(<運営者名>)
配信の停止:<停止のURL>
送信者の住所:<CEOが決めた表示>
お問い合わせ:<窓口>
```

## 3. 定期の配信文(issues/)

### 3-1. メルマガ(月1〜2回)

```
件名:<具体名詞を1つ入れる。例:六甲の冬に、手袋を3組量った>(全角30字以内。使わない語なし)

<リード:2〜3文。季節と山の場面から>

■ 今月量ったもの
- <道具>:実測<◯g>(カタログ値<◯g>)。<合わなかった点を1行>
  → <記事URL>

■ 関西の山の状況(<YYYY年MM月DD日>時点)
- <山域>:<発表の要旨>(出典:<発表元の名称とURL>)
  ※ 出かける前に、必ず発表元で最新の情報を確かめてください

■ 次に読む1本
- <記事タイトル>:<読む理由を1行> <URL>

■ 読者の質問から
- 「<質問の要旨(個人が分からない形)>」→ <答えか、答えている記事>

<宣伝の枠は1つまで。ASPリンクがある号は、冒頭に「このメールには広告(アフィリエイトリンク)を含みます」>

――(フッターは第1通と同じ。特定電子メール法の表示)
```

### 3-2. LINE(記事の通知・入荷・週末の前)

```
【新しい記事】<タイトル>
<読む理由を1文。具体名詞を1つ>
<URL>
```

```
【入荷】YAMATO OUTDOORのグッズ(自社商品)に<商品名>を追加しました
<どの山で使う前提で作ったかを1文>
<SUZURIのURL>
```

LINEは1通を短く(3〜4行)。1回の配信は最大3吹き出しまでで、通数は「送った回数×送った友だちの数」で数える(ステップ配信も含む)。
1対1のチャットの送受信と自動応答は通数に数えない(LINEヤフー for Business「料金プラン」2026-11-01確認)。

## 4. 配信の承認依頼(承認トレイ)

プロパティ:件名「<LINE / メルマガ>『<件名>』を<日時>に配信」/ 種類「外部への連絡」/ 依頼元 `community` /
根拠(配信の約束との一致・材料の出どころ・前回の数字)/ 承認すると「CEOが<配信ツール>で予約配信する」/ 要約。

```json
{
  "changes": [
    "<LINE / メルマガ>を<YYYY-MM-DD HH:MM>に配信(対象:登録者全員 約<◯>人。人数は配信ツールの画面で確認した時点の値)",
    "宣伝の枠:<なし / グッズ1 / ASPリンク1(冒頭に広告の表示あり)>"
  ],
  "draft": { "label": "配信する文面", "text": "件名:…\n\n<本文>" },
  "links": [{ "label": "文面で紹介する記事", "href": "https://yamato-outdoor.com/…/" }]
}
```

## 5. 問い合わせの返信テンプレ(replies/templates.md の初期値)

返信はすべて**CEOが送る**。AIは下書きまで。冒頭の宛名・末尾の署名はCEOが決めた形にする。

### 5-1. 記事の内容への質問

```
お問い合わせありがとうございます。YAMATO OUTDOORの<運営者名>です。

<質問の要旨>について、記事を書いたときに確かめた範囲でお答えします。
<答え。実測・体験は記事に書いた範囲だけ。確かめていないことは「確かめていない」と書く>

<関係する記事があれば、タイトルとURL>
```

### 5-2. 記事の誤りの指摘

```
ご指摘ありがとうございます。<該当の箇所>を確認し、<誤りでした / 確認中です>。
<誤りなら:◯月◯日までに記事を直し、記事内に更新日を入れます>
```
→ 校閲部に事実確認を依頼する(直すのはコンテンツ制作部)。

### 5-3. 「この山に今週末行けるか」など、安全に関わる判断を求める質問

```
お問い合わせありがとうございます。
登山道の状況や天候は日々変わるため、YAMATO OUTDOORから行ける・行けないの判断をお伝えすることはできません。
<山域>の状況は、<管理者・自治体・気象庁など発表元の名称とURL>で、出発前に最新の情報をご確認ください。
<関係する記事があれば:装備や準備の考え方はこちらにまとめています。URL>
```

### 5-4. 取材・提携・広告の申し出

```
ご連絡ありがとうございます。内容を確認し、<◯営業日以内>に担当よりご連絡します。
```
→ PR・パートナーシップ部に渡す(採点して台帳へ)。この部は受け取った旨の返信だけ。

### 5-5. 個人情報(配信の停止・登録の削除・開示)の依頼

```
ご連絡ありがとうございます。<配信の停止 / 登録の削除>を承りました。<処理した日>以降、配信はいたしません。
```
→ 停止はCEOが配信ツールで処理し、停止の記録を残す。開示・訂正などの請求は法務に論点を確認してからCEOが返す。

## 6. イベント・企画登山の企画書(events/)

```
# <企画名>(企画書・下書き)

## ねらい
- 読者にとって:<次に行く日が決まる / 一人では行きにくい山に出ていける>
- 想起・事業にとって:<関西の山域の縄張り / soft CVの登録者が会う場 / 記事の一次情報>

## 概要
- 日時:<候補日2つ+予備日>
- 場所:<山域・コース・コースタイム(出典)・標高差>。エスケープルート:<◯◯>
- 形式:現地集合・現地解散 / 参加費なし / 交通・宿泊は各自(旅行業法の論点を避ける既定。法務 rulebook 8章)
- 定員:<人数>(主催者1人あたりの人数はスキル3-6の初期値以内。最終はCEO)
- 参加条件:<コースタイム◯時間を歩いた経験・装備(レインウェア・ヘッドランプ・行動食・水◯L)>

## 安全
- 中止の基準:<前日18時の予報で◯◯なら中止>(スキル3-6)
- 当日の連絡体制・下山連絡・登山届(提出先と方法)
- 保険:<主催者の賠償責任・参加者の傷害の要否はCEOが確認>

## 集める情報
- 名前(呼び名で可)・連絡先・緊急連絡先。健康状態は聞かず、参加条件で判断してもらう
- 写真の掲載の可否(顔が分かる写真は同意がある人だけ)

## 告知と申し込み
- 告知:<LINE / メール / SNS(SNS部に投稿キューを依頼)>。告知はL2
- 申し込みの受け口:<Googleフォームなど。個人情報の扱いは法務>

## 協力先
- <PR部が打診する先(自治体・山の施設)。無ければ「なし」>

## 記録
- 終わったら:参加人数・天候・事故やヒヤリの有無を、事業報告部の登山の記録に渡す
```

## 7. 日報の自分の節(STANDARDS 5章)

受け口が未開設のとき:

```
### コミュニティ・イベント部
- 結果:受け口は未開設(LINE_FRIEND_URL・NEWSLETTER_URL・CONTACT_URL がすべて空。src/lib/site.ts、11/3時点)。配信の種 12件
- 判断:発信先が無いので配信文は作らない。開設の判断材料を先にそろえる
- やったこと:ステップ配信の第1〜3通を下書き(非公開リポジトリ scenario.md)。/privacy改定の論点を法務に依頼
- 依頼:legal 受け口開設前の/privacy改定案 / executive LINE開設の判断(承認トレイに積みました)
```

受け口が開いたあと:

```
### コミュニティ・イベント部
- 結果:LINE友だち 42人(+5。記事末から4・SNSから1。LINE公式アカウントの管理画面をCEOが確認した値、11/10時点)。質問2件
- 判断:先週の配信のクリックは初期値の線より上。頻度は月2回のまま
- やったこと:木曜の配信文を下書きして承認トレイへ。質問1件を記事化の候補として企画部へ
- 依頼:planning 質問「冬の金剛山で軽アイゼンは要るか」を企画の候補に
```
