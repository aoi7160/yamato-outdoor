# グッズ部の専門スキル

メンバー:**Merch Lab**(誰に・何を・なぜ)/ **Design Studio**(SVGのラフ・商標の確認依頼)/ **Sales Insights**(売上・クリック・品ぞろえの見直し)。
参照ファイル:

| ファイル | 中身 |
|---|---|
| `references.md` | SUZURIの価格の仕組み・手数料・アイテム・商標・フォントの出典と確認日 |
| `templates.md` | 企画書・SVGのひな形・承認トレイのJSON・日報の節の実例 |

## 0. 始める前に(毎回)

1. `CLAUDE.md`(「デザインの約束」のフォント・山のシルエット・等間隔の三角形を並べない)と `.claude/skills/yamato-ops/STANDARDS.md` を読む
2. `docs/persona.md` の 0章(Mission/Value)・2章(P1)・3章(S1・S2)・5章(コピーの基準・使わない語)を読む
3. `console/agents/goods.md` を読む。`src/lib/site.ts` の `SHOP_URL` と `src/lib/cv.ts` の `shop` 枠の文面を見る
4. Notion「YAMATO BASE CAMP」の「承認トレイ」を開く。**Notionにつながっていなければ、ここで止めて「Notionにつながっていないため未実行」とだけ返す**
5. 非公開リポジトリ `yamato-outdoor-editorial` の `content/goods/` を見る(過去の企画・デザイン案・販売メモ。無ければ作る)

## 1. 役割と到達基準

**役割:** ブランドのマーチャンダイザー兼ブランドマネージャー。売れるグッズを作る人ではなく、
**「YAMATO OUTDOORの名前と世界観を、読者が山に持っていく形にする」**人として動く。三階建ての2階「作る」の入り口(`docs/persona.md` 1章)。

**合格の基準:**

- 出す企画はすべて、3-1の企画採点表で11点以上(15点満点)で、点数の根拠が1行ずつある
- デザイン案は、使う場面(山のどこで・何に付けて・何と一緒に写るか)と、想起の手がかり(名前・約束・関西・見た目)がどう入っているかを説明できる
- 名前・ロゴ・地名を使う案は、**承認トレイに積む前に法務部の商標の判断が出ている**
- 価格は「原価+トリブン=販売価格」の内訳と確認日つきで、3-4の価格帯のどこに置いたかの理由がある
- 販売分析は、取れた数字と取れない数字を分けて書き、取れない数字を作らない

## 2. 事業への効き方

| 担当KPI(`console/agents/goods.md`) | 事業への効き方 |
|---|---|
| 本日のSUZURI売上(円) | 小さいが、三階建ての2階が動いている証拠。P&Lには分析部の確定値として事業報告部が記帳する |
| 販売中のアイテム(点) | 品ぞろえの広さ。**多ければよいわけではない**(3-5) |
| ショップへのクリック | GA4の `cv_click`(`cv_id=shop`)。記事末・ヘッダーのカートからの関心の量 |

**想起への効き方(この部の本当の仕事):**

グッズは、記事やSNSと違って**検索結果の外で名前が目に入る**唯一の手段。
ボトルのステッカー・帽子・ドライTシャツが、六甲の山頂や登山口の写真に写り込むたびに、「YAMATO OUTDOOR」という名前が持ち主以外の人にも届く。

| 想起の手がかり(STANDARDS 2章) | グッズでの効かせ方 |
|---|---|
| 名前 | 「YAMATO OUTDOOR」をフルで入れる。略称・カタカナ・ロゴだけの案は、認知が育つまで出さない |
| 約束 | Missionの語彙(ベースキャンプ・荷・天候・一歩・出ていく)を、説明ではなく短い句で |
| 一次情報 | 記事で検証したこと(例:実測したルート・歩いた稜線)を図案の題材にする。体験を盛らない |
| 関西 | 六甲・金剛・比良・大峰・岩湧山。**実在の稜線と標高**を図案にする(国土地理院で確かめる) |
| 見た目 | ダークトーン・山のシルエット・霧。写真を盛らない。等間隔の三角形を並べない |

測り方:グッズの効果を売上だけで見ない。分析部に、指名検索・SNSでの名前の言及・ショップへのクリックの推移を新作の前後で比べてもらう(数字を出すのは分析部)。

## 3. 判断の型

### 3-1. 企画採点表(15点満点・11点以上で案出しに進む)

| 項目 | 3点 | 1点 | 0点 |
|---|---|---|---|
| ① 山で使う場面がある | 登山中に使う・身に付ける(ドライTシャツ・帽子・ソックス・ボトルに貼るステッカー) | 登山口・車・帰り道で使う | 山と関係ない |
| ② ペルソナが自分ごとにできる | P1かS1かS2の誰か1人の具体的な場面が書ける | 「登山好きな人」までしか書けない | 書けない |
| ③ 名前と世界観が伝わる(想起) | 「YAMATO OUTDOOR」と約束・見た目の両方が入る | どちらか一方 | どちらも無い |
| ④ 関西かMissionに根がある | 実在の関西の山・稜線・標高、またはMissionの語彙 | 一般的な山のモチーフ | 無い |
| ⑤ SUZURIで品質が出る | 線と面がはっきりした1〜2色で、そのアイテムの印刷方式に合う | 細部が潰れる心配がある | 写真・グラデーション頼み |

**ペルソナごとの効く方向**(`docs/persona.md`):

| ペルソナ | 効く企画 | 効かない企画 |
|---|---|---|
| P1(34歳・吹田・月1〜2回) | 控えめで山で実際に使えるもの。主張しすぎないロゴ・関西の稜線 | 映え・「山ガール」的なノリ・意識高い系のブランド語り |
| S1(27歳・京都・ブランドの認知入口) | 普段着と兼用できる色と形。サイズ展開が分かること | 山でしか着られない格好 |
| S2(46歳・神戸・作り手に共感) | 「なぜこの仕様か」を説明できるもの(素材・図案の由来) | 理由の説明が無い限定品 |

**名実一体の線:** 記事で言っていることと矛盾するものは作らない。
例:記事で「綿は汗で冷える」と書いているのに、綿のTシャツを「山で着る1枚」として売らない(綿のTシャツは街着として企画し、山で着る企画はドライ素材のアイテムにする)。

### 3-2. アイテムの選び方

SUZURIのアイテム一覧(`references.md`)から、①の場面で選ぶ。立ち上げ期の優先順:

| 優先 | アイテムの型 | 理由 |
|---|---|---|
| 1 | ステッカー | 安く、ボトル・ヘルメット・スマホ・車に貼られて**名前が人の目に触れる回数が最も多い**。想起のための「名刺」 |
| 2 | 帽子(ジェットキャップ・バケットハット)・ソックス | 山で身に付け、写真に写る。P1が手に取りやすい価格帯 |
| 3 | ドライ素材のTシャツ・長袖 | 山で着られる。S2には素材の理由を添える |
| 4 | 綿のTシャツ・パーカー・スマホケース | 街での認知(S1)。山で着る前提にしない |

### 3-3. デザイン案の作り方(SVGのラフ)

1. **題材を1つに絞る**:稜線1本・標高1つ・言葉1句。2つ以上入れると、小さいアイテムで潰れる
2. **稜線は実在のものから起こす**:国土地理院の地理院地図の断面図などで形と標高を確かめ、出典(どこからどこまでの断面か)を企画書に書く。
   利用条件は国土地理院のコンテンツ利用規約で確かめ、法務部に確認を頼む。**等間隔の三角形を並べない**
3. **文字**:名前は「YAMATO OUTDOOR」(欧文はSchibsted Grotesk)、和文の大きい句はZen Old Mincho、中くらいの和文は字間を開けたZen Kaku Gothic New(`CLAUDE.md`)。
   ラフでは `font-family` 指定のままでよい。入稿用のアウトライン化はクリエイティブ制作部
4. **色**:ダークトーンの1〜2色。生地の色(白・黒・グレー・カーキ)ごとに、反転版も作る
5. **サイズ**:実寸で考える。ステッカーは5〜8cm角で山名が読めるか、帽子の正面は幅6cm前後で名前が読めるかを、SVGの `viewBox` を実寸(mm)にして確かめる
6. **案の数**:1企画につき方向の違う案を2〜3。違いを「何を強く出したか」で説明する(全部似た案は出さない)
7. ひな形は `templates.md` 2。ファイルは `content/goods/<YYYY-MM>-<slug>/` に `concept.md` と `draft-a.svg` などで置く

### 3-4. 価格とトリブンの決め方

SUZURIは**販売価格=アイテムの原価+トリブン(作り手の利益)**。初期費用・在庫は無い(`references.md`)。
だからこの部のリスクは在庫ではなく、**値付けを誤ってブランドの印象を下げること**と、**品ぞろえが散らかること**。

| 価格帯 | 対象 | トリブンの目安(社内の仮置き) | 考え方 |
|---|---|---|---|
| 名刺(想起用) | ステッカー | 原価にほぼ乗せない〜200円 | 売上ではなく、名前が貼られる回数を取りにいく |
| 定番 | 帽子・ソックス・Tシャツ | 販売価格の15〜25% | P1は「趣味に使いすぎと言われたくない」。山の道具店で手に取る価格感から浮かせない |
| 支援 | S2向けの少数の企画 | 販売価格の25〜35% | 図案や素材の理由を説明できるものだけ。理由が書けないなら定番の帯に戻す |

- 原価は、SUZURIのアイテム作成画面で**その日の値を見て**企画書に書く(確認日つき)。原価は改定されるので、承認依頼のたびに確かめ直す
- 価格は100円単位で切りのよい数字に。同じアイテムの型は、企画が違っても価格をそろえる(ショップで見比べられる)
- 振込手数料(`references.md`)を差し引いて、月の受取額がどれくらい残るかを企画書に1行

### 3-5. 販売分析の判断

| 見ること | 出どころ | 判断の目安 |
|---|---|---|
| アイテム別の販売点数・トリブン | SUZURIの管理画面(CEOが見る)→ コンソールの「データ連携」に手入力 | 公開から90日、またはショップへのクリックが50回たまるまでは判断保留 |
| ショップへのクリック(記事別・置き場所別) | データ分析部(GA4の `cv_click`・`cv_id=shop`・`cv_place`) | クリックが多いのに売れない → 価格帯か品ぞろえ。クリックが少ない → 記事末の枠の文面(`src/lib/cv.ts`)の見直し案 |
| 品ぞろえ | SUZURIのショップ | 販売中は**10点まで**を目安。90日売れず、想起の役割(名刺・定番)も無いものは取り下げ案 |
| 季節 | 企画部の需要カレンダー | 12月(年末年始・振り返り)・春の登山シーズン前に新作を合わせる。時期を決めるのは企画部 |

**売上の実データ(金額)はリポジトリにコミットしない**(`CLAUDE.md`)。日報(Notion)と、非公開リポジトリの販売メモにだけ書く。

## 4. 定例の手順

運営の時間割では `weekly`(毎週月曜)の7番目に呼ばれる。

### 4-1. 毎週月曜(weekly)

1. **販売の点検(Sales Insights)**
   - CEOからSUZURIの数字(前週の販売点数・トリブン)をもらっているか、日報・承認トレイのコメントで確かめる。もらっていなければ「未取得(SUZURIの売上はAPIで取れず手入力のため)」と書き、日報の依頼に1行
   - ショップへのクリック(7日)はデータ分析部の日報の節から拾う。無ければ「未取得」
   - 3-5の目安に当て、判断保留か、打ち手があるかを決める
2. **進行中の企画の点検(Merch Lab・Design Studio)**
   - `content/goods/` の企画のうち、法務部の商標の判断待ち・クリエイティブ部の清書待ちのものを見る。2週間止まっていれば、その部への依頼を日報に書く
   - 法務部の回答は、日報の依頼への返信か、承認トレイのページの見出し3「法務の確認(日時)」に書かれる。法務部は月次と依頼時に動くので、公開の時期が迫っている企画は、CEOに「法務で確認して」と頼んでもらう依頼を日報に書く
   - 法務部の判断と清書がそろったものは、4-3で承認トレイに積む
3. **その月の最初の月曜だけ:新作の企画(Merch Lab)**
   - 企画部からの季節商品の企画依頼(承認トレイ「企画」・日報)を確かめる。依頼があればそれを優先する
   - 依頼が無ければ、自分で1〜2企画を立てる:最近公開・承認された記事の題材(山・稜線・装備)と、企画部の需要カレンダーの6〜8週間先を見て、3-1で採点する
   - 11点以上の企画だけ、3-3でSVGのラフを2〜3案作り、企画書(`templates.md` 1)と一緒に `content/goods/` に置く
   - 名前・ロゴ・地名を使う案は、法務部に商標の確認を依頼する(日報の依頼の行。確認してほしい語・アイテム・候補の区分を書く)
   - 清書は、法務部の判断が出てから日報の依頼に「クリエイティブ部:<企画>の案◯を清書(入稿サイズ・生地の色)」と書く(クリエイティブ部は翌週の制作キューで拾う)
   - 置いたファイルを非公開リポジトリにコミットしてpushする(L1)
4. 日報の自分の節を書く(6章)

### 4-2. 依頼されたとき

- 「グッズの企画を出して」→ 4-1の3を1回分
- 「デザイン案を作って」→ 3-3。題材の指定が無ければ、企画採点表の上位の企画から
- 「グッズの売れ行きを見て」→ 4-1の1。数字を渡されていなければ、何をどこから写してほしいかを1文で返す
- 「記事末のショップの枠を見直して」→ `src/lib/cv.ts` の `shop` の文面案(3案)を、ショップへのクリックの数字と一緒に承認トレイ「企画」へ(実装はサイト開発部)

### 4-3. グッズ登録の承認依頼(清書と商標の判断がそろったら)

1. クリエイティブ部の清書(開けるURL)と、法務部の判断(問題なし・条件つき)を企画書に書き写す
2. SUZURIのアイテム作成画面の原価を見て(CEOに確認を頼むか、公開されている価格表で確かめる)、3-4で価格を決める
3. 承認トレイに種類「グッズ登録」で積む(`templates.md` 3)。**SUZURIへの商品登録・価格設定はL2。押すのはCEO**
4. 承認されたら、SNS部(告知の投稿キュー)とコミュニティ部(入荷の配信案)に知らせる(日報の依頼の行)

## 5. 品質基準とチェックリスト

**企画書**
- [ ] 企画採点表が11点以上で、各項目に根拠が1行ある
- [ ] 誰の、山のどの場面かが書いてある(P1・S1・S2のどれか)
- [ ] 記事で言っていることと矛盾しない(綿を山で着る前提にしない 等)
- [ ] 使わない語(最強・保存版・初心者必見・登山家・アドベンチャー)や、盛った実績を使っていない
- [ ] 体験を作っていない(「私たちが毎週登る」など、確かめていない事実を書いていない)

**デザイン案**
- [ ] 「YAMATO OUTDOOR」を略さず入れた(または入れない理由がある)
- [ ] 稜線・標高は実在のもので、出典(国土地理院の何を見たか)を書いた
- [ ] 等間隔の三角形を並べていない
- [ ] 実寸で山名と名前が読める
- [ ] 他社のロゴ・商標・写真・既存のイラストをなぞっていない
- [ ] 方向の違う案が2〜3ある

**承認依頼**
- [ ] 法務部の商標の判断が出ている
- [ ] 清書の画像が開けるURLである(URLの無い納品は「納品した」と書かない)
- [ ] 原価・トリブン・販売価格の内訳に確認日がある
- [ ] 売上の実額・SUZURIのトークンを公開リポジトリに書いていない

## 8. よくある失敗

| 失敗 | なぜ起きるか | 避け方 |
|---|---|---|
| ロゴを大きく入れただけのTシャツを並べる | ブランドを出したくなる | 3-1の①④。山の場面と関西の題材から始める |
| 品ぞろえを増やせば売れると思う | SUZURIは在庫が要らず、足すのが簡単 | 10点まで。増やす前に、売れない理由を3-5で見る |
| 綿のTシャツを「山で着る1枚」として売る | 定番アイテムだから | 名実一体。山で着る企画はドライ素材にする |
| 稜線を見た目で描く・三角形を並べる | 手早く山らしく見せたい | 実在の稜線を国土地理院で確かめて起こす |
| 地名や「YAMATO」系の名前を確かめずに使う | 地名は自由に使えると思い込む | 名前・地名を使う案は全部、法務部に商標の確認を依頼する |
| 原価を前回の数字のまま使う | 確かめる手間を省く | 承認依頼のたびに、その日の原価と確認日 |
| 売上の数字が無いのに「好調」と書く | 報告を埋めたくなる | 取れない数字は「未取得」と理由。CEOに何を写してほしいかを1文で頼む |
| 体験を作って商品説明を書く | 物語があると売れそうに見える | 体験は運営者のもの(`docs/content-pipeline/rules.md` R1)。説明は図案の由来(出典のある事実)で書く |

## 9. 今の状態と、次に上げる能力

**今の状態(2026-11-01):**

- SUZURIのショップはある(`SHOP_URL` 設定済み・記事末の `shop` 枠とヘッダーのカートが出ている)
- 販売中のアイテム数・売上は**AIからは未確認**:SUZURIのショップページは画面の描画にスクリプトが要り、ページ取得では商品と価格が読めない。SUZURI APIは未接続
