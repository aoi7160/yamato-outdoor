# 提出前チェックリスト

上から順に確認し、報告書を出すときに「チェックリスト通過」と書き添える。1つでも外れたら出さない。

## 1. 事実
- [ ] お金の数字は、P&L台帳かデータ分析部の確定値にあるものだけ(推測・記憶で書いていない)
- [ ] 数字に出どころと時点がある(社内版は本文、対外版は確定値のみ載せる)
- [ ] BASE CAMPの「DEMO」の値を使っていない
- [ ] 写真から推測した記述(天気・人数・場所)をCEOに確認した
- [ ] 理念・キャッチコピーは `docs/persona.md` から一字一句そのまま
- [ ] 登山用語・法令名(景品表示法・電気通信事業法)の使い方が正しい

## 2. 検算
- [ ] 内訳の合計が合計欄と一致する(売上・費用・時間・PVの内訳)
- [ ] 計画書の数字が、ロードマップの「当面の目標」・P&Lの「計画」列と一致する
- [ ] 作業件数を `git_activity.py` の出力と突き合わせた(前回の報告と期間が重なるなら件数も一致)
- [ ] 日付は日本時間(PRのマージ日時を+9時間した)

## 3. 漏れ
- [ ] 全ブランチ(未マージを含む)を見た
- [ ] 各部の日報・速報で、報告書に載せるべきもの(売上・承認・差し戻し)を拾った
- [ ] 山行・取材を載せた(無い月は「なし」と書く)
- [ ] 未達・遅れ・課題を、成果と同じ分量で書いた

## 4. 読み手
- [ ] 対外版:言い換え表の言葉が残っていない(コミット・PR・GA4・ペルソナ・CV など)
- [ ] 対外版:ASP名・報酬額・個人名・未確定の売上を載せていない
- [ ] 顔が写る写真を載せるなら、本人の同意をCEOが確認した
- [ ] 社内版:来月の重点はCEOが承認したものだけ(未承認なら明記)

## 5. 見た目
- [ ] `scripts/preview.py` で全ページを画像にして目で見た
- [ ] ほぼ空のページ・写真とキャプションの泣き別れ・表のはみ出し・変な改行がない
- [ ] グラフに凡例と数値ラベルがある(色だけで区別させていない)

## 6. 残す
- [ ] PDFと構成ファイル(JSON)をNotionの報告書アーカイブに置いた
- [ ] 新しい失敗があれば `lessons.md` に足し、スキルの変更をコミットした
