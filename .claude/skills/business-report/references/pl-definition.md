# 月次P&Lの定義

目的は**管理会計**。「事業を立ち上げ、月◯万円の利益を出した」「週◯時間で月◯万円」と、
事業責任者として数字で語れる記録を残すこと。税務申告(青色申告の帳簿)とは別物で、代わりにしない。
ただし科目は申告で使う勘定科目に寄せておき、年末に会計ソフトへ移しやすくする。

---

## 1. 台帳(実データの置き場所)

実データは**公開リポジトリに置かない**(リポジトリは public)。Notion「YAMATO BASE CAMP」の下に
次の3つのデータベースを作り、月末にCSVで書き出して `scripts/pl.py` に渡す。

| DB | 1行の単位 | 列 |
|---|---|---|
| 売上台帳(revenue) | 成果1件(ASPの1成果、SUZURIの1注文、タイアップ1件) | `date` 発生日 / `confirmed_date` 確定日 / `channel` 収益源 / `source` 記事・商品 / `status` 発生・確定・入金・否認 / `amount` 円(税込) / `note` |
| 費用台帳(expenses) | 支払い1件 | `date` 支払日 / `item` 品目 / `category` 科目 / `amount` 円(税込) / `business_ratio` 事業割合(0〜1) / `allocation` once・monthly12 / `receipt` 有・無 / `note` |
| 作業時間ログ(time) | 1日×1区分 | `date` / `category` 区分 / `hours` 時間(0.25刻み) / `note` やったこと |

- ひな形のCSVは `templates/ledger/`。NotionのDBもこの列名で作る(書き出したCSVがそのまま読める)
- 売上は**1件1行**。状態が進んだら行を増やさず `status` を書き換える(二重計上を防ぐ)

## 2. 売上の科目(channel)

| channel | 例 | 計上のタイミング |
|---|---|---|
| アフィリエイト:Amazon | Amazonアソシエイト | 確定(Amazonは翌月末に確定) |
| アフィリエイト:楽天 | 楽天アフィリエイト | 確定 |
| アフィリエイト:ASP | A8.net・もしも・バリューコマース・afb など。`source` にASP名と案件名 | 確定(承認) |
| グッズ | SUZURIのトリブン | 注文日(SUZURIの売上明細の日付)。キャンセルは否認 |
| タイアップ・受託 | 記事広告・レビュー制作 | 納品・検収の日 |
| デジタルコンテンツ | note・Kindle | 販売日 |
| その他 | | |

**計上基準は「確定ベース」**。ASPの「発生」は否認されることがあるため、P&Lには入れず「未確定(参考)」として
別に表示する。入金は資金繰りの話なので、P&Lには影響させず「入金済み(参考)」として出す。

> 立ち上げ期は確定が1〜2ヶ月遅れる。月次報告では「確定」「未確定」の両方を並べ、
> 未確定が大きい月は**その旨を必ず書く**(利益が少なく見える理由を説明できるように)。

## 3. 費用の科目(category)

| category | 例 | 注意 |
|---|---|---|
| 通信費 | ドメイン・サーバー・Cloudflare・スマホの通信(按分) | ドメインは年額 → monthly12 |
| ソフトウェア | microCMS・Claude等のAI・デザインツール・会計ソフト | 年額払いは monthly12 |
| 広告宣伝費 | SNS広告のテスト・ステッカーの配布 | |
| 取材費 | 山行の交通費・駐車場・入山料・ロープウェイ | **取材目的の山行だけ**。記事・報告に使った山行と紐づける(`note` に山名) |
| 検証用品費 | レビューのために買ったギア | 1点10万円以上は資産(減価償却)になるので `note` に「要確認」と書きCEOに確認 |
| 外注費 | 撮影・デザイン・記事の外注 | |
| 支払手数料 | 振込手数料・決済手数料 | |
| 雑費 | どれにも入らないもの | 月に3件を超えたら科目を見直す |

- **按分**:私用と兼用のもの(PC・スマホの通信・自宅の通信)は `business_ratio` に事業割合を入れる。
  割合の根拠(例:「平日夜と週末の作業時間の比率」)を `note` に1度だけ書き、毎月同じ割合を使う
- **年額払い**:`allocation=monthly12` にすると、支払月から12ヶ月に均等に配る
- **自分の人件費は入れない**(個人事業)。代わりに「時間あたり利益」で評価する

## 4. 作業時間の区分(category)

`記事` / `取材` / `アプリ` / `SNS` / `営業` / `計画と報告` / `その他`

- 事業計画書(10〜12月)の「時間の使い方」の区分と同じ。計画と実績を比べられるようにする
- 山行は `取材` に入れる(移動時間を含む)。記事に使わない純粋な遊びの山行は入れない
- 0.25時間(15分)刻み。毎日記録できない日は、週末にまとめて推定で入れ `note` に「推定」と書く

## 5. 指標

| 指標 | 式 | 使い道 |
|---|---|---|
| 売上(確定) | 確定・入金の合計 | P&Lの売上 |
| 営業利益 | 売上(確定) − 費用 | 「月◯万円の利益」 |
| 営業利益率 | 営業利益 ÷ 売上 | 立ち上げ期はマイナスでよい。推移を見る |
| 時間あたり利益 | 営業利益 ÷ 作業時間 | 「週◯時間で月◯万円」。本業の時給と比べない(立ち上げ期は投資) |
| 累計営業利益 | 開始月からの合計 | 投資の回収状況 |
| 計画比 | 実績 ÷ 事業計画書の月次目標 | 差が±30%を超えた項目には一言の理由 |

## 6. 月次の締めの流れ

| いつ | 誰が | 何を |
|---|---|---|
| 月末 09:00 | 事業報告部 | 回収依頼:未記帳の費用・領収書、作業時間の抜け、山行の記録と写真 |
| 翌月1日 06:00 | データ分析部 | 売上の確定値(ASP・SUZURI・Amazon・楽天) |
| 翌月2日 | 事業報告部 | 台帳のCSVを書き出し、`python3 scripts/pl.py <フォルダ> <YYYY-MM>` |
| 翌月3日 | CEO | P&Lを確認して承認(確定)。確定後の修正は台帳の `note` に修正履歴を残す |
| 翌月5日 | 事業報告部 | 月次事業報告書(社内版)に載せて提出 |

## 7. 報告での見せ方

社内版の月次報告書には、次の順で載せる(`templates/monthly-internal.json`)。

1. KPIタイル:売上(確定)/ 営業利益 / 作業時間 / 時間あたり利益
2. P&L表:科目ごとに 当月 / 前月 / 累計 / 計画。合計行は `total_rows` で強調
3. 未確定の売上・未回収の領収書・按分の割合(注記)
4. 作業時間の内訳(横棒グラフ)と、計画した時間配分との差

対外版には、確定した数字だけを「3 収支の状況」に載せる。未確定は載せない。
