# 企画書・発注書・発注表・取材計画の型(企画・編集会議部)

例の件名・日付・キーワードは**書き方の見本**。コンテンツマップに実在する行かどうかは、使うたびにマップで確かめる。

---

## 1. 企画(承認トレイに積む)

1企画 = 1ページ。プロパティ(`console/README.md` 11-1):

| プロパティ | 書くこと |
|---|---|
| 件名 | `企画:<企画名>(<山の名前>向け)` / マップに無いときは `コンテンツマップへの追加提案:<KW>` |
| 状態 | 承認待ち |
| 依頼元 | `planning` |
| 種類 | 企画 |
| 根拠 | 1行に1つ:山の日と残り週数 / 12週ルールの判断 / コンテンツマップの行(シート名・主対策KW・優先度)/ SEO部の検索需要の予測(引用・時点)/ 共食いの確認結果 / 必要な実測と回収する登山 |
| 承認すると | 発注書を出す先と期限(例:SEO部が設計書を11/12までに → コンテンツ制作部が経路Bで執筆し、11/19までに承認トレイへ) |
| 要約 | P1が次に行く日のために何を決められるようになるか(1〜2文) |

本文の json(1つだけ。発注書の全文を `draft` に入れると、コンソールの「詳細」でそのまま読める):

```json
{
  "changes": [
    "山:GW・春山(2027-04-29)。段階0の公式で公開目標 2027-02-04・企画の締切 2027-01-14",
    "コンテンツマップ:新規記事案シートの行「<主対策KW>」(優先度A・未着手)",
    "発注:seo 設計書 → content 執筆(経路B)→ creative サムネ → affiliate 案件とリンク"
  ],
  "links": [{ "label": "つながる既存記事", "href": "https://yamato-outdoor.com/mountain-climbing/boots/salomon-hiking-shoes/" }],
  "draft": { "label": "発注書", "text": "(2章の発注書の全文)" }
}
```

本文の json の下に見出し3「企画の根拠」で、季節×ペルソナの1文・捨てた候補とその理由・3-4の並べ方のどこで選んだかを箇条書きで残す。

## 2. 発注書

承認された企画を、受ける部ごとに1枚ずつ。日報の自分の節の「依頼」には1行で、全文は企画のページの見出し3「発注書(日時)」の下に書く。

```
発注:<企画名> —— 設計書
受ける部:seo(SEO・検索戦略部)
期限:2026-12-10
前工程:なし(この発注が最初)
受け取る物:コンテンツマップの行「<主対策KW>」/ P1の1文「残雪の残る遠征で、いまの装備のまま行けるか」/ 山の日 2027-04-29
完成の条件:docs/articles/<slug>.md(docs/articles/README.md の見出し)が claude/* ブランチにある。共食いの確認結果を含む
次工程:content(経路Bで執筆)。完成したら日報の節で「設計書 完了」と書く
```

部ごとの「完成の条件」の決まり文句:

| 受ける部 | 完成の条件 |
|---|---|
| seo | 設計書が `claude/*` ブランチにある / 検索需要の予測は日報の節に時点つき |
| content | 承認トレイに種類「記事公開」で積まれ、【要実測】【体験を入れる】の数が根拠に書いてある |
| creative | サムネ・図解が承認トレイの `images` に開けるURLで入っている(URLの無い納品は完成ではない) |
| affiliate | 案件と buy-box の位置が承認トレイの依頼(種類「リンク差し替え」等)に `diffs` つきで入っている |
| sns(稼働後) | 告知の投稿案が投稿キューにある(投稿はしない) |
| goods | 季節商品の企画が承認トレイに「企画」で積まれている |
| editorial(更新の発注) | 価格・廃番の確認結果が出典と確認日つきで日報の節にある |

## 3. 発注表(発注台帳)

週報のページの見出し2「発注表」。今週と6週先までの全行を毎週書き直す(完了した行は、完了した週だけ残して翌週に消す)。

| 企画 | 山(D) | 部 | 発注 | 期限 | 状態 | 遅れの理由・取り戻す案 |
|---|---|---|---|---|---|---|
| 残雪期の登山靴の見直し | GW・春山(4/29) | seo | 設計書 | 12/10 | 進行中 | — |
| 残雪期の登山靴の見直し | GW・春山(4/29) | content | 執筆(経路B) | 1/7 | 未着手(前工程待ち) | — |
| 冬の低山の手袋 | 雪山(来年12/15) | content | 執筆(来年向け) | 11/26 | 遅れ(2日) | 承認待ちが4本で新規停止中。修正依頼の反映後に着手 |

- **状態**:未着手(前工程待ち)/ 進行中 / 完了 / 遅れ(◯日)/ 取り下げ
- 遅れは期限の翌朝の morning で拾い、日報の節の「結果」に書く
- 月初に、先月の行から「公開予定日に間に合った発注の割合」を出す(期限内に完了 ÷ 期限が先月だった発注)

## 4. 取材計画(CEOの次の登山で回収する実測)

週報のページの見出し2「取材計画」。**体験の中身(いつ・どこで・何を感じたか)は公開リポジトリにもNotionの公開ページにも書かない。**
中身はCEOの回答として非公開リポジトリ `yamato-outdoor-editorial` の `content/` に入る。企画部が書くのは「何を量ってきてほしいか」だけ。

```
次の登山で回収したいもの(優先順)
1. 「冬の低山の手袋」:山頂の気温と風速、手袋を外した時間(日付と時刻も)—— 【要実測】2か所
2. 「残雪期の登山靴の見直し」:今の靴の実測重量(片足・g)—— 家で量れる
3. 来年用の取材メモ(雪山):霧氷が出ていたか、凍結していた区間と時刻

回収できる山の条件:12〜2月・関西の標高800m以上(金剛山・比良など)。1回の登山で1〜3を全部回収できる
```

- 1回の登山で回収するのは**3件まで**(CEOが山で量れる量には限りがある)
- 家で量れるもの(重量・寸法)は登山と別に分け、すぐ頼む
- 季節の体験は「来年用の取材メモ」として今季のうちに頼み、来年の同じ山の企画の根拠にする
