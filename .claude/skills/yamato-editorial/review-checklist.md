# 公開前審査シート・台帳の型

`SKILL.md` 4章の「公開前審査」で使う。上から順に見て、重大度(B=ブロッカー / M=メジャー / m=マイナー)を付ける。
判定は `SKILL.md` 3-1(ブロッカー0・メジャー1以下で合格)。

---

## 1. 審査シート(1記事1枚。非公開リポジトリ `content/editorial/review-<slug>-YYYYMMDD.md`)

### A. 体験(`docs/content-pipeline/rules.md` R1)

| # | 見ること | 重大度 | 結果 |
|---|---|---|---|
| A1 | 目印以外の体験の文が、すべて根拠(CEOのコメント・取材シート・experience-log)を指させる | B | |
| A2 | 数量・状況・原因・感覚の具体化・頻度・比較・心情の付け足しが無い(R1-2) | B | |
| A3 | 「履き込んで」「何度も」「いつも」「今のところ」「愛用」「〇年使った」が根拠なしに無い(R1-3) | B | |
| A4 | 使用回数・使用期間・「3回使って」に、本文・`.profile`・タイトルで触れていない | B | |
| A5 | `.profile` の中身が `/about` の範囲。登った山・実績を足していない(R7・persona 5章「盛った実績」) | B | |
| A6 | 一般論で体験を代用していない(「一般に〜と言われる」で体験の章を埋めていない。R1-4) | M | |
| A7 | 目印は具体的(何を・どう測って・どこに)で、10か所以下 | M | |

## 2. 差し戻しの文例(✗ → ○)

| ✗ | なぜダメか | ○ |
|---|---|---|
| 「ここ、もう少し具体的に」 | 何を足せばよいか分からない | 「◯◯」:コメント:【メジャー】何が=重量が「軽い」だけで数字が無い。なぜ=実測値を書く(tone-and-manner.md 2-2)。どう=【要実測:右足の重さ(g)・サイズ】を置く |
| 「表現が硬い」 | 好み。ルールが無い | (出さない) |
| 「事実が違うかも」 | 確かめていない | 「◯◯」:コメント:【ブロッカー】何が=1,120gとあるが、メーカー公式は1,180g(サイズ27.0cm・2026-11-01確認・URL)。どう=出典の値と確認日に直す |
| (本文を丸ごと書き直して貼る) | 書く部と審査する部が混ざる | 箇所ごとの修正案「…」に直す(理由:…)だけ |

## 3. 再審査のときに見ること

- 前回の指摘がすべて直ったか(直っていない指摘は、同じ文面で残す)
- 変更された段落の体験の文(A1〜A3)をやり直す。直す過程で体験が足されることがある
- 変更で崩れたもの(h2の本数・内部リンク・字数)

## 4. 事実確認の台帳(`content/editorial/fact-ledger.md`)

1事実1行。記事を公開したら(または最初の実行で)、本文の数字・固有名詞・リンクを全部行にする。

```markdown
| 記事 | 箇所(h2) | 種類 | 本文の値 | 出典URL | 最終確認日 | 結果 | 状態 | 次回 |
|---|---|---|---|---|---|---|---|---|
| salomon-hiking-shoes | 現行シリーズの違い | 仕様 | (本文の値) | https://salomon.jp/… | 2026-11-02 | 一致 | — | 2027-05-01 |
| salomon-hiking-shoes | (用語のリンク) | 出典リンク | ケブラーの解説 | https://www.l-m.co.jp/… | 2026-11-02 | 403 | 依頼済み(制作) | 2026-11-09 |
```

- 種類:価格 / 廃番・型番 / 仕様 / ルート / 制度 / 出典リンク
- 次回:`SKILL.md` 3-3の周期で計算
- 状態:— / 依頼済み(渡した部)/ 未確認(理由)/ 対応済み(日付)。「依頼済み」と「未確認」の数がKPI「情報が古い記事」の元

## 5. 審査の記録(`content/editorial/review-log.md`)

```markdown
| 日付 | 記事 | 種類 | 判定 | B | M | 指摘の種類 | 回目 |
|---|---|---|---|---|---|---|---|
| 2026-11-02 | 比良のリュックの記事 | 記事公開 | 修正依頼 | 1 | 2 | 体験の付け足し / 結論の位置 / 価格の時点 | 1 |
```

同じ「指摘の種類」が2記事で出たら、`SKILL.md` 3-7の一般化に回す。
