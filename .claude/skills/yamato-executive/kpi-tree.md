# KPIツリーと閾値(社長室・経営企画)

BizOpsが週報・月次で使う。**数字は自分で取らない。** データ分析部の確定値(GA4・Search Console・Clarity)と、
アフィリエイト部・グッズ部・事業報告部の報告にある値を、この表に当てはめるだけ。指標の定義はデータ分析部が正。

閾値はすべて**社内の初期値**(2026-11-01に設定)。外部の統計ではない。四半期ごとに実績で見直し、
推奨が外れた型は monthly で見直し案を出す。

---

## 1. ツリー

```
売上(月)
├─ アフィリエイト発生額 = 記事内のアフィリエイトクリック × 発生率 × 平均報酬   (EPC = 発生額 ÷ アフィリエイトクリック)
│   └─ 記事内のアフィリエイトクリック = 記事のPV × 記事内のアフィリエイトクリック率
│       └─ 記事のPV ≒ 検索クリック + 回遊(関連記事・内部リンク)+ 直接・SNS
│           └─ 検索クリック = 表示回数 × CTR
│               └─ 表示回数 = インデックスされた記事 × 記事あたりの表示回数
│                   └─ インデックスされた記事 = 公開・更新した記事 × インデックス率
│                       └─ 公開・更新した記事 = 承認された記事 ← CEOのレビュー ← 【要実測】の回収(CEOの登山)
└─ SUZURI売上 = ショップへの遷移(cv_click の shop)× 購入率 × 単価

想起(売上の先行指標。STANDARDS 2章)
├─ 指名検索:Search Consoleのクエリに「yamato outdoor」「ヤマトアウトドア」を含む表示・クリック
├─ 直接流入・リピート訪問(GA4)
├─ soft CV:cv_click の cv_stage=soft(メール・LINE・SNSフォロー)
└─ AI検索からの流入(traffic_source_kind = ai)と、SNSでの名前の言及
```

| 数字 | 出どころ(取る部) | 定義の正 |
|---|---|---|
| 公開・更新の本数 | データ分析部(microCMS) | `console/README.md` 10-1 |
| インデックス率 | SEO部(Search Console) | SEO部のスキル |
| 表示回数・検索クリック・CTR | データ分析部・SEO部(Search Console。直近7日・昨日まで) | `docs/analytics.md` 4章 |
| PV・回遊(related_click・toc_click)・読了 | データ分析部(GA4) | `docs/analytics.md` 2-4 |
| 記事内のアフィリエイトクリック | データ分析部(GA4の click_outbound で affiliate_network ≠ none) | `docs/analytics.md` 2-5 |
| アフィリエイト発生額 | アフィリエイト部・事業報告部(ASPのCSV) | 分析部の確定値 |
| SUZURI売上 | グッズ部・事業報告部 | 分析部の確定値 |
| soft CV | データ分析部(GA4の cv_click) | `docs/analytics.md` 7章 |
| 承認待ち・滞留日数 | 承認トレイ(Notion) | このファイル |
| 【要実測】【体験を入れる】の残り | 承認トレイの記事本文の印の数(コンテンツ制作部の報告) | このファイル |

## 2. 段階(ステージ)と、判断に使う数字

| 段階 | 入る条件(どれか1つ) | 抜ける条件(すべて) | 判断に使う | 見るだけ |
|---|---|---|---|---|
| 0 立ち上げ | 公開記事30本未満 / 検索クリック月1,000未満 | 公開30本以上かつ検索クリック月1,000以上が2か月続く | 本数・インデックス率・表示回数・承認の滞留・実測の残り | 売上・CTR・EPC |
| 1 牽引 | 検索クリック月1,000〜10,000 | 月10,000超が2か月続く | CTR・記事内のアフィリエイトクリック率・soft CV・回遊率 | EPC・単価 |
| 2 収益化 | 検索クリック月10,000超 | — | EPC・記事別の発生額・案件単価・指名検索・リピート | — |

段階を上げ下げしたら、週報の冒頭に「段階が◯→◯になった。判断に使う数字を◯◯に切り替える」と書く。

## 3. ボトルネックの閾値(上流から順に見る)

上から順に見て、**最初に当たった行**がボトルネック。当たる行が無い週は「ボトルネックなし。段階の主指標を伸ばす週」とする。

| 順 | 段 | 閾値(当たったらボトルネック) | 誰に何を頼む案にするか |
|---|---|---|---|
| 1 | 実測の回収 | 承認トレイの記事本文の【要実測】【体験を入れる】が合計10か所以上、または同じ記事で21日以上残る | 企画・編集会議部:CEOの次の登山1回で回収できる実測を束ねた取材計画 |
| 2 | CEOのレビュー | 種類「記事公開」の承認待ちが4本以上、または最長7日以上滞留 | コンテンツ制作部:新規を止めて修正依頼の反映を先に。経営企画:決めてほしいことを減らす |
| 3 | 公開の本数 | 公開・更新が2週続けて週1本未満(目標は週2本。`CLAUDE.md`「新しい記事はAIが書いて承認トレイに積む(週2〜4本)」) | 企画・編集会議部:発注表の遅れの解消 |
| 4 | インデックス | 公開から14日たった記事のうち、インデックスされていないものが20%超 | SEO部:インデックスの原因の切り分けと内部リンクの穴埋め |
| 5 | 表示回数 | 4週移動平均の表示回数が、前の4週より下がった(段階0は「伸びていない」こと自体を見る) | SEO部:クエリの取りこぼしの調査 / 企画:季節の山とのずれの確認 |
| 6 | CTR | SEO部が持つ「掲載順位ごとのCTRの目安」を、表示回数の多い上位10ページの半数以上が下回る | SEO部:タイトル・概要の見直し候補 |
| 7 | 記事内のアフィリエイトクリック | 月100PV以上で buy-box のある記事で、アフィリエイトクリック率(アフィリエイトクリック ÷ PV)が1%未満 | アフィリエイト部:案件と置き場所の点検 |
| 8 | 再訪(想起) | soft CVの受け口がすべて空 / 受け口があるのに soft CV率(soft CV ÷ 記事のセッション)が0.3%未満 | CEO:受け口を開ける判断 / コミュニティ部・SNS部:受け口の準備 |
| 9 | 収益 | EPCが前月比で30%以上下がった(段階2のみ判断に使う) | アフィリエイト部:報酬率の変更・提携終了の確認 |

閾値が「数字が取れない」ために判定できない行は、ボトルネック扱いにせず「判定不能:<数字>が未取得」と週報に書く。
同じ行が3週続けて判定不能なら、その数字をつなぐことを優先3つの候補に入れる(数字が無いこと自体がボトルネックになっている)。

## 4. 想起の固定行(週報に毎週書く)

| 行 | 数字 | 判断 |
|---|---|---|
| 指名検索 | Search Consoleで「yamato outdoor」「ヤマトアウトドア」を含むクエリの表示・クリック(7日) | 段階0では「出始めたか」だけ見る |
| 直接流入 | GA4の direct のセッション | 自分のアクセスを除けているか(内部トラフィックのフィルタ)を分析部に確認してから使う |
| リピート | GA4のリピーター数 | 月次で見る(週次はぶれる) |
| soft CV | cv_click の cv_stage=soft | 受け口が無ければ「受け口なし」 |
| AI検索 | traffic_source_kind = ai のセッション | 1件でも出たら、その記事名を週報に書く(書き方が効いている証拠。`docs/analytics.md` 11章) |
