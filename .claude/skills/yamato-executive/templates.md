# 出力の型(社長室・経営企画)

例の数字・件名はすべて**書き方の見本**。実在の数字ではない。実際に書くときは出どころと時点を必ず添える。

---

## 1. 日報の締め(毎日・evening)

日報のページの本文の末尾に、見出し2「経営企画のまとめ」を置く。プロパティにも同じ内容を入れる。

```
## 経営企画のまとめ
本日の合計:売上 未取得(ASPのCSVはコンソールのブラウザ内のみ)/ PV 42(GA4・分析部の確定値・11/2 20:30時点)/ 公開1・更新0(microCMS)
段階0・ボトルネック:CEOのレビュー(記事公開の承認待ち4本・最長9日)

明日の優先3つ
1. 「登山 手袋」記事の修正依頼を反映して承認待ちに戻す(content)—— 滞留を4→3本に
2. 雪山の需要の山(12/15)向け企画の発注表を確定(planning)—— 公開目標日まで残り13日
3. 指名検索の計測行を週報に追加(analytics)—— 想起の固定行

決めてほしいこと(2件)
1. メール登録の受け口を開けるか → 推奨:開ける(Googleフォーム1枚)。期限:11/9。詳細は承認トレイ「企画:soft CVの受け口を1つ開ける」
2. 釣りジャンルを来年3月の渓流解禁に向けて開くか → 推奨:今回は見送り。期限:12/1
```

プロパティ:「決めてほしいこと」は件名だけを1行ずつ、「明日の優先3つ」は番号つきで3行。数字のプロパティは取れたものだけ。

## 2. 週報(毎週月曜・weekly)

タイトル `YYYY-MM-DD 週報`。見出しの順番を変えない(CEOは毎週同じ位置を見る)。

```
## 1. 今週の結論(3行)
- 段階0。ボトルネックは「CEOのレビュー」(先週と同じ)
- 先週の優先3つは 1.5/3
- 決めてほしいこと:2件(下の5)

## 2. 本部ごとの数字(出どころ・時点)
| 本部 | 数字 | 先週 | 今週 | 出どころ |
| プロダクト・コンテンツ | 公開・更新 | 1 | 2 | microCMS(分析部) |
| プロダクト・コンテンツ | 表示回数(7日) | 未取得 | 310 | Search Console(分析部) |
| ビジネス・レベニュー | アフィリエイト発生 | 未取得 | 未取得 | CSVはブラウザ内のみ |
| コーポレート | 名簿のずれ | 3 | 1 | 人事部 |

### 想起の固定行
指名検索 0 / 直接流入 未取得(内部トラフィックの除外を確認中)/ soft CV 受け口なし / AI検索 0

## 3. 段階とボトルネック
<kpi-tree.md 3章のどの行に当たったか。根拠の数字>

## 4. 先週の優先3つの採点
| # | 優先 | 結果 | 採点 | 理由(やらなかった / やったが動かなかった / 外部要因) |

## 5. 今週の優先3つの案
| # | 何を | どの数字を・いつまでに・どれだけ | 担当の部(案) | I | C | E | CEO負荷 | 点 |
今週やらないこと:<4位以下を1行ずつ>

## 6. 決めてほしいこと
<意思決定メモ(4章)を件数分。長いものは承認トレイへのリンク>

## 7. 決定ログ
<5章の表>

## 8. 仕組みの提案
<境界表に足す行・閾値の見直し・部の分割など。無ければ「なし」>
```

## 3. 月次の振り返り(毎月1日・monthly)

```
## 1. 先月の結論(3行)
## 2. 数字(分析部の月次の確定値・事業報告部のP&L下書きから転記)
## 3. 優先3つの達成率と決定ログの完了率
   週ごと:1.5 / 2 / 1 / 2.5 → 月 58%。決定ログ 12件中 完了8・進行中3・取り下げ1
## 4. 判断の振り返り
   | 先月の推奨 | 採用 | 数字はどう動いたか | 推奨が外れた理由(外れたときだけ) |
## 5. 来月の重点の案(最大2つ)
## 6. 組織の見直し(ORG.md 7章に当たる部があれば)
## 7. 閾値の見直し案(kpi-tree.md。外れた推奨が2回続いた型)
```

四半期の初月は「5」に四半期の目標を足し、承認トレイにも積む:

```
O:関西の日帰り登山の装備で、YAMATO OUTDOORの記事がGoogleに載り始める
KR1:公開・更新 24本(週2本)
KR2:公開14日後のインデックス率 80%以上
KR3:soft CVの受け口を1つ開け、受け口からの登録を1件以上
```

## 4. 意思決定メモ(CEOに決めてほしいこと 1件)

CEOが**Yes / No か、A / B で答えられる**形にする。5行で収まらないものは承認トレイに積み、日報・週報には1行とリンク。

```
問い:メール登録の受け口(Googleフォーム)を開けてよいか(Yes / No)
推奨:Yes。戻せる判断(URLを空に戻せば消える)
理由:soft CVの受け口が0のため、P1(ブックマークしない・検討期間2〜6週間。docs/persona.md)の2回目の訪問を作れない。
      記事末のCV枠は site.ts の NEWSLETTER_URL を入れるだけで出る(docs/analytics.md 7-2)
やらない場合:記事が読まれても再訪の口が無いまま。想起のKPI(soft CV)が測れない
期限:11/9(冬の需要の山の前に受け口をそろえたい)
承認すると:サイト開発部が site.ts にURLを入れる変更を claude/* ブランチに作り、mainへのマージを承認トレイに積む
```

承認トレイに積むときのプロパティ(`console/README.md` 11-1):

| プロパティ | 値 |
|---|---|
| 件名 | `企画:<問いを短く>` |
| 状態 | 承認待ち |
| 依頼元 | `executive` |
| 種類 | 企画 |
| 根拠 | 1行に1つ。数字には出どころと時点 |
| 承認すると | 誰が・何をするか(経営企画は実行しない) |
| 要約 | 何を・なぜ(1〜2文) |

本文の json(1つだけ。意思決定メモの全文を `draft` に入れると、コンソールの「詳細」でそのまま読める):

```json
{
  "changes": ["推奨:Yes(戻せる判断)", "承認後:サイト開発部が site.ts の変更を claude/* ブランチに作る"],
  "links": [{ "label": "CV設計(docs/analytics.md 7章)", "href": "https://github.com/aoi7160/yamato-outdoor/blob/main/docs/analytics.md" }],
  "draft": { "label": "意思決定メモ", "text": "問い:…\n推奨:…\n理由:…\nやらない場合:…\n期限:…" }
}
```

## 5. 決定ログ(Decision Log)

週報の見出し2「決定ログ」に表で持つ。行は消さない(取り下げも残す)。

| 決定日 | 決定 | 決めた人 | 出どころ | 担当の部 | 期限 | 状態 |
|---|---|---|---|---|---|---|
| 11/2 | 雪山の企画「冬の六甲の手袋」を進める | CEO | 承認トレイ「企画:…」承認 | planning → seo・content | 公開 11/30 | 進行中 |
| 11/2 | 釣りジャンルは来年度まで開かない | CEO | 週報の決めてほしいこと | — | — | 完了 |

- **状態**:進行中 / 完了 / 遅れ(期限を過ぎた)/ 取り下げ(理由を決定の列に追記)
- 決まっていないことは「未決」の箇条書きに分け、表に入れない。「〜の方向で」は決定ではない
- CEOの判断の出どころは、承認トレイの「CEOの判断(日時)」の見出しか、週報への返信。会話で決まったことは、日時と「会話で」と書く

## 6. 承認トレイの確認メモ

依頼の根拠が欠けているときに、そのページ本文に足す。状態は変えない。

```
### 経営企画の確認(2026-11-02 20:50)
- 根拠に報酬の確認日がありません(案件台帳の行の確認日を書いてください)
- 「承認すると」に、誰が何をするかが書かれていません
→ 補ったら、この見出しの下に「補った(日時)」と1行足してください
```
