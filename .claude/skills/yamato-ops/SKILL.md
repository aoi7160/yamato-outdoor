# 運営の時間割(社長室・経営企画が進行役)

引数:`morning` / `evening` / `weekly` / `monthly` のどれか1つ(無ければ、いまの日本時間から一番近いものを選ぶ)。

## 0. 始める前に(毎回)

1. 作業ディレクトリに `aoi7160/yamato-outdoor` が無ければ、add_repo で追加してクローンする。
   非公開の `aoi7160/yamato-outdoor-editorial` も、使う部があれば同じ階層にクローンする
2. `CLAUDE.md` と `.claude/skills/yamato-ops/STANDARDS.md`(全部署の共通基準)を読む
3. Notion「YAMATO BASE CAMP」を検索して開き、「日報・週報」「承認トレイ」「案件台帳」の場所を確かめる。
   **Notionにつながっていなければ、ここで止めて「Notionにつながっていないため実行できませんでした」と報告する**
4. 「日報・週報」に今日(日本時間)のページ `YYYY-MM-DD 日報`(種類:日報・状態:未読・日付:今日)が無ければ作る。
   本文に見出し2「各部の報告」を置いておく

## 1. 時間割

各行の部のスキル(`.claude/skills/yamato-<id>/SKILL.md`)を開き、その「定例の手順」のうち、該当する頻度の手順を実行する。
**1つの部が失敗しても止めない。** 失敗した理由をその部の節に1行書いて、次の部へ進む。

### morning(毎日 6:41)—— その日の判断材料をそろえる

| 順 | 部 | やること(詳細は各スキル) |
|---|---|---|
| 1 | `yamato-analytics` | 前日の数字を確定させる(取れない数字は未取得と理由) |
| 2 | `yamato-seo` | 順位・インデックス・サイト内のリンク切れの差分 |
| 3 | `yamato-editorial` | 公開記事の定期の事実確認(価格・廃番。曜日ローテーション)と校閲チェックの結果 |
| 4 | `yamato-affiliate` | 提携状況・セール・リンクの点検(木曜は案件台帳の全件点検) |
| 5 | `yamato-planning` | 需要カレンダーと承認トレイを見て、本日の発注を決める |

### evening(毎日 20:47)—— 1日を締めて、CEOに渡す

| 順 | 部 | やること |
|---|---|---|
| 1 | `yamato-reporting` | 当日の売上・費用・作業時間の記帳(分かる範囲) |
| 2 | `yamato-hr` | 今日動いた定期実行・スキルの記録(動かなかった部があれば名簿と照合) |
| 3 | `yamato-executive` | 日報の締め:本日の合計・明日の優先3つ・CEOに決めてほしいこと(日報のプロパティも埋める) |

### weekly(毎週月曜 7:43)—— 今週の優先順位を決める

| 順 | 部 | やること |
|---|---|---|
| 1 | `yamato-analytics` | 週次の数字(先週比・記事別) |
| 2 | `yamato-seo` | コンテンツマップの次の候補・リライト候補・内部リンクの穴 |
| 3 | `yamato-planning` | 編集会議:6〜8週間先の需要の山から企画を決める |
| 4 | `yamato-creative` | 制作キュー(サムネ・図解)を消化する |
| 5 | `yamato-sns` | 今週の投稿キューを作る(投稿はしない) |
| 6 | `yamato-community` | 今週の配信案を作る(配信はしない) |
| 7 | `yamato-goods` | グッズの企画・販売の点検 |
| 8 | `yamato-hr` | 名簿の棚卸し(定義と実体のずれ) |
| 9 | `yamato-executive` | 週報:本部ごとの数字・先週の優先3つの結果・今週の優先3つの案 |

### monthly(毎月1日 8:13)—— 月を締めて、仕組みを見直す

| 順 | 部 | やること |
|---|---|---|
| 1 | `yamato-analytics` | 月次の数字の確定 |
| 2 | `yamato-reporting` | 月次P&Lの下書きと事業報告書(社内版)の下書き |
| 3 | `yamato-legal` | サイト全体の監査(外部送信の公表・広告表記・画像の権利) |
| 4 | `yamato-dev` | パフォーマンスと依存関係の月次点検 |
| 5 | `yamato-partnership` | 連絡先リストの更新と、提案書の下書き(連絡はしない) |
| 6 | `yamato-executive` | 月次の振り返りと、来月の重点の案 |

### 時間割の外で動く部

- `yamato-content`(+ `write-article`):記事の執筆・修正依頼の反映。定期実行「YAMATO 記事の自動執筆」(月・木 5:52)と、頼まれたとき
- `yamato-editorial` の公開前審査:記事が承認トレイに積まれたとき
- `yamato-dev`:改修を頼まれたとき
- 各部:CEOに直接頼まれたとき

## 2. 締め

1. 日報のページの「各部の報告」に、この回で動いた部の節がそろっているか確かめる(無い部は「未実行:理由」)
2. 承認トレイに積んだもの(件名)を日報の「各部の報告」の最後に箇条書きで足す
3. 最後に、日本語で3行以内で報告する:動いた部の数 / 積んだ承認依頼の数 / CEOに決めてほしいこと(あれば)

## 3. やらないこと

- L2(公開・mainへのマージ・SNS投稿・配信・外部への連絡・お金が動くこと)。承認トレイに積むまで
- コンテンツマップ(スプレッドシート)の書き換え
- 公開リポジトリへの社外秘の記録(STANDARDS 5章)
- 数字を作ること。取れない数字は「未取得」と理由
