# 文書の型・データの取り方・出す前のチェックリスト(事業報告部)

スキル `yamato-reporting` の参照ファイル。事業報告書・事業計画書は**Notionのページ**で作る
(置き場所:「YAMATO BASE CAMP」→「日報・週報」の子ページ、または「事業報告」ページ)。
PDFが要ると頼まれたときは、Notionの内容から `anthropic-skills:pdf` スキルで作る(専用のスクリプトは未実装)。
**金額・作業時間・写真・メンバーの氏名は公開リポジトリに書かない。**

---

## 1. 月次事業報告書(社内版)—— 毎月5日まで

読み手:CEO・メンバー。目的:先月の事業を、数字と出来事で1ページで分かるようにする。**方針・優先順位はCEOが承認したものだけ**を書く(案は経営企画)。

## 2. 事業報告書(対外版)—— 四半期の翌月10日まで(下書き)

読み手:投資家・金融機関など社外。**送るのはCEO本人**。下書き → 法務(表現・権利)→ CEO。

```
# YAMATO OUTDOOR 事業報告(YYYY年 第◯四半期)

## 事業の概要
- Mission:挑戦の、ベースキャンプになる。(docs/persona.md 0章の表記どおり)
- 何をしているか:関西の山の装備とルートを、実際に使い・歩いて記録するメディア / 自社のグッズ(SUZURI)
- 三階建て:記録する(稼働中)/ 作る(立ち上げ)/ 送り出す(構想)。docs/persona.md 1章の「今」の欄を写す

## 実績(四半期。確定値だけ)
| 指標 | 当四半期 | 前四半期 | 定義と出どころ |
|---|---|---|---|
| 売上 | | | P&L台帳(確定ベース) |
| 営業利益 | | | |
| 公開記事数 | | | microCMSの公開記事 |
| 月間PV(四半期の平均) | | | GA4(データ分析部の確定値) |
| soft CVの登録者 | | | LINE・メール(受け口があれば) |

## 主な取り組みと結果
- <事実と数字。見込みは「見込み」と書く>

## 課題と次の四半期(CEOが承認した方針)
```

対外版の決まり:
- **見込み・計画は、実績と分けて「見込み」「計画」と書く。** 実績の表に混ぜない
- 提携先・取引先の名前は、相手の同意があるもの(PR部の台帳で「公表可」と確認できるもの)だけ
- メンバーの写真・氏名は、本人の同意をCEOが確かめたものだけ
- 指標には定義を付ける(「PV=GA4の表示回数」など)。前の四半期と定義が変わったら注記
- 盛らない。悪い数字も同じ表に載せる(Editorial Policyの「合わなかった点を同じ分量で」と同じ姿勢)

## 3. 事業計画書の清書 —— 経営企画の案がCEOに承認されたとき

- 中身は経営企画の案のまま。この部がやるのは**清書と数字の整合だけ**(計画の数字がP&Lの科目と同じ定義か、足し算が合うか、実績の欄が台帳と一致するか)
- 整合しない箇所は直さずに、経営企画に「<箇所>:<何と何が合わない>」と返す
- 月次の計画値は、Notion「月次の締め」の「計画との差」の元になる表(科目×月)に写す

## 4. 出す前のチェックリスト

検算:
- [ ] 台帳の明細の合計 = 月次の締めの売上・費用(1円でも違えば出さない)
- [ ] 営業利益 = 売上 − 費用。時間あたり利益 = 営業利益 ÷ 作業時間(作業時間が空なら空欄)
- [ ] 前月の報告書の「今月」= 今月の報告書の「先月」(確定後に直したなら修正履歴がある)
- [ ] 売上がデータ分析部の確定値と一致(集計し直していない)

出どころ:
- [ ] 表のすべての数字に、出どころと時点がある
- [ ] 取れなかった数字は空欄で、理由(未接続・未取得・CEO未入力)がある。0と書いていない
- [ ] 推測(写真から読んだ天気・人数など)は「推測」と書き、CEOの確認待ちにしている

中身:
- [ ] 方針・優先順位はCEOが承認したものだけ(案を書いていない)
- [ ] 対外版:見込みと実績を分けた / 社名・氏名・写真の同意 / 法務の確認を経た
- [ ] 使わない語(最強・保存版・初心者必見 ほか)・「山行」が無い。数字は半角・桁区切り(`docs/tone-and-manner.md` 2-2)
- [ ] 公開リポジトリに金額・時間・氏名・写真を書いていない

## 5. 活動の記録の取り方(記録AI)

月の活動は、**日付で絞り込みすぎずに**漏れなく拾う(未マージのブランチ・閉じたPull Requestも含む)。

| 何を | どこから | どう取るか |
|---|---|---|
| コードの変更 | 公開リポジトリの全ブランチ | `git fetch --all` のあと `git log --all --since=<前月1日> --until=<当月1日> --format='%ad %d %s' --date=short`。マージ済みかは `git branch -r --merged origin/main` で分ける |
| Pull Request | GitHub | `gh pr list --state all --search "updated:>=<前月1日>"`(つながらなければ「未取得」) |
| 記事 | microCMSの公開記事・校閲部と制作部の日報の節 | 公開日・更新日が前月のもの |
| 各部の出来事 | Notion「日報・週報」の前月のページ | 各部の節の「やったこと」と承認トレイの「対応済み」 |
| 登山 | 登山記録DB | 前月の行。推測が残る行はCEOに確認 |
| 非公開の記録 | 非公開リポジトリ `yamato-outdoor-editorial` | 取材・実体験の追加(ファイルの追加だけ数える。中身は写さない) |

公開リポジトリの `docs/roadmap.md` を含む `claude/media-roadmap-creation-*` ブランチは**読むだけ**(mainに入れない。CLAUDE.md)。
