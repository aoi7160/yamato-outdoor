# アフィリエイト部の出力テンプレート(実例つき)

実例の数字は、`console/agents/affiliate.md`(2026-10-21調査)に載っている公開条件だけを使っている。
**提携状況はすべて「未申請」**(2026-11-01時点の事実)。

## 1. 案件台帳(Notion)の行

| 項目 | 書き方 | 例 |
|---|---|---|
| 案件名 / ASP | 「案件名(ASP)」 | Jackery ポータブル電源(A8.net) |
| 報酬 | 料率または単価+**確認日** | 4%(2026-10-21確認・案件の公開ページ) |
| Cookie(有効期間) | 日数+確認日 | 90日(2026-10-21確認) |
| 提携状況 | 未申請 / 審査中 / 提携中 / 終了予定 / 終了 | 未申請 |
| ピラー | P01〜P08 | P06 小物・携行品 |
| 使っている記事 | 公開記事のURL。設計だけなら `<slug>(予定)` | winter-camp-power(予定) |
| メモ | 1,000クリックあたりの期待確定額(SKILL 3-2)・SNS掲載の可否・終了予定・否認条件・旧→新の変更履歴 | 期待確定額 約21,600円(CVR0.5%は仮置き)。SNS掲載可否は提携時に確認 |

**台帳に書かないもの:** 管理画面の実際の発生額・個別の特別単価(公開リポジトリには元々書かないが、Notionでも「特別単価あり(条件は管理画面)」程度にとどめる)。

## 2. リンク設計書(非公開リポジトリ `content/affiliate/link-plans/<slug>.md`)

```markdown

- 設計日:2026-11-02 / 設計:アフィリエイト部(リンク設計AI)
- 記事の状態:承認トレイ「記事公開」承認待ち(microCMSの下書き:なし)
- 検索意図:情報+購買(コンテンツマップの検索意図の列)

## 置く製品(ゲートを通ったもの)

| 製品 | G1 判断基準 | G2 検証 | G3 店 | G4 規約 | 置く場所 | 店の順 | 案件の状態 |

| サロモン X ULTRA 5 MID GORE-TEX | 結論の早見表と「実レビュー」の節 | 運営者が実際に履いた | Amazon・楽天 | 提携時に確認 | ①早見表の直下 ②実レビューの節の終わり | Amazon → 楽天 → Yahoo! | 未提携:もしも |

- <製品名>:比較表に名前が出るだけで、判断基準を書いていない(G1)
```

## 3. 承認トレイ「リンク差し替え」(提携中の案件があるときだけ)

| プロパティ | 例 |
|---|---|
| 件名 | 「サロモンの登山靴」の記事に購入リンクを2か所追加 |
| 状態 | 承認待ち |
| 依頼元 | affiliate |
| 種類 | リンク差し替え |
| 根拠 | 本文で判断基準を書いた製品(実レビューの節)/ もしも(Amazon・楽天)提携中(YYYY-MM-DD確認)/ 記事のPV(分析部・期間)/ 1記事のbuy-box 1つ・同じ製品2か所まで |
| 承認すると | コンテンツ制作部がmicroCMSの本文に差分を反映 → 校閲部が広告表記を確認 → CEOが公開 |
| 要約 | 実際に履いた登山靴に、読者が決める場所(早見表の下・実レビューの節末)にだけ購入リンクを置く |

本文の json(1つだけ):

```json
{
  "cms": { "contentId": "microCMSの既存記事のID" },
  "links": [{ "label": "公開中の記事", "href": "https://yamato-outdoor.com/mountain-climbing/boots/salomon-hiking-shoes/" }],
  "changes": [
    "冒頭に pr-notice を追加",
    "結論の早見表の直下に buy-box を追加(Amazon → 楽天)",
    "「実レビュー」の節の終わりに同じ buy-box を追加"
  ],
  "diffs": [
    {
      "where": "記事の冒頭",
      "before": "<p>(リード1段落目)</p>",
      "after": "<p class=\"pr-notice\">※ 本記事にはアフィリエイトリンクを含みます。報酬の有無で評価は変えていません。</p><p>(リード1段落目)</p>",
      "why": "景品表示法のステマ規制に沿って、広告であることを最初に明示する。P1は広告を隠す記事を最も嫌うので、先に言うほうが信頼が残る"
    },
    {
      "where": "結論の早見表の直下",
      "before": "</table>",
      "after": "</table><div class=\"buy-box\">…(リンク設計書のbuy-box。hrefは管理画面のテキストリンク)…</div>",
      "why": "P1は目次から結論だけ拾い読みする。決めた直後の位置に置くと、本文の途中に何度も挟まずに済む"
    }
  ]
}
```

`preview` は、microCMSに実際の下書きがあるときだけ書く。

## 4. 承認トレイ「企画」—— ASP登録の提案

| プロパティ | 例 |
|---|---|
| 件名 | ASP登録の提案:もしもアフィリエイトとA8.net |
| 依頼元 | affiliate |
| 種類 | 企画 |
| 根拠 | 公開記事 N本(sitemap.xml・YYYY-MM-DD)/ リンク設計済みの記事 N本・置ける製品 N点(設計書)/ /privacy・/about あり / CONTACT_URL:空 → 受け口の作成をサイト開発部に依頼済み |
| 承認すると | CEOが各社に会員登録(本人確認・口座・サイト審査)→ 登録できたら台帳の提携状況を更新するようAIに伝える → 段階1へ |
| 要約 | 設計済みの記事の購入リンクを置くために、最初の2社に登録する。登録のボタンはCEOが押す |

## 5. 日報の自分の節

例(「4本(9点)」などの数字は書き方の説明用。実際の値は設計した結果を書く):

```
### アフィリエイト部
- 結果:提携中0件・未申請23件(案件台帳・11/02)。リンクがある公開記事0本(sitemap.xml・11/02)
- 判断:承認トレイの10本のうち、置ける製品があるのは4本(9点)。ハウツー・ルートの6本は設計なし
- やったこと:4本のリンク設計書を作成(URLなし)。必要な提携はもしも・A8.netの2社
- 依頼:CEO:公開記事が5本になったらASP登録の提案を積みます / 企画部:ブラックフライデーは11月下旬見込み(公式未発表)
```

動きが無い日は1行:`- 結果:提携中0件・期限の近い行なし・リンク切れの報告なし(11/02朝)`
