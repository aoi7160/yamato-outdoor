## ミッション

記事の中の「次に買うもの」を、読者の準備に合う案件につなぐ。
**売りたい商品から記事を作らない。** 記事(読者の課題)が先で、案件はあとから当てる(`docs/persona.md` の編集方針)。
**報酬の有無で評価を変えない。** 使っていない・確かめていない製品を「おすすめ」としてリンクしない。

## いまの状態(2026年10月)

- サイトのアフィリエイトリンクは **0本**(公開記事はサロモンの記事だけで、外部リンクはメーカー公式のみ)
- ASPの登録状況は未確認(CEOに確認する)
- だから当面の仕事は「稼ぐ」より **「正しく置ける状態を作る」** こと。段階ごとに進める

## 段階ごとの仕事

### 段階0 準備(いま〜1か月)

| やること | 誰が | 承認 |
|---|---|---|
| どのASPに登録するかの案を出す(下の「ASPの選び方」) | 案件リサーチAI | CEO |
| ASPに会員登録する(本人確認・振込口座・サイト審査) | **CEO本人**(AIはできない) | — |
| 案件台帳(Notion「YAMATO BASE CAMP」→「案件台帳」)を作り、コンテンツマップのピラーごとに当てはまる案件を調べて入れる | 案件リサーチAI | — |
| Amazonのリンクを置くなら、Amazonが求める表記(「Amazonのアソシエイトとして…適格販売により収入を得ています」)をサイトに載せる案 | リンク設計AI → 法務部 → サイト開発部 | CEO(mainへのマージ) |
| 使うASPのドメインが `src/lib/article.ts` の `AFFILIATE_HOSTS` に入っているかの確認(入っていないと `rel="sponsored nofollow"` が付かない) | リンク設計AI → サイト開発部 | CEO(mainへのマージ) |

**ASPの選び方(案。登録前に各社の最新の規約を確かめる)**

1. **もしもアフィリエイト**:Amazon・楽天・Yahoo!ショッピングの商品を1つのリンク枠で並べられる。立ち上げ期のサイトでも通りやすい。**最初の1社**
2. **A8.net**:メーカー直販・アウトドア専門店の案件の数が多い。記事が増えてから専門店案件を探す先
3. **楽天アフィリエイト**:審査なしで始められる(報酬は楽天ポイント)
4. **Amazonアソシエイト(直接)**:登録後の一定期間内に売上の実績が要る。アクセスが無いうちに申し込むと落ちやすいので、**もしも経由で売れ始めてから**
5. バリューコマース・アクセストレード:専門店・ブランドの案件が見つかったときに足す

### 段階1 最初のリンク(ASPに登録できたら)

- 既存のサロモンの記事に、**実際に履いた X ULTRA 5 MID GORE-TEX** のリンクを置く案を作る
  (位置:結論の早見表の下・「実レビュー」の節の終わり。読者が決める場所に置き、本文の途中に何度も挟まない)
- 置き方は承認トレイの「リンク差し替え」に**変更前/変更後と理由(why)**を付けて積む。本文の編集はコンテンツ制作部
- 冒頭に `<p class="pr-notice">` を置く(校閲チェックの「広告表記」で自動で確かめられる)
- 以後、コンテンツ制作部が書く新しい記事には、承認トレイに積まれた時点で**案件とリンク位置の案**を付ける(毎週月曜)

### 段階2 運用(記事が10本を超え、クリックが毎週出るようになったら)

- 記事別のEPC(発生 ÷ クリック)を見て、同じ製品でもリンクの並べ方(Amazon・楽天・メーカー直販の順番)を見直す
- 案件台帳から、専門店・ブランドの案件(A8.net・バリューコマース等)を足す。報酬率だけで選ばず、**読者が実際に買う店か**で選ぶ
- セールの前に、対象になりやすい記事のリンクを点検する

## 1記事あたりのリンクの約束

- リンクを置くのは、**本文で判断基準を書いた製品だけ**。比較の表・結論・実レビューの節末に置く
- 同じ製品のリンクは1記事に2か所まで(結論と、詳しく書いた節)
- 価格を本文に書くときは「調べた時点」を添える(`docs/tone-and-manner.md` 2-2)。リンクの横に価格を固定で書かない(すぐ古くなる)
- 「最安」「今だけ」など、確かめていない言葉を書かない(景品表示法)
- アフィリエイトを含む記事は冒頭に `pr-notice`(`docs/analytics.md` 6-3)

## 案件台帳(Notion)

1案件1行。案件リサーチAIが毎週木曜に点検する。

| 項目 | 書くこと |
|---|---|
| 案件名 / ASP | 例:「〇〇ストア(A8.net)」 |
| 報酬 | 報酬率または単価。**確認日**を添える |
| Cookie(有効期間) | 各ASP・案件の条件 |
| 提携状況 | 未申請 / 審査中 / 提携中 / 終了予定 / 終了 |
| ピラー | コンテンツマップの P01〜P08 |
| 使っている記事 | 記事のURL(複数) |
| メモ | 終了予定日・セールの予定・注意点 |

## スケジュール(1週間・1か月・1年)

**毎週**

| 曜日 | 時刻 | やること | 誰が |
|---|---|---|---|
| 月 | 09:30 | 今週の新しい記事に案件とリンク位置の案を付ける(承認トレイ) | リンク設計AI |
| 月 | いつでも | ASP各社の管理画面からCSVを書き出し、コンソールの「データ取り込み」に入れる(5分) | **CEO** |
| 木 | 10:00 | 案件台帳の点検(提携状況・報酬率・終了予定) | 案件リサーチAI |
| 毎日 | 19:00 | 定例ヒアリング(1文。CSVが7日より古い・提携終了があるときは3〜5文) | 収益分析AI |

**毎月**

| 日 | やること | 渡す先 |
|---|---|---|
| 1日 | 前月の発生・確定・EPC・記事別の成績 | 事業報告部(P&Lは確定ベース)・データ分析部 |
| 第3週 | 公開記事のアフィリエイトリンクの点検(リンク切れ・提携終了・広告表記) | 校閲部・コンテンツ制作部(直すものは承認トレイへ) |
| 各ASPの支払日 | 確定額と入金の照合 | 事業報告部 |

**毎年(セールの山。需要カレンダー・企画部と共有)**

| 時期 | セール | この部がやること(3週間前まで) |
|---|---|---|
| 1月 | 初売り | 冬山・防寒の記事のリンク点検 |
| 3・6・9・12月 | 楽天スーパーセール(例年) | 楽天リンクのある記事の点検 |
| 7月 | Amazonプライムデー | 夏山・登山靴・ザックの記事の点検 |
| 11月下旬 | ブラックフライデー | 登山靴・ウェアの記事の点検。セール情報を企画部へ(6週間前) |
| 毎月 | 楽天お買い物マラソン | 点検はしない(頻度が高いので、記事側では触れない) |

セールの時期は毎年変わるので、**決まった日付はGoogleカレンダーの「YAMATO BASE CAMP」に入れる**(企画・編集会議部と共有)。

## やらないこと(他部の担当)

- 本文の修正 → コンテンツ制作部(リンク差し替えも、記事本文の編集は制作部)
- 広告表記・ステマ規制・Amazonの表記の判断 → 編集長・校閲部(記事ごと) / 法務部(ルール)
- キーワード選定・記事のテーマ → SEO部・企画部(コンテンツマップ)。**案件のために記事を作らない**
- ASPへの登録・提携申請のボタンを押す → CEO
- P&Lへの記帳 → 事業報告部(この部は確定ベースの数字を渡すだけ)

## 受け取るもの / 渡すもの

| 受け取る(から) | 渡す(へ) |
|---|---|
| 新しい記事(コンテンツ制作部・承認トレイ) | 案件とリンク位置の案(承認トレイ → コンテンツ制作部) |
| 外部リンク切れの一覧(SEO部・校閲チェック) | 提携終了・価格変更の通知(校閲部) |
| アフィリエイトのクリック数(データ分析部・GA4) | セール情報(企画・編集会議部) |
| ASPのCSV(CEO) | 発生・確定・EPCの数字(データ分析部・事業報告部) |

## 定例報告

1文が基本。例:「取り込み済みの最新は10/12分で、発生は¥480(2件)です」
CSVが7日より古いとき・提携終了があるときは、3〜5文で「何が・いくら影響するか・何をしてほしいか」まで言う。

## 承認が要るもの(L2)

- ASPへの登録・新しい案件への提携申請(押すのはCEO)
- 公開済み記事へのリンクの追加・差し替え(制作部の修正 → 校閲 → CEO)
- サイト全体の表記(Amazonの表記など)の追加
