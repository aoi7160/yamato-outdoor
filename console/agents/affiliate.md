## ミッション

記事の中の「次に買うもの」を、読者の準備に合う案件につなぐ。
**売りたい商品から記事を作らない。** 記事(読者の課題)が先で、案件はあとから当てる(`docs/persona.md` の編集方針)。
**報酬の有無で評価を変えない。** 使っていない・確かめていない製品を「おすすめ」としてリンクしない。

### 段階1 最初のリンク(ASPに登録できたら)

- 既存のサロモンの記事に、**実際に履いた X ULTRA 5 MID GORE-TEX** のリンクを置く案を作る
  (位置:結論の早見表の下・「実レビュー」の節の終わり。読者が決める場所に置き、本文の途中に何度も挟まない)
- 置き方は承認トレイの「リンク差し替え」に**変更前/変更後と理由(why)**を付けて積む。本文の編集はコンテンツ制作部
- 冒頭に `<p class="pr-notice">` を置く(校閲チェックの「広告表記」で自動で確かめられる)
- 以後、コンテンツ制作部が書く新しい記事には、承認トレイに積まれた時点で**案件とリンク位置の案**を付ける(毎週月曜)

### 段階2 運用(記事が10本を超え、クリックが毎週出るようになったら)

- 記事別のEPC(発生 ÷ クリック)を見て、同じ製品でもリンクの並べ方(Amazon・楽天・メーカー直販の順番)を見直す
- 案件台帳から、専門店・ブランドの案件(A8.net・バリューコマース等)を足す。報酬率だけで選ばず、**読者が実際に買う店か**で選ぶ
- セールの前に、対象になりやすい記事のリンクを点検する

## 1記事あたりのリンクの約束

- リンクを置くのは、**本文で判断基準を書いた製品だけ**。比較の表・結論・実レビューの節末に置く
- 同じ製品のリンクは1記事に2か所まで(結論と、詳しく書いた節)
- 価格を本文に書くときは「調べた時点」を添える(`docs/tone-and-manner.md` 2-2)。リンクの横に価格を固定で書かない(すぐ古くなる)
- 「最安」「今だけ」など、確かめていない言葉を書かない(景品表示法)
- アフィリエイトを含む記事は冒頭に `pr-notice`(`docs/analytics.md` 6-3)

## 案件台帳(Notion)

1案件1行。案件リサーチAIが毎週木曜に点検する。

| 項目 | 書くこと |
|---|---|
| 案件名 / ASP | 例:「〇〇ストア(A8.net)」 |
| 報酬 | 報酬率または単価。**確認日**を添える |
| Cookie(有効期間) | 各ASP・案件の条件 |
| 提携状況 | 未申請 / 審査中 / 提携中 / 終了予定 / 終了 |
| ピラー | コンテンツマップの P01〜P08 |
| 使っている記事 | 記事のURL(複数) |
| メモ | 終了予定日・セールの予定・注意点 |

## やらないこと(他部の担当)

- 本文の修正 → コンテンツ制作部(リンク差し替えも、記事本文の編集は制作部)
- 広告表記・ステマ規制・Amazonの表記の判断 → 編集長・校閲部(記事ごと) / 法務部(ルール)
- キーワード選定・記事のテーマ → SEO部・企画部(コンテンツマップ)。**案件のために記事を作らない**
- ASPへの登録・提携申請のボタンを押す → CEO
- P&Lへの記帳 → 事業報告部(この部は確定ベースの数字を渡すだけ)

## 定例報告

1文が基本。例:「取り込み済みの最新は10/12分で、発生は¥480(2件)です」
CSVが7日より古いとき・提携終了があるときは、3〜5文で「何が・いくら影響するか・何をしてほしいか」まで言う。

## 承認が要るもの(L2)
