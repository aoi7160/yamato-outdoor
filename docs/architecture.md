# アーキテクチャ

このドキュメントは「今なにが動いているか」と「今後どんな時に何が必要になりそうか」を分けて書く。
Stage 2・3は変更前提のメモであり、特定OSSへの決定事項ではない。詳しい経緯は
`docs/decisions/0001-oss-foundation.md` を参照。

## Stage 1: 今動いているもの(確定)

| 領域 | 使っているもの | 費用 |
|---|---|---|
| Webサイト | Astro(静的生成) | $0 |
| CMS | microCMS(無料枠) | $0 |
| ホスティング | Cloudflare Pages(無料枠) | $0 |
| アクセス解析 | Umami Cloud(無料Hobbyプラン) | $0 |
| AI人材の定義 | `.claude/agents/` (agency-agentsのペルソナを翻案) | $0 |
| メール | Purelymail | $10/年 |
| ドメイン | Cloudflare Registrar | $11/年前後 |

固定費は年間ドメイン+メールのみ(詳細は決定記録を参照)。ここに何かを追加する時は、
必ず「何がボトルネックになったか」を先に言語化してから選ぶ。

## Stage 2以降:「こうなったらこれが必要になる」

以下は**特定のツールへのコミットではない**。症状ベースで書いてあるので、実際にその状況になった
時点で、改めて2026年8月時点の情報を鵜呑みにせず選択肢を再調査すること
(このドキュメントの初版は2026年8月の調査を元にしており、この分野は変化が速い)。

### 症状: 企業・案件のやり取りが記憶やメール検索だけで追えなくなった
- 例: PR/タイアップ案件が月に数件発生し、「誰にいつ何を送ったか」を思い出すのに時間がかかる
- 必要になる機能: 案件ステータス管理、連絡履歴の一元化、次アクションのリマインド
- 選択肢の例: Twenty(OSS CRM)。ただし案件数がまだ少ないうちはNotion/スプレッドシートでも十分機能する

### 症状: 同じ手作業(通知・SNS投稿・API連携)を毎回コピペでやっている
- 必要になる機能: トリガー→アクションの自動化、AIエージェントから外部サービスを操作する経路
- 選択肢の例: Activepieces。ただしGoogle Apps ScriptやZapier/Make無料枠で足りる範囲ならそちらの方が身軽

### 症状: 読者リストが増え、メール配信ツールの無料枠(目安500〜1000件程度)に近づいてきた
- 必要になる機能: リストのセグメント配信、開封率などの計測、自動ナーチャリング
- 選択肢の例: Listmonk(セルフホスト)。送信は外部SMTPが別途必要になる点に注意

### 症状: 記事・写真素材が十分に溜まり、動画展開の時間と予算を確保できるようになった
- 必要になる機能: 台本生成、素材編集・レンダリング
- 選択肢: この領域はツールの入れ替わりが特に速いので、その時点で改めて調査すること

### 症状: AIエージェントの数が増え、誰が何をしているか・コストをどう配分するかが1つのCLAUDE.mdでは追えなくなった
- 必要になる機能: エージェント間のタスク分担の可視化、予算・コスト管理
- 選択肢: この領域もまだ1年未満の若いOSSが多い分野なので、その時点で改めて調査すること

## 原則

- 採用は「症状が実際に出てから」。先回りして常駐サーバーを立てない
- 採用したものは `docs/integrations/<service>.md` に連携仕様(APIエンドポイント・環境変数名)だけを書き、
  ツール本体のコードはこのリポジトリにvendorしない
- 判断を変えたら `docs/decisions/` に新しいADRを追記し、上書きしない(なぜ変えたかが後から追える状態を保つ)
