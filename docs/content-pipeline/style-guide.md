# トンマナ基準書(style-guide)

公開済みの基準記事
[サロモンの登山靴で失敗しない選び方](https://yamato-outdoor.com/mountain-climbing/boots/salomon-hiking-shoes/)
と、その制作中に運営者が入れた修正から抽出した「書き方の実例集」。

- **ルールの表**は `docs/tone-and-manner.md`(表記ゆれ・数字・ひらく漢字・見出しの基本)
- **このファイル**は、そのルールが実際の記事でどう現れたか、運営者が何を直したか
- **体験の扱い**は `docs/content-pipeline/rules.md` R1 が最優先。このファイルの例文に体験が
  含まれていても、**真似してよいのは書き方であって、体験の中身ではない**

末尾の「確認待ちの矛盾」が解消するまでは、該当項目は `tone-and-manner.md` に従う。

## 1. 声

| 項目 | 基準 | 基準記事での現れ方 |
|---|---|---|
| 文体 | 常体(だ・である)。読者への問いかけも常体 | 「結論から言うと、サロモンは登山靴を作っている。」 |
| 一人称 | 「私」。登場は少なく、体験の段落に限る | 「筆者は〜」の段落は運営者の指示で削除し、`.profile` に置き換えた |
| 温度 | 淡々と、断定で止める。熱量は形容詞ではなく具体で出す | 「良し悪しではなく、出発点が違う。」 |
| 立ち位置 | 売り手ではなく、先に試した人。勧める理由と勧めない理由を同じ重さで | h2「正直に書く。サロモンを勧めない人」 |
| 主語 | 道具より「次に行く日」と読者の判断(`docs/persona.md` 5) | 「下りで景色を見る余裕が生まれる」 |

## 2. 文のリズム(基準記事の実測)

本文186文を計測した値(表のセルを除く)。

| 指標 | 値 | 目標 |
|---|---|---|
| 一文の長さ(中央値) | 30字 | 25〜35字 |
| 一文の長さ(平均) | 32.8字 | 35字以下 |
| 30字以下の文の割合 | 50.5% | 4〜6割 |
| 50字を超える文の割合 | 11.3% | **1割以下**(超えたら分割を検討) |
| 本文の文字数 | 約7,000字 | 記事の型ごとの目安は `tone-and-manner.md` 4 |

**長すぎた文(分割の手本):**

```
✗ (106字) アッパーにはMatryxという、ケブラーなどの糸を織り込んだ耐摩耗性の高い生地を使い、
   靴底はAll Terrain Contagrip、内部にAdvanced Chassisという横ブレを抑える構造が入っている。

○ アッパーはMatryxという、耐摩耗性の高い生地。靴底はAll Terrain Contagripで、
   内部にはAdvanced Chassisという横ブレを抑える構造が入る。
```

仕様の列挙は1文に詰めず、**部位ごとに文を切る**。3つ以上並ぶなら表か箇条書きにする。

### 語尾の分布

基準記事の語尾上位: 「いる」23 /「ない」18 /「ある」14 /「する」10 /「なる」7 /「いい」7。
同じ語尾が3文続いたら1つ変える(`tone-and-manner.md` 1)。「〜と思う」は記事全体で3回まで。

## 3. 見出し

### h2(目次に出る)

基準記事のh2は11本。型は次の4つに分かれる。

| 型 | 例 | 使いどころ |
|---|---|---|
| 結論型 | 結論:サロモンの登山靴は「シリーズ選び」でほぼ決まる | 2本目(リード直後)に必ず1本 |
| 問い型 | 「サロモンの登山靴は滑る」は本当か | 検索される不安への回答。**1記事に2本まで** |
| 宣言型 | 正直に書く。サロモンを勧めない人 | 欠点の章。推奨の章の直前に置く |
| 名詞型 | 過去モデル・廃盤モデルの系譜と、中古で買うときの落とし穴 | 情報の章 |

- **h2だけを上から読んで、記事の主張が通じること**(P1は目次から拾い読みする)
- h2に疑問符は付けない。問い型は「〜は本当か」「〜できるのか」で止める
- h2の長さは30字以内を目安。製品名が並ぶ章(44字になった「現行シリーズの違い。X ULTRA 5・…」)は、
  製品名を本文に回して短くする

### h3

| 型 | 例 |
|---|---|
| 名称 —— 性格付け | X ULTRA 5 —— 日帰りの主力。迷ったらここから |
| 効いたこと(体験の章) | ぬかるみの登山道でも、防水性能はしっかり効いた |
| 番号付きの条件 | 1. 1足を修理しながら長く履きたい人 |

体験の章のh3は「何が効いたか」を言い切る形にそろえる(運営者の修正:
「ぬかるみでも、中は乾いたままだった」→「ぬかるみの登山道でも、防水性能はしっかり効いた」)。
**ただしh3の中身(効いた・効かなかった)も体験なので、運営者の回答が根拠になる。**

## 4. 記事の型

### 4-1. ブランド・製品レビュー型(基準記事の構成)

```
リード
  ├ 読者が抱いている誤解か疑問から入る(検索の関連する質問を使ってよい)
  ├ 結論を1〜2文で先に言う
  ├ 「この記事では、次のことが分かるように書いた。」+ checklist(4〜5項目)
  ├ .profile(書き手ブロック)
  └ 製品の全体写真
h2 結論(早見表 + Memo)
h2 背景(ブランド・製品の成り立ち。出典必須)
h2 選択肢の違い(シリーズ・モデル。h3で1つずつ)
h2 過去モデル・中古の注意(独自価値になりやすい)
h2 実際に使った(体験の章。中身はすべて運営者の回答から)
h2 よく検索される不安の検証(「〜は本当か」)
h2 サイズ・選び方の失敗と対策
h2 正直に書く。勧めない人
h2 PAAへの回答(普段使い等)
h2 それでも選ぶ理由
h2 まとめ(箇条書き + 行動を促す締め)
FAQ(microCMSのfaqフィールド。本文には書かない)
```

**欠点(勧めない人)を、推奨(選ぶ理由)の直前に置く。** 欠点を見せたうえで勧める順番が、
P1の「悪い点が書いていないレビューは信じない」に応える。

### 4-2. その他の型

ハウツー・ルート・比較は `docs/tone-and-manner.md` 4 の型に従う。
新しい型の記事が公開されたら、この節に構成を追記する。

## 5. リード文

```
「サロモン」と聞いて、まずトレイルランニングのシューズや、街で見かける厚底のスニーカーを
思い浮かべる人は多いと思う。実際、Googleで「サロモン 登山靴」と検索すると、関連する質問の
先頭に「サロモンは登山靴ですか？」が表示される。それくらい、登山靴のブランドとしては
誤解されている。
```

- 1段落目:読者の頭の中にある前提を言い当てる(根拠になる観察を添える)
- 2段落目:結論を先に言う
- 3段落目:「この記事では、次のことが分かるように書いた。」+ checklist
- checklistの各項目は**体言止め**にそろえる(運営者の修正:「実際どうなのか」→「路面ごとの実際のグリップ」)
- checklist内で同じ語尾・同じ評価語を重ねない(「弱点」「注意点」が並ぶ → 「制約」に変更)

## 6. 体験の書き方(型だけを真似る)

基準記事の体験の段落は、次の3段で組まれている。

1. **起きたこと**(運営者の回答そのもの)
2. **それが何を意味するか**(一般化。出典のある事実か、論理だけで言えること)
3. **読者への含意**(次に行く日にどう効くか)

```
起きたこと : ぬかるみでも内部は濡れなかった。        ← 運営者の回答
意味       : 耐水圧の数値をいくら見ても、実際に濡れるかどうかの実感は湧かない。
含意       : 実際に「濡れなかった」という結果が、数字より説得力を持つ。
```

- 1が運営者の回答に無いなら、2と3も書かない。【要実体験】を置いて止める(`rules.md` R1)
- 2で論理を飛ばさない(運営者の指摘:「一度『濡れなかった』経験でしか信用できない」は
  1回の体験で一般化しているように読める → 「数字だけでは実感が湧かない」と分解した)

## 7. 装飾(contentHtml内のクラス)

基準記事での使用回数と、使いどころ。

| 装飾 | 回数 | 使いどころ |
|---|---|---|
| `.checklist` | 2 | 「この記事で分かること」と、手順・確認項目 |
| `.note`(Memo) | 2 | 結論の補足、読者が取れる対策 |
| `.note.warn`(Caution) | 2 | 失敗すると山で困ること(安全・お金) |
| `.source` | 1 | 出典の明示。リンクを付ける |
| `<table>` | 2 | 選び分けの早見表、条件ごとの相性 |
| `.profile` | 1 | リード直後。書き手の事実だけ(`rules.md` R7) |
| `<figure>` | 写真の数 | `tone-and-manner.md` 7 の書き方 |

- `.note` / `.note.warn` は**h2ひとつに1つまで**
- 「実践している対策」のような書き手の習慣を `.note` に書くときも、中身は体験扱い(`rules.md` R1-1)
- 太字(`<strong>`)は基準記事で63回。**1段落に1か所まで**を目安にする(確認待ち C10)

## 8. リンク

| 種類 | 基準記事での例 | ルール |
|---|---|---|
| 製品の公式ページ | X ULTRA 5 → salomon.jp のコレクションページ | 製品名の初出に1回だけ |
| 用語の解説 | ケブラー → 素材の解説ページ | 専門用語の初出に1回だけ |
| 出典 | 公式サポート → `.source` 内でリンク | 出典の行に必ずリンク |
| 内部リンク | (基準記事の公開時点では対象記事なし) | 本文の流れの中に2〜4本 |

リンクテキストは「こちら」にしない。外部リンクの `target` / `rel` は自動で付く。

## 9. タイトル・概要

| 項目 | 基準記事 |
|---|---|
| タイトル | サロモンの登山靴で失敗しない選び方｜シリーズ別の違い・サイズ感・向いている山がわかる |
| 型 | 「主KW+読者の目的」+「｜」+「この記事で分かること」を名詞で3つ |
| 採用しなかった型 | 「〜は買いか」(指名検索の読者は買うかどうかではなく、どれを買うかで止まっている) / 製品名1つと山名1つに絞った型(対象が狭すぎる) |

タイトルは**読者が検索した直後の悩み**に合わせる。ファネル(情報収集・比較・購入直前)を
キーワードの検索意図から判断し、タイトルの問いをその段階にそろえる。

## 10. 運営者が直した言い回し(AIが出しやすい癖)

下書きでこれが出たら、トンマナ確認エージェントが必ず直す。
理由と代替は `docs/tone-and-manner.md` 1「避ける言い回し」。追加は `correction-log.md` 経由。

| 出た表現 | 直した表現 |
|---|---|
| 関連する質問の一番上に〜が並ぶ | 関連する質問の先頭に〜が表示される |
| 〜と言われる理由と、実際どうなのか | 〜と言われる理由と、路面ごとの実際のグリップ |
| 買う前に知っておくべき弱点 | 買う前に知っておきたい制約 |
| 筆者は会社勤めをしながら〜(地の文の自己紹介) | `.profile` ブロック |
| 関西の低山 | 関西の山(+具体的な山名) |
| モデルの性格を取り違えている | モデルの得意不得意を見誤っている |
| 表の見出し「こんな山行」 | シーン |
| 表の見出し「ひとこと」 | コメント |
| 〜を基準に考えて外さない | 〜を選んでおけば間違いない |
| 私もこれを履いている(Memo内) | 削除(書き手情報は `.profile` にある) |
| 〜から試着するのが近道 | 〜を先に試着すると、選び直しの手間が省ける |
| 多くの人が想像するのがこれ | 製品名を主語にして書き直す |
| 一度「濡れなかった」経験でしか信用できない | 耐水圧の数値をいくら見ても、実際に濡れるかどうかの実感は湧かない |
| 合う靴というのは、履いた瞬間ではなく、脱いだときに分かる(締め) | 締めは複数の方向で案を出し、運営者が選ぶ |

### AIっぽさの点検リスト(運営者の修正から一般化したもの)

- [ ] 比喩の動詞が実際の動作と合っているか(「並ぶ」「走る」「刺さる」)
- [ ] 指示語(これ・それ・この)で製品や対象を受けていないか。名詞に戻す
- [ ] 気の利いた言い回しで締めていないか。締めは主張か行動に置く
- [ ] 1回の体験から一般論に飛んでいないか
- [ ] 表の見出しが名詞1〜2語になっているか
- [ ] 「近道」「鍵」「肝」「真価」など、体言止めの決め台詞が続いていないか
- [ ] 「地味に」「正直」「結局」「〜という話だ」が1記事に2回以上出ていないか
- [ ] 「いかがでしたか」「〜と言えるでしょう」「様々な」「魅力」「徹底解説」が出ていないか
- [ ] ダッシュ(——)が1つのh2の中で2回以上出ていないか
- [ ] 太字が1段落に2か所以上ないか

## 11. 確認待ちの矛盾

基準記事と `docs/tone-and-manner.md` が食い違っている点。**運営者が決めるまで、
パイプラインは `tone-and-manner.md` 側に従う。** 決まったら両方のファイルを直し、ここから消す。

| # | tone-and-manner.md | 基準記事 | 決めること |
|---|---|---|---|
| C1 | 「シューズ」に統一。「靴」「トレッキングシューズ」は使わない | 「登山靴」「靴」を使用。カテゴリ名も「登山靴」 | 「登山靴」を統一形にするか |
| C2 | 活動を指すときは「山行」 | 運営者は表見出しの「こんな山行」を「一般的でない」と修正。本文の「快適な山行」は残した | 「山行」を地の文で使ってよいか |
| C3 | タイトル全角30〜35字 | 42字 | 上限を変えるか |
| C4 | h2は4〜8本 | 11本 | 型ごとに上限を変えるか(レビュー型は11本まで等) |
| C5 | 概要は80〜120字、「〜解説します」で終わらせない | 約125字、「〜解説します。」で終わる | 概要の締め方 |
| C6 | 本文・見出しで「？」「！」を使わない | 本文で関連する質問を「」付きで引用(？付き) | 引用とFAQの質問文は例外にするか |
| C7 | ダッシュは `—`、多用しない | 「——」(2文字)を本文で2回・h3で5回 | 2文字ダッシュを正式にするか、h3の区切りを別の形にするか |
| C8 | リードは具体的な場面(時刻・気温・場所)から入る | 読者の誤解から入った | 型ごとに入り方を分けるか |
| C9 | 「使ってから書く。最低3回」(`persona.md` Editorial Policy 1) | — | パイプラインで「必要な実体験」に何回分を求めるか |
| C10 | 太字のルールなし | 63回 | 太字の上限 |
