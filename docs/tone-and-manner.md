# トンマナ / 表記ルール

記事を書くときの手元のルール。**迷ったときに引くための表**であって、読み物ではない。

役割分担:

| ドキュメント | 何が書いてあるか |
|---|---|
| `docs/persona.md` | 誰に向けて、何を約束するか(Editorial Policy / コピーの基準) |
| **このファイル** | それをどう書き表すか(文体・表記・見出し・タグ) |
| `docs/workflow.md` | どこに入れたら公開されるか |

`persona.md` と矛盾したら `persona.md` が正。

---

## 1. 文体

| 項目 | ルール |
|---|---|
| 敬体・常体 | **本文は常体(だ・である)を基本**にし、読者に直接呼びかける箇所だけ敬体にする。「〜しましょう」は使わない(指示に聞こえる) |
| 一人称 | 「私」。複数の書き手が出るまでは統一。「筆者」「当サイトでは」は使わない |
| 二人称 | 原則書かない。「あなたは」を使わず、主語を落とすか一般化する |
| 一文の長さ | **50字以内を目安。** 読点が3つ以上入ったら切る |
| 段落 | 2〜4文で改行。スマホで6行を超える段落を作らない |
| 主語 | 道具ではなく**「次に行く日」**。「このザックは軽い」ではなく「この軽さなら、翌日に残らない」 |
| 語尾 | 同じ語尾を3連続させない。特に「〜と思う」「〜だろう」の連続は自信のなさに読める |
| 断定 | **実際に確かめたことは断定する。** 確かめていないことは書かない。「〜かもしれない」で逃げるより、書かないほうがよい |

### 体験と一般論を混ぜない

```
✗ レインウェアの透湿性は数値が高いほど快適です。私のものは20,000g/m²/24hでした。
○ 私のものは20,000g/m²/24h。六甲の梅雨時に3回着たが、
   ザックの下だけは毎回濡れた。数値は背中の蒸れには効かない。
```

一般論を書くなら**必ず自分の観測をぶつける。** それが無い一般論は、他のサイトに書いてある。

## 2. 表記

### 2-1. 基本

| 項目 | ルール | 例 |
|---|---|---|
| 句読点 | `。` `、` を使う。`．` `，` は使わない | |
| 感嘆符・疑問符 | 本文では使わない。見出しでも使わない | |
| 三点リーダ | `…`(1文字)。`...` は使わない | |
| 括弧 | 補足は `()` 半角。会話・強調は `「」` | 実測1,180g(カタログ値1,120g) |
| ダッシュ | `—`(emダッシュ)。文中の言い換えに使う。多用しない | |
| 波ダッシュ | 範囲は `〜` | 月1〜2回 |
| 中黒 | 並列は `・` | 六甲・金剛・比良 |
| 記号の前後 | 和文中の半角英数の前後に空白を**入れない**(`palt`で自動調整される) | ザック32Lを背負う |

### 2-2. 数字と単位

| 項目 | ルール | 例 |
|---|---|---|
| 数字 | **半角アラビア数字**。桁区切りのカンマは4桁以上に入れる | 1,180g / 987m |
| 漢数字 | 慣用句・固有名詞のみ | 一歩、四字熟語、三点支持 |
| 単位 | 半角。数字とのあいだに空白を入れない | 32L / 4℃ / 8m/s / 20,000g/m²/24h |
| 重量 | **g単位で書く。** kgに丸めると比較にならない | 1,180g(✗ 約1.2kg) |
| 時刻 | `5時22分` または `5:22`。記事内で統一する | |
| 日付 | 本文は `2026年9月22日`。一覧の表示は `2026.09.22`(自動) | |
| 気温・風速 | 単位まで書く。体感だけで済ませない | 稜線で4℃、風速8m/s |
| 価格 | 税込で書き、**調べた時点を添える**(価格は変わる) | 32,000円(2026年9月時点) |

> **実測値は必ず自分で量った数字を書く。** カタログ値と違ったら両方並べる。
> これが `persona.md` の Editorial Policy 2 の中身であり、このメディアの存在理由。

### 2-3. ひらく / とじる

漢字で書くと硬くなる語は、ひらがなにする。

| ひらく(推奨) | とじる(使わない) |
|---|---|
| こと | 事 |
| とき | 時(時刻の意味以外) |
| もの | 物(具体的な物体以外) |
| ほど | 程 |
| ため | 為 |
| ください | 下さい |
| いる | 居る |
| ある | 有る / 在る |
| すべて | 全て |
| ほとんど | 殆ど |
| かなり | 可成 |
| わずか | 僅か |
| たとえば | 例えば |
| ただし | 但し |
| なお | 尚 |
| また | 又 |
| さらに | 更に |
| よい | 良い(「良品」などの熟語は可) |

### 2-4. 表記ゆれの統一

**同じものを2通りで書かない。** 検索でも読みやすさでも損をする。

| 統一形 | 使わない形 |
|---|---|
| レインウェア | レインウエア / レインジャケット(上下セットを指す場合) |
| ザック | バックパック / リュック |
| ヘッドランプ | ヘッドライト / ヘデライト |
| シューズ | 靴 / トレッキングシューズ(登山靴の総称としては「シューズ」) |
| テント泊 | テン泊 |
| コースタイム | CT |
| 稜線 | 尾根(地形として区別する場合を除く) |
| 山行 | 登山(活動そのものを指すときは「山行」) |
| 日帰り | 日帰りピストン(ピストンは往復の意味でのみ使う) |
| 縦走 | 通し歩き |
| エスケープルート | 逃げ道 |
| 低体温症 | ハイポサーミア |
| 行動食 | 補給食 |
| 防水透湿素材 | ゴアテックス(商標。Gore-Tex製品を指す場合のみ) |
| Webサイト | ウェブサイト / WEBサイト |
| スマホ | スマートフォン(本文は「スマホ」でよい) |

固有名詞は正式表記に従う。

| 統一形 | 注意 |
|---|---|
| mont-bell | モンベル表記も可。英字なら小文字ハイフン |
| YAMAP | 全大文字 |
| ヤマレコ | カタカナ |
| 好日山荘 | |
| 六甲全山縦走 | 「六甲縦走」と略さない |

新しい表記ゆれに気づいたら**この表に足す。** 表が育つほど、記事の質が安定する。

## 3. 見出し

| 項目 | ルール |
|---|---|
| 構造 | `h2` → `h3` の2階層まで。`h4` は使わない |
| 目次 | **目次に出るのは `h2` だけ**(`CLAUDE.md` の約束) |
| h2の数 | 4〜8本。3本以下は構成が甘く、9本以上は記事を分けたほうがよい |
| 長さ | **全角30字以内。** 目次で2行に折れると一覧性が落ちる |
| 書き方 | 体言止めか短い言い切り。疑問形は1記事に1つまで |
| 記号 | `!` `?` `【】` `★` は使わない |
| キーワード | h2の半分程度に主要KWか関連語を入れる。全部に入れると不自然になる |
| 拾い読み | **h2だけを上から読んで筋が通るか**を必ず確認する。P1は全文を読まない |

```
✗ h2: レインウェアの選び方について解説します！
○ h2: 透湿性の数値が、背中の蒸れに効かない理由
```

---

## 4. 記事の型

P1は「目次から拾い読み」する。**結論を先に置く。**

```
1. リード(3〜4段落)
   ・具体的な場面から入る(時刻・気温・場所)
   ・何を失敗して、何を確かめたのかを宣言する
   ・この記事で分かることを1文で置く
2. 結論 / 先に答え
   ・迷っている人がここだけ読んで決められる状態にする
3. 本編(h2で4〜8本)
   ・判断基準 → 実測 → 合わなかった点 → 条件別の使い分け
4. よくある質問(FAQ)
   ・microCMSのfaqフィールド。構造化データにもなる
5. 次に読む1本
   ・関連記事は自動で出るが、本文の最後に1本、手で名指しする
```

### 分量

| 記事の種類 | 目安 |
|---|---|
| ハウツー / 検証 | 6,000〜10,000字 |
| ルート記録 | 5,000〜8,000字 |
| 比較 | 8,000〜14,000字 |

字数を目的にしない。**削って成立するなら削る。**
`persona.md` の「一文を短く。説明を足すより、言い切って止める」が上位。

## 5. タイトルと概要

| 項目 | ルール |
|---|---|
| タイトル | **全角30〜35字。** 主要KWを前方に置く。`| YAMATO OUTDOOR` は自動で付くので書かない |
| タイトルの禁止 | 「最強」「完全ガイド」「保存版」「初心者必見」「〜7選」(`persona.md`の使わない語) |
| 数字 | 入れるなら**実測値**。「3回使って分かった」「実測1,180g」 |
| 概要(description) | **全角80〜120字。** 検索結果に出る。記事の要約ではなく、**読む理由**を書く |
| 概要の書き方 | 「〜について解説します」で終わらせない。何が分かるかを具体的に |

```
✗ タイトル: 【完全版】登山用レインウェアのおすすめ7選！選び方も徹底解説
○ タイトル: 3万円以下のレインウェアを4着、六甲の梅雨で3回ずつ着た記録
```

## 6. 引用・出典・リンク

| 項目 | ルール |
|---|---|
| 出典 | 数値・気象・法令を引いたら `<p class="source">※ 出典: 〜</p>` で明示する |
| 引用 | 引用部分は `blockquote`。**自分の文章のほうが多い状態を保つ** |
| 外部リンク | `target` と `rel` は自動で付く(`src/lib/article.ts`)。手で書かない |
| アフィリエイト | 含む記事は冒頭に `<p class="pr-notice">` を置く(景品表示法。`docs/analytics.md` 6-3) |
| 内部リンク | 1記事に2〜4本。**本文の流れの中**に置く。記事末にまとめて並べない |
| リンクテキスト | 「こちら」「詳細はこちら」を使わない。リンク先が分かる語にする |

---

## 7. 画像

| 項目 | ルール |
|---|---|
| 枚数 | h2ごとに1枚を目安。文字だけで6画面続けない |
| alt | **何が写っているかを書く。** KWを詰め込まない。装飾目的なら空でよい |
| キャプション | 撮影した条件を書く(場所・天候・時刻)。写真の説明は不要 |
| 実測の写真 | 重量や寸法は**測っている写真**を載せる。数字だけより強い |
| 加工 | 明るさの調整のみ。色を作り込まない(実物と違う色は最悪) |
| サムネイル | 16:9。文字を入れない(一覧・OGP・SNSで切れる) |

WebP変換・`srcset`・遅延読み込みは自動で入る(`src/lib/article.ts`)。

## 8. 記事タグ(microCMSの `tags`)

タグは**回遊のための道具**で、キーワード欄ではない。増やしすぎると機能しなくなる。

| 項目 | ルール |
|---|---|
| 個数 | **1記事3〜5個。** 6個以上は付けない |
| 粒度 | 「複数の記事に付く」ものだけをタグにする。1記事しか付かないタグは作らない |
| 表記 | `docs/tone-and-manner.md` 2-4 の統一形に従う。`#` は付けない(自動で外れる) |
| 種類 | 次の3種類から選ぶ。混ぜてよいが、種類ごとに最大2個まで |

| 種類 | 例 |
|---|---|
| 道具の分類 | レインウェア / ザック / シューズ / ヘッドランプ / テント |
| 場所 | 六甲 / 金剛山 / 比良 / 北アルプス / 関西 |
| 条件・目的 | 日帰り / テント泊 / 雨 / 冬 / 軽量化 / 初回 |

**カテゴリとタグの違い。** カテゴリ(microCMSの `categories`)はURLになる分類で、
1記事に1つだけ。タグはURLにならない横断的な目印で、複数付く。
迷ったら「URLにしたいか」で決める。

> タグの表記ゆれは `content_tags` としてGA4に送られる(`docs/analytics.md` 2-3)。
> 似たタグが2種類出ていたら、そこで気づける。

## 9. AI検索に拾われる書き方(2026年時点)

AI検索(ChatGPT・Perplexity・Gemini・AI Overviews)からの流入は
`traffic_source_kind = ai` で計測している。引用されやすい書き方には共通点がある。

| やること | 理由 |
|---|---|
| **問いの直後に答えを置く** | 引用元として抜き出しやすい |
| **定義を1文で書く** | 「〜とは、〜である」の形が拾われる |
| **数値を表にする** | 表はそのまま引用されやすい |
| **見出しを質問形にしすぎない** | 疑問形の乱用は、かえって答えの位置がぼける |
| **一次情報だと分かる書き方をする** | 「実測した」「3回使った」「私が量った」が根拠として効く |
| **日付と条件を明記する** | 情報の鮮度を機械が判断できる |

小細工は不要。**実際に確かめた一次情報を、構造を整えて書く**というだけで、
`persona.md` の Editorial Policy と同じ方向を向いている。
