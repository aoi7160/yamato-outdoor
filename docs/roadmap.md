# YAMATO OUTDOOR 事業ロードマップ

> 「山と生きる。山と挑む。」
> — 実体験ベースの装備検証メディアから、アウトドア業界のデータプラットフォームへ。

最終更新: 2026-08-27

---

## 0. この事業の「勝ち筋」（前提整理）

アウトドアメディアは死ぬほどある。個人ブログもYouTubeも飽和している。
その中でYAMATO OUTDOORが勝てる理由は、**アウトドアが好きな人**でも**メディア運営がうまい人**でもなく、
以下の3つが1人の中で交差していることにある。

| 資産 | 他のアウトドアメディアが持っていないもの |
|---|---|
| **① 実体験** | 登山・釣り・キャンプを自分でやる。借り物でない一次情報を出せる |
| **② SaaSマーケターの実務知見** | THE MODEL、行動データのトラッキング、CRO、ABM、LTV設計。**アウトドア業界にこの知見を持った人間はほぼいない** |
| **③ 開発できる** | Astro/microCMS/Cloudflareを自分で組める。計測基盤もアプリもAPIも自分で作れる |

普通のアウトドアメディアは①しかない。だから最終的にアドセンスとアフィリエイトで終わる。
**②と③があるから、このメディアは「コンテンツ資産」ではなく「データ資産」を作りにいける。**

したがって本ロードマップの基本戦略は一貫してこれ:

> **BtoCのメディア・EC・アプリで「トラフィックと行動データ」を集め、
> それを原資産にしてBtoB（SaaS/DaaS/広告）で高収益化する。**

BtoCは入口であって、ゴールではない。ただしBtoCが弱いとBtoBは絶対に売れないので、
最初の1年はひたすら①の質で殴る。

### 施策を選ぶ3つの判断軸

やりたいことが多いのは強みだが、そのままだと全部中途半端になる。
以下の**3軸が揃っているものだけをやる**。1つでも欠けたら、面白そうでも捨てる。

| 軸 | 問い | 欠けるとどうなるか |
|---|---|---|
| **① 面白い（熱量）** | 自分が本気で語れるか。続けられるか | 続かない。個人事業は熱量が切れた時点で終わる |
| **② スキル・経験資産になる** | マーケター / 事業家としての market value が上がるか | 稼げても「時間を売っただけ」で終わる。本業にも転職市場にも効かない |
| **③ 稼げる** | 直接 or 間接に金になるか。単価と再現性は | 趣味。趣味は趣味でやればいい |

**②を軸に入れたのは正しい。** ここが本ロードマップの隠れた最重要ポイント。
このメディアは「副業でいくら稼げたか」より、
**「アウトドア業界でBtoB/BtoCの事業をゼロから立ち上げ、データ基盤を作り、広告を回し、SaaSを売った」
という実績そのもの**の方が価値が高い可能性がある。
それは本業の職位にも、転職市場での市場価値にも、将来の独立にも全部効く。

だから施策の優先度は「今月いくら稼げるか」ではなく、
**「やり切ったときに、自分に何のスキルが残るか」**で決める。

以降、本ロードマップの全施策には次のスコアを付けている。

`面白い / スキル / 稼ぐ` を各 ★1〜3 で表記。**合計7以上を優先実行。**


## 2. Phase 0（0〜3ヶ月）— 血を通わせる

### ゴール
「このサイト、本物っぽいな」と読者に思わせる最低ラインを超える。

### やること

**コンテンツ**
- **1ジャンルに絞って最初の20本**を書く。登山 / 釣り / キャンプのうち、**一番熱く語れる1つ**から。
  - 理由: 検索エンジンにもAI検索にも「このドメインは何の専門家か」を最速で理解させる必要がある。3ジャンル同時は最悪手。
  - 残り2ジャンルは Phase 1 の中盤以降に横展開する。
- 記事の型を最初に決めて固定する（後述の「検証プロトコル」がそのまま Phase 3 の売り物になる）。

**検証プロトコル（超重要 / これが全事業の原資産）**

すべてのギアレビューで、以下を**必ず同じフォーマットで記録・公開**する。

| 項目 | 内容 |
|---|---|
| 実測重量 | カタログ値ではなく自分のスケールで測った値（カタログ値との差分も出す） |
| 実測サイズ | 収納時 / 展開時 |
| 使用環境 | 山域・標高・気温・天候・使用日数 |
| 耐久経過 | 3ヶ月後 / 1年後に追記する（**追記型レビュー**にする） |
| 定量スコア | 軽量性・耐久性・コスパ・携行性を5段階で固定評価 |
| 実売価格の推移 | 記録しておく |

これを「ただのレビューの書き方」だと思わないこと。これは**構造化データベースの入力作業**である。
100本溜まった時点で、他の誰も持っていない「実測ギアDB」になる。
Phase 3 のDaaS・スペックAPI・安全管理SaaSは全部これが原資産。**1本目からこの形式で書く。**

**技術・計測基盤（ここが他と決定的に差がつく）**

Phase 0 のうちに以下を仕込む。後から入れると過去データが取れないので、**記事を書く前にやる**。

- [ ] GA4 + Google Search Console + Cloudflare Web Analytics
- [ ] **カスタムイベント設計**（ただのPVではなく「購買インテント」を取る）
  - `spec_table_view` — スペック表の表示・スクロール到達
  - `comparison_toggle` — 比較表でどの製品を比較したか（**製品名をパラメータに持たせる**）
  - `affiliate_click` — どの記事の、どの位置の、どのブランドのリンクを踏んだか
  - `scroll_depth_by_section` — どのセクション（重量 / 耐水 / 価格 / 実写）で滞在したか
  - `return_visitor_product` — 同一製品ページへの再訪（＝検討中シグナル）
- [ ] microCMSのスキーマに**製品マスタ（products API）**を追加する
  - 記事とは別テーブルで、ブランド / 製品名 / カテゴリ / 実測値 / 価格 を正規化して持つ
  - 記事はそこを参照する形にする
  - **これをやるかどうかで、Phase 3 でAPIを売れるかが決まる。**今はコスト1日、後からやると数ヶ月。
- [ ] 構造化データ（`Product` / `Review` / `AggregateRating` スキーマ）を全記事に自動出力
  - SEOだけでなく、**AI検索（AIO / LLM）に引用されるための布石**。AI時代は「構造化された一次データを持つドメイン」が引用される。

**EC（SUZURI / 完全受注生産）**
- SUZURIでショップ開設。在庫リスク・初期費用ゼロ。
- 第1弾ラインナップ（絞る。多品種はブランドをぼやけさせる）:
  - ステッカー（**最重要**。安い・利益率が高い・車やギア箱に貼られて歩く広告になる）
  - Tシャツ（黒・チャコールのみ。ロゴ小さめ、背面にスローガン）
  - キャップ
  - ステンレスマグ / シェラカップ系（SUZURIの取扱アイテムに応じて）
- **売上目的ではない。**Phase 0 のSUZURIの目的は次の3つ:
  1. 「ファンが存在するか」を最小コストでテストする（1枚でも売れたら、それは強いシグナル）
  2. ブランドのビジュアル資産（ロゴ・タグライン運用）を確定させる
  3. Phase 2 の自社EC・D2Cに向けた**購買データの初期サンプル**を取る
- 記事末とサイトヘッダーに常設導線を置く。押し売りはしない。

### Phase 0 のKPI
- 公開記事 20本
- 検証プロトコルで書かれた記事 100%
- 計測イベント実装完了
- SUZURI 開設・初回販売1件以上
- アフィリエイト Layer A（Amazon / 楽天 / もしも）登録完了・`affiliate_click` 計測稼働
- ※**PVは見ない。** この時期のPVを見るとメンタルが折れるだけで、意思決定に使えない。

## 3. Phase 1（3〜12ヶ月）— 信頼性とトラフィック

### ゴール
月間1万PV。そして「YAMATO OUTDOORが言うなら本当だろう」という第一想起を作る。

### やること

**コンテンツ戦略（マーケター視点）**

キーワードを目的別に3層で設計する。全部同じ書き方をしないこと。

| 層 | 目的 | 例 | 収益 | 本数比率 |
|---|---|---|---|---|
| **トランザクショナル層** | 買う直前の人を刈る | 「〇〇テント レビュー」「軽量シュラフ 比較」 | アフィリ直結・**行動データが最も濃い** | 40% |
| **インフォメーショナル層** | 集客・被リンク獲得 | 「初心者 登山 装備 一式」「〇〇山 日帰り ルート」 | 直接収益は薄いがドメイン評価を上げる | 40% |
| **体験・ストーリー層** | ファン化・指名検索を作る | 「厳冬期の〇〇で装備が壊れた話」 | SNS拡散・ブランド | 20% |

- ③の体験層を軽視しないこと。**指名検索（「YAMATO OUTDOOR」で検索される）が発生した瞬間、
  このメディアはアルゴリズム変動に強い資産になる。** ここが個人メディアの生死を分ける。
- **追記型レビュー**を運用に組み込む（3ヶ月後・1年後に必ず追記）。
  これは他が絶対に真似できない。なぜなら他は「書いて終わり」だから。
  「1年使った結果」は検索でもAI引用でも圧倒的に強い。

**SNS / チャネル分散（アドセンス・SEO依存からの脱却）**
- **YouTube / Shorts**: 記事の撮影ついでに動画も撮る。同じ山行で2媒体分のコンテンツを作る。
- **Instagram**: ギアの実写。アウトドアは画のジャンル。
- **X**: 実測データの単発投稿が伸びる（「カタログ値と実測値が◯g違った」系）。
- **メールマガジン（最重要）**: Phase 2以降のEC・アプリ・D2Cの全部の起点になる。
  - リードマグネット: 「登山装備チェックリスト（PDF）」「〇〇山 GPXデータ付きルートガイド」を無料配布してメアドを取る。
  - **これはSaaSのリードジェネレーションそのもの。** アウトドアメディアでリスト取ってる個人はほぼいない。
  - Phase 2 でこのリストにアプリとECを投下する。

**マネタイズ（詳細は6章）**
- アフィリエイト Layer A（Amazon / 楽天）: 収益より**クリックデータ取得**が主目的
- アフィリエイト Layer B（国内高単価ASP）: 保険 / 予約 / ふるさと納税 / 車中泊。**収益の主力**
  - 裏目標として**クローズドASP（felmat / レントラックス等）への招待**を狙う
- **セカンドメディア（6-3）を Phase 1 のうちに立ち上げる。**
  「アウトドアメディアの作り方」をnote/Zennで発信 → 海外SaaS・ツール系の高単価/継続報酬を回収
- Kindle出版（KDP）: 記事20〜30本を再編集して1冊。**収益より権威（Authority）が目的**
- **アドセンスは入れない**（6-4参照）。空いた枠はメルマガ登録とアプリ事前登録に使う
- 有料デジタルコンテンツを小さくテスト（GPX付きルートガイド、釣り場ガイド 数百円〜）
  - 目的は売上より「**この読者は金を払うか**」の検証

## 4. Phase 2（12〜24ヶ月）— プロダクトとデータ

ここからが本番。メディアを「プロダクトの集客装置」に転換する。

### 4-1. アプリ構想 — 3つの案と優先順位

アプリの根幹にあるのは**「人が集まって、レビューや経験を共有する」**こと。
ただしUGCサービスが必ず死ぬポイントは1つで、**誰も最初の1件を書かない**ことにある。
したがって設計の原則は一貫してこうなる。

> **レビューを「書かせない」。自分のために記録したものが、結果的に共有価値になる構造にする。**

この原則のもとで4案を検討し、優先順位を次のように決定した。

| 優先 | 案 | 一言 | 位置づけ |
|:---:|---|---|---|
| **第1希望** | **D. 登山のための筋トレ管理アプリ** | 山に登るための身体を作る | **本命。最初に作る** |
| 第2希望 | B. 撤退ログ（失敗の共有） | 失敗を持ち帰る場所 | 独自色が最も濃い |
| 第3希望 | A. GEAR LOCKER（装備の司令室） | 装備を管理・共有する | BtoBデータへの接続が最強 |
| 却下 | C. 実測値のWikipedia | 集合知でギアDBを作る | 貢献ハードルが高く初期が死ぬ。**却下** |

**なぜDが第1希望で戦略的にも正しいのか**（直感は合っている）:

| 論点 | 登山記録・レビュー系（A / B） | **筋トレ管理（D）** |
|---|---|---|
| 起動頻度 | 山に行く日だけ = 月1〜2回 | **週2〜4回。桁が違う** |
| オフシーズン | **冬に誰も開かない**（登山アプリの構造的欠陥） | **冬こそ開く**（オフシーズンが筋力構築期） |
| 初期のコンテンツ | 他人の投稿がないと価値ゼロ | **自分の記録だけで価値が完結する** |
| メディア依存 | トラフィックがないと死ぬ | **メディアがなくても単体で成立する** |

つまり **D はコールドスタート問題を構造的に回避できる唯一の案**。
まずDで「毎週開く理由」と「ユーザーベース」を作り、そこにB（失敗の共有）とA（装備）を
接続していくのが、最も勝率の高い順序になる。

### 4-2. 【第1希望】登山のための筋トレ管理アプリ

> コードネーム: **YAMATO ASCENT**（仮）
> コンセプト: **「あの山に登るための身体を作る」**

**ターゲットは完全に登山者。** 一般的なフィットネス層は狙わない。
「筋トレアプリの中の登山カテゴリ」ではなく、**「登山アプリの中の身体づくり」**として作る。

#### なぜ登山者は筋トレするのか — ここを突き詰めるのが全て

ここを曖昧にした瞬間、ただの劣化版筋トレアプリになる。
一般的な筋トレアプリの目的は**バルクアップ（見た目）と挙上重量（1RM）**。
**登山者の目的はまったく違う。** 目的は次の8つに集約される。

| # | 登山者の本当の悩み | 必要な能力 | 一般的な筋トレとの決定的な差 |
|:---:|---|---|---|
| 1 | **下りで膝が笑う・痛くなる** | 大腿四頭筋の**伸張性（エキセントリック）耐性** | 通常のトレは短縮性中心。**下山対策は伸張性を意図的に鍛える必要がある。ここが最大の差別化点** |
| 2 | 後半でバテる・足が上がらない | **筋持久力**（高レップ・低荷重） | 最大筋力を追う設計とはボリューム設計が真逆 |
| 3 | 重い荷物を背負えない | 体幹・脊柱起立筋・僧帽筋 | 「担いだ状態での安定性」であって、挙上重量ではない |
| 4 | 高い段差・鎖場を越えられない | 股関節伸展（大臀筋・ハム）、片脚の力 | **両脚のスクワットではなく片脚**。山は常に片脚荷重 |
| 5 | **転ぶ・滑る・捻る** | バランス、足首の安定性、体幹 | **遭難原因の上位が転倒・滑落。予防としてのトレーニング** |
| 6 | 登りで息が切れる | 心肺、体重あたりの出力 | 「重量を増やす」より「体重比を上げる」が正義 |
| 7 | 縦走で翌日動けない | リカバリー能力 | 連日行動の設計はボディメイクにない概念 |
| 8 | 膝・腰・足首を痛める | 傷害予防 | **「鍛える」より「壊さない」が優先される** |

> **結論: 登山の筋トレは「重量を上げる競技」ではなく、「山で起こる特定の失敗を防ぐ競技」である。**
> このアプリは全機能をこの一文から逆算して作る。

#### 「根本を間違えないための仕掛け」

「登山のための筋トレ」から外れないよう、以下をプロダクトに構造として埋め込む。

1. **すべての種目に「山のどの場面に効くか」を必ず表示する**
   - ステップダウン →「下山の膝」／ ブルガリアンスクワット →「高い段差・片脚荷重」
   - カーフレイズ →「ガレ場での足首の安定」／ ラックウォーク →「テント泊装備の担ぎ」
2. **登山に効かない種目には、正直に「効きません」と言う**
   - ベンチプレスに「**登山への寄与度: 低**（ただし鎖場・岩場では上半身も使います）」と出す
   - **「これは山には効かない」と言えるアプリは他に存在しない。**ここが信頼の源泉になる
3. **記録画面のデフォルト単位を「登山の言葉」にする**（後述のゲーミフィケーション）
4. **メニューは筋群ではなく「山の課題」から選ばせる**
   - ×「脚 / 背中 / 胸」 → ○「**下山で膝を守る / 段差を越える / 荷物を担ぐ / 転ばない**」
   - これだけでアプリの人格が完全に変わる

#### ゲーミフィケーション — 筋トレの数字を「山の言葉」に翻訳する

一般的な筋トレアプリ（Hevy 等）は「総ボリューム 12,400kg」「1RM更新」で報酬を返す。
**これを全部、登山の単位に翻訳する。** ここがこのアプリの主戦場。

| 一般的な筋トレアプリ | **YAMATO ASCENT での翻訳** |
|---|---|
| 総ボリューム 12,400kg | **「今日のトレーニング = 標高 340m 分の登り」**（体重×挙上高×回数で仕事量を垂直距離に換算） |
| 週間ボリューム | **「今週で高尾山 3.2回分を登った」** |
| 年間累積 | **「今年の累積標高 38,400m = エベレスト 4.3回分」** |
| 1RM 更新（PR） | **「北岳の想定コースタイムが 12分 短縮」** ← **筋トレの成果を山の言葉で返す。これが最強の報酬** |
| ストリーク（連続日数） | **「◯◯山まであと32日。準備完了度 72%」** |
| バッジ・称号 | **「山の適性レベル」**: 日帰り低山 → 小屋泊縦走 → テント泊縦走 → 冬期アルプス |
| 体組成の推移 | **「体重 -1.2kg = ザックが1.2kg軽くなったのと同じ」** ← 装備の軽量化と自重の削減を同じ軸で見せる |

- **標高換算（Vertical Meters）を全画面の共通通貨にする。** これがアプリの背骨。
  スクワットもステップアップもラックウォークも、すべて「登った標高」に変換されて積み上がる
- 物理的にも正当化できる（仕事量 = 質量 × 重力 × 高さ）ので、**説明したときに納得感がある**
- **共有したくなる単位**でもある。「今週エベレスト0.4回分登った」はSNSで強い

#### 期分け（Periodization）— オフシーズンに開く理由を作る

登山アプリ最大の弱点「冬に誰も開かない」を、**構造的に逆手に取る**。

| 時期 | フェーズ | アプリが提示すること |
|---|---|---|
| 冬（11〜3月） | **筋力構築期** | 「今が一番伸びる時期。夏の縦走はこの冬で決まる」 |
| 春（4〜5月） | **筋持久力・荷重期** | 荷重歩行、高レップへ移行。「本番の装備重量で歩く」 |
| 夏秋（6〜10月） | **維持・回復期** | 山行の合間の維持メニュー。山行後のリカバリー |

> **「山に行かない時期こそアプリを開く理由がある」** — これがリテンション設計の核心。

#### MVP機能（Hevy を土台に、登山向けに再設計）

筋トレ管理アプリとしての完成度は **Hevy** を基準にする。ここは奇をてらわない。

**A. 筋トレ管理の基礎体力（Hevy相当・ここが弱いと使われない）**
1. 種目ライブラリ（＋ 各種目に「山への寄与度」と「効く場面」タグ）
2. ルーティン作成・テンプレート
3. セット記録（重量 × レップ）、前回値の自動表示
4. インターバルタイマー
5. 履歴・推移グラフ、PR記録
6. ソーシャル（フォロー、ワークアウト共有、コメント）← **「人が集まる」根幹はここで満たす**

**B. 登山アプリとしての独自機能（ここが本体）**
7. **標高換算エンジン** — 全種目の仕事量を垂直距離に変換。アプリ共通通貨
8. **目標の山を設定する** — 「9月に北岳テント泊」を登録すると、そこから逆算した期分けメニューが生成される
9. **課題ベースのメニュー選択** — 「下山で膝を守る」「段差を越える」「荷物を担ぐ」「転ばない」
10. **山の適性レベル判定** — 現在の記録から「今のあなたはこのレベルの山域」
11. **推定コースタイム** — 記録が伸びると想定タイムが縮む。**成果の可視化の主役**
12. **山行後のフィードバックループ** ← **これが決定的**
    - 下山後に聞く: 「膝は痛くなりましたか？」「後半バテましたか？」「担いだ重量は？」
    - → 弱点を特定して次のメニューに反映する
    - → **同時にこれが「案B（失敗ログ）」のデータそのものになる**

**C. 意図的に入れないもの**
- ボディメイク要素（見た目、部位別の肥大目標）— **入れた瞬間にコンセプトが死ぬ**
- 過度な栄養・PFC管理（医療・健康表示の領域に入るとリスクとコストが跳ね上がる）

- **健康・医療的な断定表現はしない。**「トレーニング記録・目安」の範囲に留める（規約・審査対策）

### 4-3. 【第2希望】撤退ログ — 失敗を持ち帰る場所

> コンセプト: **成功はInstagramに溢れている。価値があるのは失敗のほうだ。**

寒くて眠れなかった、浸水した、撤退した、ギアが壊れた、ルートを間違えた。
**「失敗のデータベース」はこの世に存在しない。** 最も価値が高く、最も投稿されにくい情報。

- **独自色が3案の中で最も濃く、最も真似されない。**「山と挑む。」というスローガンとも完全に整合する
  （挑めば失敗する。それを持ち帰るのがこのコミュニティ、という思想）
- 接続先が異常に多い:
  診断AI（「あなたの計画に対し、類似条件での失敗が◯件」）/ ⑫安全管理SaaS /
  **①DaaS（メーカーのR&Dが最も欲しいのは褒め言葉ではなく「壊れた報告」）** / 保険・自治体・救助
- **リスク**: ネガティブな場は空気が荒れやすい。運営者が最初に自分の失敗を晒せるかで成否が決まる

**実装の現実解**: 単独アプリにせず、**第1希望Dの「山行後フィードバック」と、
第3希望Aの「山行記録」に "うまくいかなかったこと" 欄を必ず置く**ことで成立させる。
機能は小さく、資産としては最大になる。

`面白い ★★★ / スキル ★★☆ / 稼ぐ ★★☆` = **7**

### 4-4. 【第3希望】GEAR LOCKER — 装備の司令室

> コンセプト: 自分のギアを全部登録して、山行ごとにパッキングして、重さと記録を管理する。

**※ 筋トレ要素は本案からは切り離し、第1希望Dに集約する。**

**機能**
1. **ギア登録** — 製品DBから選ぶだけで実測重量が自動で入る
2. **パッキングリスト** — 山行ごとの**総重量が自動計算**。UL志向の登山者は1g単位で悩んでいる（最強のフック）
3. **山行記録** — GPX・写真・天候が、使ったギアと紐づく（＋ 4-3の「失敗」欄）
4. **消耗管理** — 使用回数を自動加算。「そのシューズ、そろそろ寿命です」
5. **買い替えレコメンド** — 「この3点を替えると620g軽くなります」→ EC / アフィリ送客

**なぜこれが効くのか（事業側から見た正体）**

| ユーザーから見た姿 | 事業から見た正体 |
|---|---|
| 便利な無料ツール | **購買インテントの自動収集装置** |
| ギアを登録する | 誰が何を持っているかの**所有データ** |
| 買い替え候補を見る | **検討中プロダクトの明示シグナル**（アンケートより正確） |
| 消耗管理 | **買い替えタイミングの予測データ** |

Amazonにも楽天にもメーカーにも取れない。**「所有 × 使用 × 検討」が繋がったデータは
アウトドア業界に存在しない。** これが①DaaSの唯一無二性であり、⑰中古マーケットプレイスの土台になる。

**技術方針**
- 製品マスタは Phase 0 で作った microCMS の `products` API をそのまま使う（**だから Phase 0 でやる意味がある**）
- 匿名IDでの計測を前提に設計。**個人情報とプライバシーポリシーは最初から真面目にやる**
  （データをBtoBで売るなら、法務がザルだと契約が通らない。ここは後から直せない）

`面白い ★★☆ / スキル ★★☆ / 稼ぐ ★★★` = **7**

### 4-5. 3案をどう繋げるか — 1つのプロダクト群として

バラバラの3アプリではなく、**Dを母艦にして順に接続する**。

```
【D】登山のための筋トレ                週2〜4回起動。オフシーズンも開く
      ↓  「◯◯山に向けて鍛えている」
【B】山行後フィードバック → 失敗ログ    下山直後に聞く。UGCの入口
      ↓  「膝が痛くなった / 担いだ重量は12kg」
【A】GEAR LOCKER（装備）              重量・所有・検討データ
      ↓
【Phase 3】①DaaS / ⑫安全管理SaaS / ⑰中古MP / ⑲体力スクリーニング
```

3つが1本の線で繋がる理由はシンプルで、**登山者にとってこの3つは同じ悩みの別の面**だから。

> **「担ぐ重さ（A）」「担ぐ身体（D）」「担ぎ損なった記録（B）」** — 山では全部ひとつの問題。

この統合を実現できるのは、実測データとメディアの信頼を同時に持つプレイヤーだけ。
だから3つとも同じ思想（実測 / 一次情報 / 失敗を隠さない）の上に置く。

#### アプリの着手タイミング

- **Phase 1後半（6〜9ヶ月目）**: Dの設計と、**自分自身が使う最小版（dogfooding）**を作る
  - 自分が一番のユーザーになれるのがDの強み。ユーザー0人でも価値検証ができる
- **Phase 2 前半**: D を公開ローンチ。メディアとメルマガから初期ユーザーを流す
- **Phase 2 後半**: B（山行後フィードバック）を D に追加
- **Phase 3**: A（GEAR LOCKER）を接続し、BtoBデータ基盤として完成させる

> **注意: 記事100本とアプリ開発の同時進行は物理的に無理。**
> Phase 1 の主戦場はあくまでメディア。アプリは「設計と自分用の試作」までに留め、
> **公開ローンチは Phase 2 に置く**。ここを守らないと両方が中途半端になる。

### 4-6. EC の進化

```
SUZURI（Phase 0）  → 自社EC（Shopify / Phase 2）→ D2C オリジナルギア（Phase 3）
受注生産・リスク0     セレクトショップ型            OEM小ロット
```

- **Shopifyで `shop.yamato-outdoor.com` を構築**
  - まずは「YAMATO OUTDOORが厳選したギア」の**セレクトショップ型**（仕入れ or ドロップシッピング）
  - アフィリエイト（数%）ではなく粗利（20〜40%）を取りにいく
  - **さらに重要: 決済まで自社で完結すると、購買データが自社に溜まる。**
    アフィリは「クリック」までしか見えない。ECは「誰が何をいくらで買ったか」が見える。
    これは Phase 3 のDaaSの解像度を一段上げる。
- SUZURIのオリジナルグッズは自社ECに統合（SUZURI連携 or 在庫を持てるものだけ内製）
- アプリの「買い替えレコメンド」→ 自社EC が最強の導線になる

## 6. アフィリエイト・広告収益の設計

前提認識を先に置く。
**アフィリエイトと広告は「稼ぐ」軸だけでなく「スキル」軸で極めて強い施策である。**
アフィリエイト＝ 媒体選定・導線設計・CVR最適化・ROAS管理 の実地訓練であり、
SaaSマーケターの本業スキルとほぼ同じ筋肉を使う。しかも**自分の金と自分の意思決定で回せる**。
本業では絶対に得られない学習効率がある。だから積極的にやる。

ただし**メディアの信頼だけは絶対に売らない**。
文脈に合わない高単価案件（転職・脱毛・金融など）を貼った瞬間、
Phase 3 のBtoB（数十万〜数百万円）が全部売れなくなる。**目先の数千円と、将来の数百万円を天秤にかける。**

### 6-1. アフィリエイトを5層で設計する

#### Layer A: ボリューム層 — Amazon / 楽天 / Yahoo
- 料率2〜5%。承認率が高く、レビュー記事に自然に置ける
- **役割は収益より「クリックデータの取得」。** どの製品が誰にどれだけ検討されているかのシグナルが取れる。
  これが Phase 3 のDaaS（BtoB案①）の原資産になる。**だから Phase 0 から入れる。**
- 経由は もしもアフィリエイト（かんたんリンク・W報酬）/ バリューコマース（LinkSwitch）が効率的
- `面白い ★☆☆ / スキル ★☆☆ / 稼ぐ ★★☆`

#### Layer B: 国内高単価ASP — 収益の主力
アウトドア文脈で**自然に**貼れて、かつ単価が高い領域だけを狙う。

| 領域 | 単価目安 | 相性 |
|---|---|---|
| 登山保険 / 山岳保険 / レジャー保険 | 2,000〜8,000円 | ◎ 「遭難と保険」の記事は絶対に必要な情報。読者価値が高い |
| キャンプ場・アウトドア体験予約（アソビュー / なっぷ / じゃらん） | 数百〜数千円 | ◎ エリア記事と直結 |
| ふるさと納税（さとふる / 楽天） | 数百〜数千円 | ◎ **アウトドアギアの返礼品と異常に相性が良い**。年末に爆発する |
| キャンピングカー・車中泊（レンタル / 購入リード / 車査定） | 5,000〜30,000円 | ○ 車査定は超高単価。「車中泊仕様にした」記事から自然に流せる |
| 中古ギア買取査定（釣具・登山用品） | 数千円 | ○ 「ギアの手放し方」記事は需要がある |
| アウトドアD2C・大型ECの新規会員登録 | 数千円 | ○ |

- ASP: A8.net / afb / バリューコマース / アクセストレード / felmat / レントラックス / janet
- **クローズドASP（felmat・レントラックス等）に招待されるかが分岐点。**
  同じ案件で単価が1.5〜3倍になる。記事50〜100本 + 一定PVで声がかかる。**Phase 1 の裏目標にする。**
- `面白い ★★☆ / スキル ★★☆ / 稼ぐ ★★★`

#### Layer C: Kindle / 電子書籍 — 権威づくり ★3軸で強い
1. **Kindle Unlimited / Audible の無料体験アフィリ**
   - 1件数百円だが承認率が高く、PVが小さい時期でも回る。「山の本」記事と自然に繋がる
2. **自分でKindle本を出す（KDP出版）** ← こちらが本命
   - 「実測で選ぶ 登山装備の教科書」的な本を、**既存記事を再編集して出す**。追加取材コストほぼゼロ
   - 印税35〜70% + Kindle Unlimited の読み放題ページ単価
   - **最大の価値は収益ではなく「著者」という権威（Authority）。**
     BtoB営業（特に自治体・メーカー・エンタープライズ）で「本を出しています」は決定的に効く。
     Phase 3 の⑨自治体案件、⑫安全管理SaaSの信頼担保にそのまま使える
   - スキル資産: 出版マーケティング / ローンチ設計 / レビュー獲得 / カテゴリ攻略。
     **「本を出してランキング1位を取った」経験はマーケターとして単体で価値がある**
- `面白い ★★★ / スキル ★★★ / 稼ぐ ★★☆`

#### Layer D: 海外SaaS・継続報酬（Recurring）★スキル軸で最強
- **継続報酬モデルを自分の財布で体験することは、SaaSマーケターにとって最高の教材。**
  LTV・チャーン・コホート・MRR積み上げを、座学ではなく実感として理解できる。本業に直接効く
- 候補:
  - GPS / 地図系サブスク（Gaia GPS、AllTrails、onX 等）— アウトドア文脈で唯一自然に貼れる海外SaaS
  - 写真・動画・編集（Adobe、Canva 等）— レビュー撮影の裏側記事から
  - VPN / クラウドストレージ — 海外遠征・旅行文脈
  - Shopify / ConvertKit / Ahrefs / Notion 等のツール系 — **本体には貼らない**（後述 6-3 で回収）
- ドル建て報酬なので為替の影響を受ける。円安局面では有利
- **注意: 日本語圏のアウトドア読者に海外SaaSはほぼ刺さらない。**
  無理に本体メディアに入れるとノイズになる。→ 回収場所は 6-3
- `面白い ★★☆ / スキル ★★★ / 稼ぐ ★★☆`

#### Layer E: 自社広告枠 — 媒体主として売る
- アドセンスは「Googleに枠を貸す」＝**最も安く買い叩かれる形**。しかもUXを壊す
- Phase 2 以降は**自分で広告枠を売る**: 純広告、メルマガ内広告、記事内固定枠、アプリ内枠
- **スキル資産としてここが一番おいしい。**
  広告主側（出稿側）の経験しかないマーケターは山ほどいるが、
  **媒体側（パブリッシャー側）で枠を作り、価格を決め、売り、レポートを返した経験がある人はほぼいない。**
  この両面を知っていることは、キャリア上の明確な差別化になる
- `面白い ★★☆ / スキル ★★★ / 稼ぐ ★★★`

### 6-2. 広告運用の経験を積む（予算ゼロ前提の現実解）

「予算はかけられないが広告の経験を積みたい」への回答。順番が大事。

**方法1: 自社商材で少額運用する（最初にやる）**
- SUZURI・自社EC・アプリ・有料コンテンツという**自分の売り物がある**ので、
  月1〜3万円でも「実データで回す」経験ができる。**代理店に入るより学習効率が高い**
- 学べること: Meta広告のクリエイティブテスト、Google P-Max、CPA/ROAS管理、LP改善のPDCA
- コツ: 少額だからこそ**「何を検証するか」を先に決める**。
  例:「アウトドア層にはUGC風クリエイティブと製品カット、どちらがCTRが高いか」
  → 売上ではなく**学習が成果物**だと割り切る

**方法2: 予算ゼロで回せるCRMで練習する（同時にやる）**
- メール / LINE のシナリオ設計、セグメント配信、件名A/Bテスト、カゴ落ち復帰
- **実は広告よりCRMの方が、SaaSマーケの現場で差がつく領域。**しかも無料で無限に練習できる
- Phase 1 で作るメルマガリストがそのまま練習台になる

**方法3: 媒体側としてタイアップを受け、広告主のKPIを覗く（Phase 2）**
- 広告主が何をKPIにし、何をもって成功と判断するかが**発注側の生データとして見える**
- ここで得た知見をそのまま BtoB案⑥（SEO/AIOレポート）の商材に転用する

**方法4: クライアント予算で運用する（Phase 3）**
- BtoB案⑩（D2C立ち上げ支援）のスコープに広告運用を含める
- **他人の予算で経験を積み、かつ報酬をもらう。**最も効率が良い
- ただし実績がないと任されない。方法1で自社実績を作るのが前提条件

### 6-3. セカンドメディア「作り手側」チャネル ★3軸すべて最高スコア

**このメディアを作る過程そのものを、別チャネルでコンテンツにする。**

想定コンテンツ:
- 「アウトドアメディアを Astro + microCMS + Cloudflare で作った全記録」
- 「SaaSマーケターが、個人メディアにTHE MODELを実装してみた」
- 「個人メディアに購買インテント計測基盤を入れる方法」
- 「Kindle出版してみた結果」「SUZURIで受注生産ECをやってみた」「クローズドASPに招待されるまで」

なぜ3軸すべてで最高スコアなのか:

| 軸 | 理由 |
|---|---|
| 面白い | やっていることをそのまま書くだけ。ネタが自動的に湧く。取材コストゼロ |
| **スキル** | アウトプットで理解が固まる。かつ**「発信するマーケター」としての個人ブランド**になり、転職・登壇・執筆・独立の全部に効く。**②の軸を最も直接的に満たす施策** |
| **稼ぐ** | **単価が桁違い。** Shopify / Ahrefs / ConvertKit / Notion 等のツール系は高単価かつ**継続報酬**。Layer D の海外SaaSアフィリを回収できる唯一の場所 |

**運用の絶対条件: 本体メディア（yamato-outdoor.com）とは必ず分ける。**
note / Zenn / X、または別ドメインで運用する。
本体にWeb制作やマーケの話が混ざると「アウトドアの専門家」というポジションが濁り、
Phase 3 のBtoB（メーカー・自治体向け）が売れなくなる。**ブランドの純度は最大の資産。**

### 追加案 — マーケター視点で考えた新規案

「良いモノは作れるが、売り方のデータもオペレーションも持っていない」。
SaaS業界では当たり前のことが、この業界では誰もやっていない。**そこが全部、商材になる。**

#### ④ レビュー・コンテンツ製造代行（Content Ops as a Service）★最有力・最速

**課題**: メーカーは自社EC・Amazon・楽天の商品ページに載せる**実写素材と実測データが慢性的に足りない**。
カタログ写真しかない商品ページはCVRが低い。分かっていても、社内に撮れる人も、山に行ける人もいない。

**提供物**: YAMATOの検証プロトコルをそのままパッケージ化して納品する。
- フィールド実写写真（30〜50カット）
- 実測スペック表（重量・サイズ・耐水など、第三者実測値）
- 使用動画・ショート動画素材
- 競合比較表
- 商品ページ用のコピーライティング

**なぜ強いか**:
- **メディアが元々やっている作業（取材・撮影・実測）を、そのまま商品にできる。** 追加コストがほぼゼロ。
- 記事広告（1回売って終わり）と違い、**素材は継続案件になる**（新製品が出るたび発注される）。
- 「第三者が実測した数値」はメーカー自身が作れない。**構造的に外注せざるを得ない。**

**単価**: 1製品 15〜40万円 / 年間契約 月額20〜50万円
**開始時期**: **Phase 1後半から売れる。**PVが小さくても「素材の質」で売れるため、
BtoBの最初の1件はこれになる可能性が高い。

---

#### ⑤ アウトドア・スペックDB API（Product Data as a Service）

**課題**: アウトドアギアのスペックデータは、メーカーごとにフォーマットがバラバラで、
**正規化された機械可読なDBが業界に存在しない。** ECも比較サイトも価格アプリも、毎回手入力している。

**提供物**: Phase 0 から積み上げた製品マスタを、正規化されたAPIとして提供。
- 重量・サイズ・素材・耐水圧・対応温度・実売価格推移
- **カタログ値ではなく第三者実測値がある**のが決定的な差別化
- 顧客: EC事業者、比較サイト、価格追跡アプリ、メーカーの競合分析部門

**なぜ強いか**:
- **AI検索時代の布石。** LLMは構造化された一次情報源を引用する。
  「アウトドアギアのスペックといえばYAMATO」という引用元ポジションを取ると、
  検索アルゴリズムに左右されない参照トラフィックが発生する。
- データは複製コストゼロ。売れば売るほど粗利率が上がる、典型的なSaaSの経済性。

**単価**: 月額 3〜30万円（API callベース）
**開始時期**: Phase 3（製品データ500件以上が目安）

---

#### ⑥ アウトドア版 SEO / AIO ブランド可視性レポート ★本業スキル直結

**課題**: ガレージブランド・中小メーカーは、
「自社ブランドが検索でどう見られているか」「AIに聞いたとき何と答えられているか」を**誰も把握していない**。
SEO会社に頼むと業界知識がなく的外れ、社内にはやれる人がいない。

**提供物**: **これはあなたの本業スキルそのもの。**
- ブランド名・製品名の検索ボリューム推移と競合比較
- 「◯◯ テント おすすめ」等の刈り取りキーワードで、誰が上位を取っているか
- **AI検索（ChatGPT / Google AI Overview）で自社ブランドが言及されているか（AIO可視性）**
- 自社ECのCVR診断・商品ページ改善提案
- 月次レポート + 改善提案

**なぜ強いか**:
- **仕入れコストがほぼゼロ**（Ahrefs等のツール代のみ）で、実行コストは自分の時間だけ。
- SaaS業界では標準的な分析が、この業界では**魔法に見える**。
- ここから⑤DaaSと④コンテンツ代行に**自然にアップセルできる**。入口商材として完璧。
- 「メディアとして業界で一番検索を理解している」という証明が、そのまま営業資料になる。

**単価**: 月額 5〜15万円（レポート） / 30〜100万円（スポットコンサル）
**開始時期**: **Phase 1 から売れる。** PVすら要らない。必要なのは知見と実績記事だけ。
→ **BtoBの最短の収益源はこれ。**

#### ⑦ キャンプ場・ガイド事業者向け「脱ポータル」集客支援

**課題**: キャンプ場は なっぷ / じゃらん 等のポータルに10〜15%の手数料を払い続けている。
自社直販を増やしたいが、Webの改善能力がない。

**提供物**: ②の予約ウィジェットに行く**前**に、まず**診断とCRO**で入る。
- 自社サイトの予約導線診断（フォーム離脱、モバイル対応、価格表示）
- ローカルSEO / Googleビジネスプロフィール最適化
- YAMATOメディアからの送客（記事特集 + 成果報酬）
- **効果が出てから**、予約ウィジェット / 予約管理SaaSへアップセル（＝②のPLG）

**なぜ順序を変えるか**: いきなり予約システムを売るのは、
「システム移行」という重い意思決定を最初に迫ることになり、売れない。
**「手数料が減った」という成果を先に見せてから**、システムに乗り換えさせるのが正しい順序。

**単価**: 診断 10〜30万円 / 月額 3〜10万円 / 送客成果報酬
**開始時期**: Phase 2

#### ⑧ 読者パネル型「プロダクト・リサーチ」事業 ★構想の結節点

**課題**: メーカーは新製品を出す前に、**リアルなユーザーの声を定量で取る手段がない**。
一般的なアンケートパネルにアウトドア愛好家はほぼ含まれない（含まれても「年1回キャンプする人」）。

**提供物**: メディア読者 + アプリユーザーを**「YAMATOフィールドテスター」として組織化**し、メーカーに提供。
- 試作品のフィールドモニターテスト（実際に山で使わせて定量レポート）
- 新製品コンセプトの定量調査（n=300〜1000のガチ勢）
- 価格受容性調査（PSM分析）
- 「所有ギアデータ」を使ったターゲティング（例: 「◯◯社のテントを所有している人だけに聞く」）

**なぜこれが構想の結節点なのか**:
- **BtoB収益**になる（メーカーへの調査提供）
- **コミュニティ**になる（パターンA: テスターは最もロイヤルなファン）
- **D2C開発の土台**になる（パターンB: 自社ギアを作るときの声がすでに集まっている）
- **DaaSの精度を上げる**（①: 行動データ + 意識データが揃う）

つまり**A・B・Cの全パターンに同時に効く唯一の施策**。優先度を高く置くべき。

**単価**: 1調査 30〜150万円 / モニターテスト 50〜200万円
**開始時期**: Phase 2後半（アプリのMAUが1,000を超えてから）

---

#### ⑨ 自治体・DMO向け アウトドアツーリズム・データレポート

**課題**: 自治体の観光課・DMOは「アウトドア需要で人を呼びたい」が、
**どの山・どの川・どのアクティビティに需要があるのかのデータを持っていない**。
コンサルに頼むと数百万円で、中身は一般論。

**提供物**:
- 検索データによるエリア別アウトドア需要分析（「◯◯山 登山」の検索推移、季節性、流入元地域）
- 競合エリアとの比較（隣の県のあの山になぜ人が流れているか）
- 自メディアの行動データ（どのエリア記事がどれだけ読まれ、どこから来ているか）
- 施策提案 + メディアでの特集記事（実行までセットで出せる）

**なぜ強いか**:
- **自治体には予算がある**（観光振興・関係人口創出の予算枠は大きい）。
- ふるさと納税の返礼品（アウトドア体験・ギア）の設計支援にも横展開できる。
- 「メディアを持っているから実行までできる」= コンサルにない強み。

**単価**: 100〜500万円 / 案件（年度予算）
**開始時期**: Phase 2後半〜Phase 3。実績記事とPVが要る。

#### ⑩ ガレージブランドのための「D2C立ち上げ支援」パッケージ

**課題**: 職人的なガレージブランドは、モノは作れるが**ECの立ち上げ・運用ができない**。
Instagramだけで売っている、DMで注文を受けている、という状態が普通にある。

**提供物**: SaaSのカスタマーサクセスの型を持ち込む。
- Shopify構築 + 商品ページ制作（④の素材とセット）
- メール/LINEのシナリオ設計（カゴ落ち、再購入、新作案内）
- LTV・リピート率の可視化ダッシュボード
- 在庫・受注のオペレーション設計

**なぜ強いか**: 自社ECを自分で作って回している（Phase 2）から、**実体験として売れる**。
「うちはこれで月◯◯万売っています」が最強の営業資料。

**単価**: 初期 50〜150万円 + 月額 5〜20万円
**開始時期**: Phase 3（自社ECの実績が出てから）

#### ⑪ アウトドア業界特化の人材・副業マッチング

**課題**: アウトドア業界は求人媒体が弱く、
「アウトドアが好きで、かつマーケ/EC/開発ができる人材」を採れない企業だらけ。
一方で読者には「好きなことを仕事にしたい」層が確実にいる。

**提供物**: 求人掲載 / スカウト / 副業マッチング。ニッチだが**1件あたりの単価が高い**（成功報酬30〜100万円）。
**開始時期**: Phase 3。メディアの読者属性が固まってから。※優先度は中。

#### ⑫ レンタルギア事業者向け「装備管理SaaS」→ 安全管理SaaSへ

③のVertical SaaSに至る**現実的な入口**。

**課題**: レンタルギア事業者・アウトドア施設は、
在庫のギアを**Excelか紙で管理している**。何回貸したか、いつ買ったか、いつ壊れたかが分からない。
結果、寿命を超えた装備が現場に出て、事故につながる。

**提供物（段階）**:
1. **入口**: QR/バーコードでの貸出・返却・在庫管理（＝業務が明確に楽になる。導入されやすい）
2. **中盤**: 使用回数・使用時間の自動蓄積 → 消耗アラート
3. **本命**: YAMATOの検証データを紐づけた**「安全基準・点検履歴システム」**
   → ここまで来ると、商業登山ガイド・自治体・救助隊が顧客になる（＝③）

**なぜ順序を変えるか**: 「安全管理」から売ろうとすると、
「今困っていない」（＝事故が起きるまで顕在化しない課題）ので売れない。
**「今困っている在庫管理」から入って、安全管理にアップセルする。** これがVertical SaaSの定石。

**単価**: 月額 2〜10万円（小規模事業者） → 20〜100万円（法人・自治体）
**開始時期**: Phase 3

### 追加案 — 「広告・アフィリの経験」がそのまま武器になる6案

6章でアフィリエイトと広告を自分でやり込むことで、**BtoBの商材が増える**。
「自分でやった」という一次経験は、この業界では圧倒的な差別化になる。

#### ⑬ メーカー向け「アフィリエイト・プログラム構築／運用代行」★スキル軸で最高

**課題**: アウトドアメーカーの自社ECは、アフィリエイトプログラムを持っていないか、
ASPに登録しただけで放置している。**「アフィリエイターに選ばれる案件の作り方」を誰も知らない。**
料率設定、成果地点、承認基準、素材提供、トップアフィリエイターとの個別交渉…全部ノウハウの塊。

**提供物**:
- ASP選定・プログラム設計（料率 / 成果地点 / 承認ルール / 特単の設計）
- アフィリエイター向け素材（バナー、実測データ、比較表）の提供 ← ④のコンテンツ代行とセット
- 有力メディアへの個別アプローチ・特単交渉の代行
- 成果レポーティングとチャネル別ROIの可視化

**なぜ強いか**:
- **自分がアフィリエイター側（媒体側）を本気でやっているから、「何をされたら貼りたくなるか」が分かる。**
  広告主側の代理店には絶対に持てない視点
- **スキル資産として最高。** アフィリエイト市場を「媒体側」と「広告主側」の両方から
  設計・交渉・運用した経験を持つマーケターは、事業会社でも代理店でも極めて希少
- 成果報酬の一部をレベニューシェアにすれば、**自分にも継続収入（recurring）が入る**

`面白い ★★☆ / スキル ★★★ / 稼ぐ ★★★` — **単価**: 初期30〜80万円 + 月額5〜20万円 or レベニューシェア
**開始時期**: Phase 2（自分のアフィリ実績が語れるようになってから）

#### ⑭ アウトドア・メディアネットワーク（広告枠の共同販売）

**課題**: 個人のアウトドアブロガー・YouTuber・インスタグラマーは、
単体では広告主に相手にされない（規模が小さすぎて商談コストが合わない）。
一方メーカー側は「どのメディアに出せばいいか分からない」。**間に立つ人がいない。**

**提供物**: 個人アウトドアメディアを束ねて、**広告枠をまとめて売る（メディアレップ／アドネットワーク）**。
- 参加メディアの枠を一括販売、YAMATOが窓口になって商談・入稿・レポートを担当
- マージン 20〜30%
- 発展形: マイクロインフルエンサーのキャスティング事業

**なぜ強いか**:
- **仕入れコストゼロ**（在庫は他人のメディア枠）。純粋な仲介マージン
- 自分がメディア運営者なので、**同業者から信頼されて枠を預けてもらえる**。ここが参入障壁
- ネットワーク全体のデータが集まる → ①DaaSの母数が一気に増える
- スキル資産: **媒体ビジネス・レップ業の実務**。これも経験者が極端に少ない

`面白い ★★☆ / スキル ★★★ / 稼ぐ ★★☆` — **単価**: 販売額の20〜30%
**開始時期**: Phase 3

#### ⑮ ガレージブランド向け「クラウドファンディング立ち上げ支援」★即金性が高い

**課題**: アウトドアギアは Makuake / CAMPFIRE / Kickstarter と**異常に相性が良い**
（ストーリー性、実物の写真映え、こだわり層）。
しかし個人の作り手は、ページ制作も事前集客も広告運用もできず、
プラットフォーム任せで数十万円しか集まらずに終わる。

**提供物**: ローンチのフルパッケージ。
- プロジェクトページの構成・コピー・撮影（④のコンテンツ代行がそのまま使える）
- **事前集客**（＝ここが最重要かつ、YAMATOにしかできない）
  - メディア記事 + メルマガリスト + SNSで「予約リスト」を作ってから公開日に一気に落とす
  - **これはSaaSのプロダクトローンチと全く同じ設計。本業スキルが完全に転用できる**
- 公開後の広告運用（**クライアント予算で広告経験が積める** ← 6-2 方法4）
- リターン設計・価格設計（PSM分析。⑧の読者パネルで事前検証できる）

**なぜ強いか**:
- **成果が金額で即座に出る**ので、実績を作りやすく、次の営業がラク
- 成功報酬型にできる（支援総額の10〜20%）。**当たると単発で数百万円**
- メディア・リスト・広告・調査・撮影の**全アセットを一度に使う**ので、事業の総合力がそのまま売上になる

`面白い ★★★ / スキル ★★★ / 稼ぐ ★★★` — **単価**: 着手金30〜50万円 + 支援総額の10〜20%
**開始時期**: Phase 2後半（メルマガ2,000件以上が目安）
→ **合計9点。BtoB案の中で最もバランスが良い。**

**提供物**: メーカー・小売・キャンプ場・ガイド事業者向けの無料ニュースレター。

- 将来的にスポンサー枠（Layer E）で収益化もできる

`面白い ★★☆ / スキル ★★★ / 稼ぐ ★☆☆（間接的には★★★）`

#### ⑰ 中古ギア・レンタルのマーケットプレイス（アプリ連動）

**課題**: アウトドアギアは高額で、初心者の参入障壁が高い。
一方で経験者の家には「使わなくなったギア」が眠っている。メルカリはあるが、
**ギアの状態（使用回数・経年）が分からず、買う側が不安**。

**提供物**: GEAR LOCKERアプリの延長。
- アプリに登録済みのギアを、**そのまま出品できる**（使用回数・使用環境のログ付きで出せる ← 他にない信頼性）
- レンタルにも展開（初心者が試してから買う）
- 手数料 5〜10%

**なぜ強いか**: **アプリの所有データがあるからこそ成立する。**
「このテントは12泊使用、うち雨天3泊」という履歴付き中古は、メルカリには絶対に作れない。
さらに⑫の装備管理SaaSと技術基盤を共有できる。

`面白い ★★★ / スキル ★★☆ / 稼ぐ ★★☆` **開始時期**: Phase 3（アプリMAU 5,000以上）

**提供物**: 装備・気象・ルート・遭難対応の体系的なオンライン講座。
- 法人向けライセンス販売（1社◯名まで年間◯万円）

- ⑫の安全管理SaaSと「安全」というテーマで束ねる

`面白い ★★☆ / スキル ★★☆ / 稼ぐ ★★☆` **開始時期**: Phase 3

#### ⑲ ツアー会社・山岳ガイド向け「参加者の体力事前スクリーニング」★アプリDが生む新規案

**課題**: 登山ツアー会社・山岳ガイド・旅行会社は、**参加者の体力が分からないまま山に連れて行っている**。
申込フォームの自己申告（「初心者です」「体力に自信あり」）はまったくアテにならない。
結果、パーティ全体の遅延、途中撤退、そして**事故**が起きる。ガイドが最も恐れているのがこれ。

**提供物**: アプリD（YAMATO ASCENT）のトレーニング記録と適性レベル判定を、事業者向けに開放する。
- ツアーごとに「要求レベル」を設定 → 申込者に事前チェックを案内
- 「このツアーの要求レベルは 4。◯◯様は現在 3.2。あと6週間、この内容を推奨します」
- 参加者にとっては**断られるのではなく「間に合わせ方が分かる」**ので、体験がポジティブになる
- 事業者にとっては**事故リスクの低減 + キャンセル率の低下 + 参加者の事前教育**

**なぜ強いか**:
- **アプリDがなければ絶対に作れない商材。**第1希望を選んだことで自然に生まれたBtoB案
- ツアー会社にとって「事故」は事業存続に関わる最重要リスク。**予算がつく領域**
- ⑫の安全管理SaaS（装備の安全）と、**「人の安全」**という同じ文脈で束ねられる
- 参加者はそのままアプリの新規ユーザーになる（**B2B2C の獲得チャネル**）

`面白い ★★☆ / スキル ★★★ / 稼ぐ ★★☆` — **単価**: 月額3〜15万円 / 参加者あたり課金
**開始時期**: Phase 3（アプリのユーザーベースが必要）

### 実行順の結論

```
Phase 1   ⑥ SEO/AIOレポート        ← 最も早く売れる。PVすら要らない
   ↓
Phase 1後半 ④ コンテンツ製造代行     ← 取材作業がそのまま商品になる
   ↓
Phase 2   ⑯ 業界ニュースレター       ← BtoBのリード装置を先に置く
          ⑬ アフィリPG構築代行      ← 自分のアフィリ経験が武器になる
   ↓
Phase 2後半 ⑮ クラファン支援 / ⑧ 読者パネル  ← 全アセットを束ねて高単価化
   ↓
Phase 3   ① DaaS / ⑫ 安全管理SaaS   ← 本命。ここまでの顧客との会話で要件を固める
```

**原則: いきなりSaaSを作らない。**
⑥④⑮のような受託・レポートで顧客の課題を至近距離で聞き、
**「同じ課題を何社からも聞いた」ものだけをプロダクト化する。**
顧客ゼロでプロダクトを作ると必ず外す。これはSaaSの立ち上げでも王道。

**そして重要なのは、⑥④⑬⑮は全部「自分が実際にやっていること」の横流しであること。**
アフィリをやり込んだから⑬が売れ、ECを回したから⑩が売れ、
広告を自腹で回したから⑮の広告運用が任される。
**BtoCの実務が、そのままBtoBの商材になる構造**を意識して進める。

## 8. BtoBのGTM設計（マーケター視点）

BtoB事業は「引き合いを待つ」と永遠に始まらない。THE MODELをそのまま持ち込む。

### ターゲット・セグメント

| セグメント | 社数感 | 意思決定者 | 攻め方 |
|---|---|---|---|
| ガレージブランド（1〜5名） | 数百 | 代表本人 | メディア経由・DM・イベント |
| 中小アウトドアメーカー | 数十 | マーケ責任者 | レポート送付・展示会 |
| キャンプ場・ガイド事業者 | 数千 | オーナー | 記事掲載をフックに |
| 自治体・DMO | 多数 | 観光課 | 実績記事 + 提案書 |
| 大手メーカー | 数十 | 宣伝部 | Phase 3以降。実績が要る |

### ファネル設計

```
【マーケ】メディア本体が最強のリード獲得装置
  ・BtoB向けコンテンツを書く（例:「アウトドアブランドのEC商品ページ改善10選」）
  ・「掲載希望・お仕事のご相談」ページを Phase 1 のうちに設置しておく
     ← これが無い個人メディアが多すぎる。置くだけで問い合わせが来る
      ↓
【インサイドセールス】自分から仕掛ける
  ・ABM: 攻めたい30社をリスト化
  ・その会社の製品を「本気でレビューする」→ 記事を送る
     ＝ これが最強のアウトバウンド。売り込みではなく価値提供から入る
  ・⑥のミニレポート（無料）を作って送る ＝ SaaSのアセスメント商法
      ↓
【フィールドセールス】
  ・入口商材（⑥レポート / ④単発コンテンツ）で小さく始める
  ・実績を作ってから年間契約・SaaSへ
      ↓
【カスタマーサクセス】
  ・成果をレポートで可視化する（PV、CVR、送客数、売上寄与）
  ・アウトドア業界でここまでやる会社はいない → 解約されない
  ・④→⑥→⑩→①へアップセル
```

### 決定的なポイント
> **「レビューさせてください」ではなく「御社の製品が市場でどう比較されているかのデータがあります」**
> から入る。前者は雑誌の営業と同じ。後者はSaaSの営業。単価が一桁変わる。

## 9. 長期ゴール — 4つのシナリオ

Phase 2の終盤（2年目）に、どれか（または複合）を選ぶ。今は決めなくていいが、意識して積む。

### パターンA: コミュニティ・ライフスタイル型 —「大人の秘密基地」
- オンラインサロン / Discord → 会員制キャンプ場 / ゲストハウス / カフェ
- **相性の良い施策**: ⑧読者パネル、SUZURI/D2C、有料コンテンツ
- **向いている人**: 事業規模より「一生続けられる場と仲間」を取りたい

### パターンB: ブランド・メーカー型 — YAMATO OUTDOOR をギアブランドに
- 検証で溜めた「本当に欲しいギア」を製品化。OEM小ロット → D2C
- メディアは自社ブランドの最強の販促媒体になる
- **相性の良い施策**: ⑧読者パネル（開発の声）、⑤スペックDB（設計の根拠）、EC
- **向いている人**: モノ作りで業界に名を残したい

### パターンC: 事業売却（M&A）型 — 数千万〜億でのEXIT
- 組織化・仕組み化してPVと利益を最大化 → メディア企業 / 大手に売却
- **相性の良い施策**: SEO集客の最大化、アフィリ・EC収益の安定化、属人性の排除
- **向いている人**: まとまったキャピタルゲインで次に行きたい
- **注意**: 「自分がいなくても回る」設計が必須。実体験メディアと最も相性が悪い方向でもある

### パターンD: プラットフォーム型 —「アウトドア業界のDX基盤」★本ロードマップの推奨
- メディア + アプリ + データ + BtoB SaaS を統合し、業界のインフラになる
- 出口は「事業会社への高額売却」または「調達して拡大（IPOも射程）」
- **BtoCの単なるメディアの売却額（PV × 数十円）と、SaaSの売却額（ARR × 5〜10倍）は桁が違う。**
  月間ARR 500万円のVertical SaaSは、それだけで数億円の評価が付く。
- **相性の良い施策**: 全部
- **推奨理由**: ①②③の構想も、SaaSマーケターという経歴も、開発力も、全部この方向に向いている。
  そしてA（コミュニティ）とB（ブランド）は、Dの途中で**同時に**実現できる。CだけがDと排他。

> **推奨: Dを本線に置き、AとBを内包して進める。Cは「いつでも選べるオプション」として持っておく。**

## 10. 直近90日アクションプラン

## 11. 意思決定が必要な論点

このロードマップを進めるうえで、早めに決めるべきこと。

1. **最初の1ジャンルはどれか**（Month 1で決定必須）
2. **アプリの開発着手時期** — 記事100本を待つか、並行するか
   - 推奨: 設計と自分用の試作は Phase 1後半、**公開ローンチは Phase 2**。
     第1希望D（筋トレ）は**自分が第一号ユーザーになれる**ので、トラフィックがなくても価値検証ができる。
     ただし記事100本との完全並行は物理的に無理（→ 4-5参照）
   - あわせて決めること: **アプリの名前**（YAMATO ASCENT は仮）／ Hevyのどこまでを再現するか
3. **どこまで一人でやるか** — Phase 2以降、記事外注 / 開発外注のラインをどこに引くか
4. **長期ゴール（A〜D）の本線** — Phase 2 終盤（2年目）に確定させる
5. **法人化のタイミング** — BtoB案件（⑥④）を受注する段階で必要になる
6. **セカンドメディアをどこでやるか** — note / Zenn / 別ドメイン
   - 推奨: **note か Zenn で始める**（初速が出る）。伸びたら別ドメインに移行
7. **本業との兼ね合い** — 副業規定、競業避止、法人化した場合の扱い。**最初に確認しておく**
8. **時間配分** — 週に使える時間を先に決める（例: 平日2h × 3 + 週末6h = 週12h）。
   その枠に入らない計画は、計画ではなく願望

## 付録: このロードマップの読み方

- **Phase を飛ばさない。** Phase 1 の記事100本がないと、Phase 3 のBtoBは絶対に売れない。
  「データがあります」と言っても、メディアに信頼がなければ誰も買わない。
- **ただしPhase 0 の技術的仕込み（計測 / 製品マスタ / 構造化データ）だけは前倒しでやる。**
  ここだけは後からやり直しが効かない。
- **BtoBは「作ってから売る」ではなく「売ってから作る」。**
  ⑥や④のような、今すぐ提供できるものから顧客と接点を持ち、
  その会話の中で①⑤⑫のプロダクト要件を固める。
- **3軸（面白い / スキル / 稼ぐ）で7点未満のものは、思いついてもやらない。**
  やりたいことが多いのはこの事業の強みだが、同時に最大のリスクでもある。
  捨てる判断を明文化しているのが、このロードマップの本当の役割。
- **迷ったら「1年後の自分に何のスキルが残るか」で決める。**
  短期の収益は後から取り返せるが、時間は取り返せない。
