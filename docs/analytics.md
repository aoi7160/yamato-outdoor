# 計測とCVの設計

記事を公開する前にやっておく「数字が取れる状態」の作り方。
**コード側の実装は済んでいる**ので、ここに書いてあるのは管理画面での作業と、
出てきた数字の見方が中心になる。

実装の置き場所:

| 対象 | 場所 |
|---|---|
| IDの読み込み・外部送信一覧の定義 | `src/lib/analytics.ts` |
| タグの読み込み・Consent Mode・ページ情報の受け渡し | `src/components/Analytics.astro` |
| 行動イベント(スクロール・クリック・Core Web Vitals) | `src/components/AnalyticsEvents.astro` |
| CVの定義 | `src/lib/cv.ts` / 行き先は `src/lib/site.ts` |
| 記事末のCV導線 | `src/components/ArticleCta.astro` |
| プライバシーポリシー・外部送信の公表 | `src/pages/privacy.astro` |
| サイトマップ / RSS / llms.txt | `src/pages/sitemap.xml.ts` / `rss.xml.ts` / `llms.txt.ts` |

## 0. 結論(この順にやる)

| # | やること | 所要 | 効果 |
|---|---|---|---|
| 1 | GA4プロパティを作り、**データ保持を14ヶ月に変更** | 10分 | ここを忘れると2ヶ月で過去データが消える |
| 2 | GTMコンテナを作り、`GTM_ID` を Cloudflare に入れる | 15分 | 以降タグの追加でデプロイが不要になる |
| 3 | GTMでGA4タグとカスタムイベントを設定 | 40分 | 読了率・外部リンク・CVが取れる |
| 4 | Search Console を**ドメインプロパティ**で登録し、サイトマップを送る | 10分 | 検索クエリが見えるようになる |
| 5 | Microsoft Clarity を入れて GA4 と連携 | 10分 | どこで読むのをやめたかが録画で見える |
| 6 | 内部トラフィック(自分のIP)を除外 | 5分 | 初期は自分のアクセスが数字の大半になる |
| 7 | CVの受け口(まずはGoogleフォーム1枚)を作り、`site.ts` にURLを入れる | 20分 | 記事末のCV枠が表示される |
| 8 | Bing Webmaster Tools に GSC からインポート | 3分 | Bing/Copilot経由の流入が見える |

1〜6が終われば「記事を公開してよい」状態。7以降は記事と並行でよい。

## 1. どこに何を置く構成か

```
        ブラウザ
           │
           │  ① Consent Mode の既定値を先に置く(EEA/英国/スイスは既定で拒否)
           │  ② ページ情報を dataLayer に積む(ページ種別・ジャンル・タグ・流入種別)
           │  ③ load後のアイドル、または最初の操作でタグを読み込む
           ▼
    ┌─────────────┐
    │     GTM     │ ← タグを足すのはここ。以降サイトの再デプロイは不要
    └──┬───────┬──┘
       │       │
       ▼       ▼
      GA4   (Clarity / 広告ピクセルはコード側から直接読む)
```

**GTMをハブにする理由は「デプロイを介さずにタグを増やせる」こと。**
Clarityと広告ピクセルだけはコード側から直接読んでいる。理由は2つ。

1. プライバシーポリシーの外部送信一覧を `src/lib/analytics.ts` から生成しているため、
   GTM側で勝手にタグが増えると**公表内容と実態がずれる**(法令上これがいちばん危ない)。
2. GTM経由でさらに別のタグを呼ぶと読み込みが1段深くなり、表示が遅れる。

→ **計測タグを足すときは、必ず `src/lib/analytics.ts` の外部送信一覧にも1行足す。**

### 読み込みを遅らせている件

`CLAUDE.md` の方針どおり、計測タグは描画を邪魔しない位置まで後ろにずらしている
(`load` 後のアイドル時間、または最初のスクロール/タップ/キー入力のどちらか早い方)。

- 利点: LCP と INP に計測タグの重さが乗らない。
- 欠点: **1秒以内に離脱した人の数件は取り逃す。** セッション数がわずかに少なく出る。

初期は絶対値より「どの記事が読まれたか」の比較のほうが重要なので、この交換で問題ない。
GTMを同期で読むとモバイルのLCPが目に見えて悪化する。

## 2. GA4

### 2-1. 作る

1. https://analytics.google.com/ → 管理 → プロパティを作成
2. 業種・規模は適当でよい。タイムゾーンを**日本**、通貨を**円**にする
3. データストリーム → ウェブ → `https://yamato-outdoor.com` → 測定IDが出る(`G-XXXXXXXXXX`)

### 2-2. 最初にやる設定(ここを飛ばすと後から取り返せない)

| 設定 | 場所 | 値 |
|---|---|---|
| **データ保持** | 管理 → データの収集と修正 → データの保持 | **14ヶ月**(既定は2ヶ月。前年同月比が見られなくなる) |
| Google シグナル | 同 → データ収集 | 有効(地域・年齢の推定が付く) |
| 内部トラフィックの除外 | 管理 → データストリーム → タグ設定を行う → 内部トラフィックの定義 | 自宅と職場のIPを登録し、データフィルタを**有効**にする |
| 拡張計測機能 | 同 → 拡張計測機能 | 有効のまま。ただしスクロールは自作のものを使う |
| Search Console のリンク | 管理 → サービス間のリンク設定 → Search Console | 4.の登録後に実施 |

> **内部トラフィックの注意。** データフィルタは作った直後は「テスト」状態で、
> 有効にしないと除外されない。立ち上げ期は自分のアクセスが全体の8割になるので必須。
> IPが固定でない回線なら、代わりにブラウザの拡張(Google Analytics オプトアウト)を使う。

### 2-3. カスタムディメンションを登録する

サイト側は下の値を毎ページ `dataLayer` に積んでいる。GA4で**受け取る箱を作らないと
レポートに出てこない**ので、管理 → カスタム定義 → カスタムディメンションを作成 で登録する。

| ディメンション名 | 範囲 | イベントパラメータ | 何が分かるか |
|---|---|---|---|
| ページ種別 | イベント | `page_type` | 記事 / 一覧 / トップ / Aboutで数字を分けられる |
| ジャンル | イベント | `content_genre` | 登山・釣り・キャンプ別の伸び |
| カテゴリ | イベント | `content_category` | ギア / ルート / ハウツー別の伸び |
| タグ | イベント | `content_tags` | `|` 区切り。表記ゆれの検出にも使える |
| 流入種別 | イベント | `traffic_source_kind` | **`ai` / `search` / `social` / `referral` / `direct` / `internal`** |
| 参照元ホスト | イベント | `referrer_host` | AI検索のどのサービスから来たか |
| 著者 | イベント | `article_author` | 将来ライターが増えたとき |
| 読了目安(分) | イベント | `article_reading_minutes` | 長い記事ほど読まれないのかの検証 |

`traffic_source_kind` が要るのは、**2026年時点のGA4が既定でAI検索を「referral」に
まとめてしまう**ため。ChatGPT・Perplexity・Gemini・Copilot・Claude などからの流入を
サイト側で判定して送っている(判定リストは `src/components/Analytics.astro` の `AI_HOSTS`)。

あわせて、管理 → データの表示 → **チャネルグループ** で「AI検索」を作っておくと、
集客レポートでそのまま並べて見られる(条件: 参照元が `chatgpt.com` / `perplexity.ai` /
`gemini.google.com` / `copilot.microsoft.com` などに一致)。

### 2-4. 送っているイベント

拡張計測機能で足りないぶんを自作している。GTMで「カスタムイベント」トリガーを作り、
同名でGA4イベントとして送れば、そのままレポートに出る。

| イベント名 | いつ | パラメータ |
|---|---|---|
| `scroll_depth` | 25 / 50 / 75 / 90% に到達 | `percent_scrolled`, `page_type` |
| `article_read` | 記事ページで90%到達(=読了) | `seconds_on_page` |
| `toc_click` | 目次のリンクを押した | `toc_position`, `toc_text`, `toc_place` |
| `related_click` | 関連記事を押した | `related_position`, `related_title` |
| `share` | シェア or リンクのコピー | `share_method`(`x` / `threads` / `facebook` / `line` / `copy_link`) |
| `cv_click` | CV導線を押した | `cv_id`, `cv_stage`, `cv_place` |
| `click_outbound` | 外部リンクを押した | `link_domain`, `link_url`, `link_text` |
| `file_download` | PDF・GPXなどのファイル | `file_name`, `file_extension` |
| `contact_click` | mailto / tel を押した | `method` |
| `page_not_found` | 404ページが表示された | `missing_path` |
| `web_vitals` | タブを離れたとき | `lcp_ms`, `cls`, `inp_ms` と各 `_rating` |

> GA4の既定のスクロール計測は**90%の1点しか取れない**。
> 「どこで離脱したか」を知るには25/50/75が必要なので自作している。

### 2-5. キーイベント(旧コンバージョン)にするもの

管理 → イベント → 該当イベントの「キーイベントとしてマークを付ける」をON。

| 段階 | イベント | 理由 |
|---|---|---|
| soft | `cv_click`(`cv_stage=soft`) | 立ち上げ期の主役。連絡先を残してもらう |
| hard | `cv_click`(`cv_stage=hard`) | 問い合わせ・ブランド遷移 |
| 参考 | `article_read` | 記事の質の代理指標。KPIにはしない |

`article_read` をキーイベントにすると数字が大きく出て気分は良いが、
**それが増えても事業は進まない。**「読まれた」は前提条件であってゴールではない。

## 3. GTM

### 3-1. 作る

1. https://tagmanager.google.com/ → アカウントを作成 → コンテナは**ウェブ**
2. `GTM-XXXXXXX` が出る → Cloudflare Pages の環境変数 `GTM_ID` に入れる(Productionのみ)
3. `main` に反映されてデプロイが走ると、サイト側がGTMを読み始める

> コード埋め込み用のスニペットをコピーする必要はない。
> `src/components/Analytics.astro` がIDから組み立てている。
> `<noscript>` のiframeは入れていない(JSが無効な環境ではGA4自体が動かないため意味がない)。

### 3-2. GA4タグ

| 項目 | 値 |
|---|---|
| タグの種類 | Google タグ |
| タグID | GA4の測定ID(`G-XXXXXXXXXX`) |
| トリガー | Initialization - All Pages |

「Google タグ」を Initialization トリガーにするのが今の推奨。
これだけでページビューと拡張計測機能が動き出す。

### 3-3. カスタムイベントを通す

2-4 のイベントを1つずつ通す。数が多いので**まとめて1つのタグで送る**のが楽。

1. **変数を作る**(変数 → ユーザー定義変数 → データレイヤーの変数)
   `page_type` / `content_genre` / `content_category` / `content_tags` /
   `traffic_source_kind` / `referrer_host` / `article_author` /
   `article_reading_minutes` / `percent_scrolled` / `cv_id` / `cv_stage` / `cv_place` /
   `share_method` / `link_domain` / `link_url` / `toc_text` / `toc_position` /
   `file_name` / `file_extension` / `seconds_on_page` / `lcp_ms` / `cls` / `inp_ms`
2. **トリガーを作る**(トリガー → カスタムイベント)
   イベント名に正規表現を使い、1本にまとめる:
   `^(scroll_depth|article_read|toc_click|related_click|share|cv_click|click_outbound|file_download|contact_click|page_not_found|web_vitals)$`
   (「イベント名」の一致条件を「正規表現に一致」にする)
3. **GA4イベントタグを作る**
   - イベント名: `{{Event}}`(dataLayerのイベント名をそのまま使う)
   - イベントパラメータ: 上で作った変数を必要な分だけ並べる
   - トリガー: 2で作ったもの
4. プレビュー(Tag Assistant)で発火を確認 → **公開**

> GTMは「公開」を押すまで反映されない。プレビューで動いていても、
> 公開を忘れると本番では何も送られない。最初にいちばんやる失敗。

### 3-4. Clarityはどこで入れるか

`CLARITY_ID` を環境変数に入れるだけでよい(GTMのテンプレートは使わない)。
理由は1.に書いたとおり、プライバシーポリシーの公表内容と実装を1箇所に揃えるため。

## 4. Search Console

### 4-1. 登録は「ドメインプロパティ」で

URLプレフィックスではなく**ドメインプロパティ**にする。
`http/https`・`www`有無・サブドメインをまとめて1つで見られるので、後から作り直さずに済む。

1. https://search.google.com/search-console/ → プロパティを追加 → **ドメイン**
2. 表示されたTXTレコードを **Cloudflare の DNS** に追加(DNSがCloudflareなので数分で通る)
3. 確認完了

> DNSでの確認ができない場合だけ、URLプレフィックスで登録し、
> 表示されたメタタグの`content`値を環境変数 `GSC_VERIFICATION` に入れる。

### 4-2. サイトマップを送る

サイトマップ → 新しいサイトマップの追加 → `sitemap.xml`

`https://yamato-outdoor.com/sitemap.xml` はビルド時に自動生成される。
microCMSで記事を公開すると再ビルドが走るので、**サイトマップの更新作業は不要**。
`lastmod` には記事の `revisedAt`(microCMSの最終更新)が入る。

### 4-3. 公開直後にやること

- URL検査 → 記事URLを入れて「インデックス登録をリクエスト」(初期は1本ずつでも効く)
- 設定 → クロールの統計情報 で、実際に取りに来ているか確認

### 4-4. GA4と繋ぐ

GA4の 管理 → サービス間のリンク設定 → Search Console → リンク。
そのあと**レポート → ライブラリ**で「Search Console」のコレクションを**公開**しないと
レポートが出てこない(ここで詰まる人が多い)。

## 5. Microsoft Clarity

無料のヒートマップはこれで決まり。PV上限がなく、全ページ自動、セッション録画付き。

1. https://clarity.microsoft.com/ → Add new project → サイトURLを入れる
2. プロジェクトIDをコピーして、Cloudflare の環境変数 `CLARITY_ID` に入れる
3. Settings → Setup → **Google Analytics** で GA4 と連携する
   (GA4のレポートからClarityの該当録画へ飛べるようになる)

サイト側では、録画を絞り込むためのカスタムタグを自動で付けている。

| Clarityのタグ | 中身 |
|---|---|
| `page_type` | 記事 / 一覧 など |
| `genre` / `category` | 登山・ギアなど |
| `source_kind` | `ai` / `search` / `social` ほか |

### 見るところ(初期はここだけでよい)

- **Dead clicks** … 押せると思って押された、押せない場所。装飾を押している場合が多い
- **Rage clicks** … 反応しないので連打された場所。致命的なUIの不具合
- **Scroll depth** … 記事のどこで止まっているか。目次直下で止まるなら導入が長い
- **録画を5本だけ見る** … 数字より速い。特にスマホの録画

> EU圏からのアクセスを本格的に集める段になったら、Clarity側の
> Settings → Cookie consent を有効にする(現状は日本向けのため未設定)。

## 6. 同意と法令(ここは飛ばせない)

### 6-1. 外部送信規律(電気通信事業法)

2023年6月施行。**利用者の端末から第三者へ情報を送信させる場合、送信先と項目を
通知または公表する義務がある。** GA4・Clarity・広告ピクセルはすべて対象。

対応は `/privacy` で済ませている。表の中身は `src/lib/analytics.ts` の配列から
生成しているので、**環境変数でタグを有効にすると自動的に一覧へ載る。**
逆に言えば、GTM側で勝手にタグを増やすと公表内容と実態がずれる。
→ タグを足すときは必ず `src/lib/analytics.ts` を更新する。

### 6-2. Consent Mode v2

同意バナー(CMP)は置いていない。代わりに次の形にしている。

| 地域 | 既定 | 理由 |
|---|---|---|
| EU・英国・スイス | **拒否**(計測しない) | 同意を取る仕組みが無いので、送らない側に倒す |
| 日本その他 | 許可 | 外部送信は `/privacy` で公表。個別停止の手段も用意 |

`/privacy` の「計測を停止する」ボタンで、そのブラウザの計測を止められる
(localStorageに保存し、次の読み込みからタグ自体を読まない)。

### 6-3. ステマ規制(景品表示法)

2023年10月施行。**広告なのに広告と分からない表示が禁止。**
アフィリエイトリンクを含む記事では、記事の冒頭に明示を置く。

```html
<p class="pr-notice">※ 本記事にはアフィリエイトリンクを含みます。報酬の有無で評価は変えていません。</p>
```

リンク側の `rel="sponsored nofollow"` は `src/lib/article.ts` が自動で付ける
(ASPのドメイン一覧 `AFFILIATE_HOSTS` に載っているもの)。ASPを増やしたら1行足す。

## 7. CV設計

### 7-1. 段階を分けて置く

このメディアは物販の手前にあるので、「いますぐ買う」はCVにならない。
**次にまた来る状態を作ること**がCVになる。

| 段階 | 中身 | 立ち上げ期の役割 |
|---|---|---|
| micro | シェア、リンクのコピー、関連記事への回遊 | 記事の質の確認。KPIにはしない |
| **soft** | メール登録 / LINE友だち追加 / SNSフォロー | **ここが主役。** P1は指名検索が起きにくいので、再訪の口を作る |
| hard | 問い合わせ、ブランド側サイトへの遷移 | ブランドが立ち上がってから |

ペルソナP1(`docs/persona.md`)は「検討期間2〜6週間」「ブックマークしない」層。
**1回目の訪問で決めさせるのではなく、2回目を作る**のが正しい設計になる。

### 7-2. 出し方

`src/lib/site.ts` のURLを埋めると、記事末に自動で枠が出る。
**空のままなら何も描画されない**ので、「準備中」が並ぶことはない。

```ts
export const NEWSLETTER_URL: string = 'https://forms.gle/xxxxx';  // ← 入れると表示される
export const LINE_FRIEND_URL: string = '';
export const CONTACT_URL: string = '';
// 物販(SUZURI)の SHOP_URL は設定済みなので、hard段階のCV枠はすでに出る
```

上から優先で、**最大2枠**しか出さない。3つ以上並べると選べなくなって、どれも押されない。
枠の文面は `src/lib/cv.ts` で編集する。

### 7-3. 受け口は外部でよい

Cloudflare Pagesは静的配信なので、フォームは外に置くのがいちばん安く早い。

| 用途 | 無料でできる方法 |
|---|---|
| お問い合わせ | Googleフォーム。`CONTACT_URL` に貼るだけ |
| メール登録 | Googleフォーム → スプレッドシート。配信は MailerLite の無料枠(1,000件まで) |
| LINE | LINE公式アカウント(無料枠: 月200通)。友だち追加URLを `LINE_FRIEND_URL` に |

**まずはGoogleフォーム1枚でよい。** 受け口が無いと、記事を公開しても
「読まれたが何も残らない」状態が続く。凝ったフォームは後から差し替えられる。

### 7-4. 計測

クリックは `cv_click` として送られ、`cv_id` / `cv_stage` / `cv_place` で分解できる。
GA4の探索(自由形式)で、行に**ページ**、列に `cv_id` を置くと
「どの記事がどのCVを生んだか」がそのまま出る。

## 8. あと少しで効く無料のもの

| ツール | 何のため | 手間 |
|---|---|---|
| **Bing Webmaster Tools** | Bing・Copilot経由の検索クエリ。**GSCからワンクリックでインポートできる** | 3分 |
| **IndexNow** | 公開したURLをBing等へ即時通知。Cloudflareのダッシュボードから**トグル1つで有効化できる**(Cloudflare → サイト → SEO) | 3分 |
| **Cloudflare Web Analytics** | Cookieを使わない実数。GA4が広告ブロックでどれだけ落ちているかの検算に使える | 5分 |
| **PageSpeed Insights** | 公開後にトップと記事1本を実測。`web_vitals` イベントの裏取り | 随時 |
| **リッチリザルトテスト** | 記事の構造化データ(Article / BreadcrumbList / FAQPage)の確認 | 公開前に1回 |
| **RSS → SNS自動投稿** | `https://yamato-outdoor.com/rss.xml` を IFTTT / Zapier の無料枠に繋ぐ。公開と同時にXへ流れる | 10分 |

## 9. 入れないと判断したもの(理由付き)

「無料だから全部入れる」は、外部送信先が増えるぶん法務の手間と表示速度の負担になる。
次のものは**このメディアには合わない**と判断している。

| ツール | 判断 | 理由 |
|---|---|---|
| **Leadfeeder / 企業IP解析** | 入れない | 訪問元の**法人**を特定するBtoB向けの道具。読者は個人の登山者なので、判定できるのはISPの名前だけになる |
| **LinkedIn Insight Tag** | 入れない | 職種・企業規模を見る道具。ペルソナは「34歳・営業企画・月1〜2回登る」個人で、勤務先の属性は購買に関係しない |
| **HubSpot CRM** | 入れない | 商談管理が本体。記事にポップアップを出すだけなら重すぎる。メール収集はフォーム+MailerLiteで足りる |
| **Twilio Segment(CDP)** | 保留 | 発想は正しい(将来のツール乗り換えを楽にする)が、無料枠は月1,000人まで。立ち上げ期に到達する規模ではなく、超えた瞬間に有料になる。**繋ぎ先が3つを超えてから**考える |
| **PostHog** | 保留 | 良いツールだが、役割がGA4+Clarityと8割重なる。A/Bテストを実際に回す段になったら入れる |
| **Meta / X ピクセル** | 任意(既定OFF) | 「将来の広告のために今から溜める」理屈は正しい。ただし外部送信先が2つ増え、プライバシーポリシーへの記載も要る。**広告を出す予定が具体化した時点で** `META_PIXEL_ID` を入れれば有効になる |

## 11. 公開後、最初の1ヶ月の見方

初月はアクセスが出ない。**セッション数を見ても何も分からない**ので、次だけ見る。

| 週 | 見るもの | 判断 |
|---|---|---|
| 1週目 | Search Console「インデックス作成」 | 記事がインデックスされているか。されていなければURL検査 |
| 2〜3週目 | Clarityの録画5本 + `scroll_depth` | 25%で落ちるなら導入が長い。50%で落ちるなら見出しの並びが悪い |
| 4週目 | Search Console「検索パフォーマンス」→ クエリ | **想定KWで出ているか**より、**想定していないKWで出ていないか**を見る。そこに次の記事のネタがある |
| 随時 | `traffic_source_kind = ai` | AI検索から来ているなら、その記事の書き方(結論先出し・表・定義の明示)が効いている証拠 |

順位が付くのは早くて3ヶ月。それまでは数字ではなく**本数と更新**で動かす。
